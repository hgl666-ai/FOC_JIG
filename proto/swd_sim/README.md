# SWD 烧录引擎 spike（纯仿真原型）

> **这是原型验证代码。** SWD 引擎本身已经**正式搬进固件源码树**（`U1/Core/Src/swd_*.c`
> 等 6 个模块，见 `docs/09`），本目录只剩下"线级目标模型 + 仿真跑法"：
> `run_spike.cmd` 现在直接编译**固件真源码**，只把最底层 5 个 GPIO 原语换成 HAL 替身。
>
> 当时这个 spike 回答的问题是：治具主控 U1（STM32F103C8T6）用 GPIO 位翻转做 SWD 主机，
> **能不能读出 IDCODE、停住 F405 内核、擦干净扇区、把镜像写进去并回读校验？**
> **答：能。** 59 项断言全过（见下方"验证了什么"），随后整套代码就进了固件。

## 怎么跑

```
proto\swd_sim\run_spike.cmd
```

需要 gcc（`C:\Program Files\mingw64\bin\gcc.exe`，或 PATH 里的 gcc）。
构建产物在 `build\` 下，`build\build.log` / `build\run.log` 是完整日志（ASCII）。

模型不是"把协议 API 换成桩函数"，而是真的按 ADIv5 约定在 SWCLK 上升沿采样 SWDIO、
在下降沿驱动 SWDIO，解码 8 位请求头 / 3 位 ACK / 32+1 位数据，并统计
**总线冲突次数**与**奇偶校验错误**——这两项必须是 0（实测 0）。

## 验证了什么（59/59 通过）

1. **连接**：两次线复位 + `0xE79E` 切换序列被目标识别，读到 `IDCODE = 0x2BA01477`，
   总线零冲突；重复探测（不带复位）也 OK；上电请求拿到 `CDBGPWRUPACK/CSYSPWRUPACK`。
2. **内核**：`DHCSR` 写钥匙 `0xA05F` 后 `S_HALT=1`；`DBGMCU_IDCODE` DEV_ID = `0x413`（F405/407）；
   冻结 IWDG（`DBGMCU_APB1_FZ`）。
3. **MEM-AP**：读 UID、读 `DBGMCU_IDCODE`、读擦除后的 Flash（`0xFFFFFFFF`）——
   这一组同时证明 **posted read（延迟读）处理正确**（第一次直接读 DRW 会拿到脏数据）。
4. **烧录 boot 镜像**（512 B @ `0x08000000`）：擦 1 个扇区 → 编程 → 回读校验 →
   目标 Flash 内容与镜像**逐字节相同**，编程字数 = 128。
5. **尾部补齐**：254 B（不是 4 的倍数）镜像写入 `0x08020000`（扇区 5），
   末两字节按 `0xFF` 补齐，下一个字未被触碰，**扇区 0 的镜像未被破坏**（分区不越界）。
6. **两种读路径一致**：32 次单字读与 1 次 auto-increment 块读结果完全相同。
7. **复位运行**：`AIRCR SYSRESETREQ` 后 `S_HALT=0`，PC = 复位向量 `0x08000101`，
   SP = 向量表 `0x20001000`。
8. **负向用例**（6 类）：
   - 目标不在（线悬空）→ 干净地返回 `NO_ACK`，不死等；
   - 连续 4 次 WAIT → 重试后成功；
   - 1 次 FAULT + sticky 清除 → 重试后成功；
   - 未擦除重复编程 → 目标报 `PGAERR`，主机返回 `FLASH_ERR`；
   - 回读校验能抓出被改动的字节 → `VERIFY_MISMATCH`；
   - BSY 永不落 → 超时退出，不死循环。

## 实测数据（仿真里数出来的 SWCLK 周期数）

| 项目 | 值 |
|---|---|
| 一个 SWD 事务（写） | 48 个 SWCLK 周期 |
| 烧 512 B（含擦 1 扇区 + 编程 + 回读校验） | 51 246 周期 / 1076 事务 |
| 折合 | **102 492 周期 / KB** |
| 全片 1 MB @2 MHz | **52.5 s**（@4 MHz：26.2 s） |
| 300 KB 应用 @2 MHz | **15.4 s**（@4 MHz：7.7 s） |

这是**第一阶段（未优化）**的路径：每次访问都重写 TAR、每写一个字都清一次标志位、
SR 轮询一次花 3 个事务（≈8.4 个事务/字）。

**第二阶段（三项都是已经验证过机制的改动，预计省 ~3 倍）**：
- 数据用 auto-increment 块写（TAR 每批只写一次）→ 每字 2 事务降到 1；
- 去掉每字一次的标志位清除（只在出错和结尾清）→ 每字省 2 事务；
- SR 轮询预置 TAR，之后每次只发 1 个事务（返回上一次结果，最后一次 drain）→ 每字省 2 事务；
- 回读校验已改为块读（本次已实现，1 事务/字）。

→ 预计每字 ≈3 个事务 → **全片 1 MB ≈19 s @2 MHz / ≈9 s @4 MHz；300 KB ≈5.5 s / 2.8 s**。

> 还有一条更快的路（第三阶段，ST-Link 的做法）：把一小段 Flash 擦写例程搬进目标 SRAM 执行，
> SWD 只负责送数据，目标自己轮询 BSY → 每字 1 事务 ≈6 s/1MB @2 MHz。
> 代价是要维护一份跑在目标上的代码镜像，**建议先不做**，看节拍要求再定。

## 这个仿真**没有**验证的东西

先说不重要的：**线级约定（turnaround/空闲电平/线复位/切换序列/CSW 字段/寄存器位号）
已经在第 15 轮对着 ADIv5 规范（IHI0031H）、RM0090、PM0214 和 DAPLink 源码逐条核对过了**
（见 `docs/09` §1.1），并且加了 27 项"规范自检"把这些常量钉死。
所以下面这份清单现在只剩**电气与真实时序**：

1. **时钟速率与抖动**：`SWD_DELAY_LOOPS` 现在填 8（约 1MHz）。上板要实测能跑多快
   （预期 2~4 MHz）。
   **关于中断干扰：分析结论是不需要临界区**——SWD 是边沿触发的静态协议，
   时钟由主机自己产生，目标侧没有超时；ISR 只会把时钟周期拉长，目标照样在上升沿采样，
   而 ACK 的方向切换时点也是主机自己定的（拉长对目标更宽松）。
   唯一要求是**不要有超长 ISR**：我们的 USB 接收中断只往环形缓冲里塞字节（几微秒），
   `APP_SendFrame()` 的阻塞发送在主循环里、不在中断里。上板时用逻辑分析仪看一眼波形确认即可。
2. **电气**：SWCLK 在 MHz 下走飞线/顶针的振铃，建议串 22~100 Ω 并保证地线回流；
   3.3 V 电平兼容（F405 与 F103 都是 3.3 V，但要不要给被烧板供电还没定）。
3. **目标上电/复位时序**：不做 connect-under-reset（`SWD_USE_NRST=0`）。
   NRST 接不到时，被烧板里已有程序占用 PA13/PA14 或进 STOP 模式会连不上。
4. **RDP 读保护**：模型没建。量产板若开了 RDP1，AP 访问会被拒绝。
5. **真实 Flash 时序**：模型里编程/擦除是"轮询 N 次就完成"，没有建 16 µs/字、
   0.3~1.3 s/扇区的真实时间（这些数字来自 STM32F405 数据手册 Table 39）。
6. **多 AP / 多 drop**：模型只有 AP0、单 drop。
7. **目标端的应答细节**：真实 DP 对校验错的请求会回 FAULT；本模型的包同步规则
   不会把校验错的包识别成包，表现为"无应答"。FAULT 路径用注入方式验证。
8. **模型自身也可能错**：第 15 轮就证明了这点——我第一版把 `CSW.AddrInc` 的语义
   和 `FLASH_CR.STRT` 的位号写错，模型里跟着错，于是 59 项断言全绿而真机必挂。
   **有权威资料可查的常量，必须对资料核，不能靠模型自证。**

## 与固件集成时要注意

- 本目录**不参与** Keil 工程构建，也不需要 CubeMX 再生成。
- 搬进固件时：`swd_config.h` 里把 `SWD_SIM_BUILD` 分支去掉，改用 `main.h`；
  引脚**已确认（2026-10-27 新版治具原理图）**：`SWCLK = PA14`（`U1-SCLK`）、`SWDIO = PA13`（`U1-SWD`）、
  `SWD_PINS_CONFIRMED = 1`、不用 NRST（`SWD_USE_NRST = 0`）。
  > 历史：早期曾按"空闲脚"占位成 SWCLK=PB1 / SWDIO=PB3（都在 GPIOB 的 CRL 范围，切换方向只需一次寄存器写），
  > 该占位值**已作废**，只作留档；详见 `docs/09` §2。
- 上板前把 `SWD_DELAY_LOOPS` 从 8 逐步调到合适值；
  ⚠ **PA13/PA14 就是 U1 自己的 SW-DP**，要把它们当普通 IO 打 DUT 必须让 `SWJ_CFG=100`
  （`SWD_FREE_DEBUG_PINS=1`，见 `docs/09` §2.1）——这时 U1 自己的 SWD 调试/下载会失效，
  升级/救砖走 H1(BOOT0)+复位+USART3。
