# 17 上位机（PC）→ 治具 U1 命令清单

> 给**上位机软件工程师**：这份只讲 PC 侧要发什么、会收到什么。
> 治具内部怎么实现、协议为什么这么设计 → `docs/15`（DUT 协议）/ `docs/13`（内部链路）/ `INFO/命令大全.txt`（早期命令的详细散文版）。
>
> **本文所有长度/布局都与固件常量对齐**（`U1/Core/Inc/flash_map.h`、`meas_pack.h`、`pulse_pack.h`），改布局必改这里。

## 0. 一句话回答"我这几个核心功能有命令路径吗"

**有。六个功能全部有命令路径**，而且现在**六项可以一条命令跑完**（`0x0010`）：

| 核心功能 | 命令路径 | 条数 |
|---|---|---|
| **烧录 DUT** | `0x0009` → N×`0x000A` → `0x000B` → `0x0112` | 4 段（上传 N 帧） |
| **① DUT 通讯/协议自检** | `0x0011`（透传 DUT 的 PING/INFO） | 1 条 |
| **② 电压检测** | `0x0015` | **1 条** ✅ |
| **③ MCU 脉冲检测** | **`0x0019`**（内部：进测试模式→发PWM→采集→关输出） | **1 条** ✅ |
| **④ 三相输出检测** | **`0x001A`**（内部：进测试模式→发PWM→采集→判定→关输出） | **1 条** ✅ |
| **⑤ 编码器检测** | **`0x001B`**（内部：进测试模式→清零→发→读U2→读DUT→判定→关输出） | **1 条** ✅ |
| **⑥ 相电流检测** | **`0x0014`**（内部已经含进测试模式与关输出） | **1 条** ✅ |
| **②③④⑤⑥ 一次跑完** | **`0x0010`** → 见 §14 | **1 条** ✅ |
| **设备自检 / 在线状态** | **`0x0017`** → 见 §13（**任何状态都能问**） | **1 条** ✅ |
| 单项手动调试（细粒度） | 旧的 `0x0011`+`0x000F` / `0x0016` / `0x0012`+`0x0013`+`0x0018` 仍然可用 | 3~6 条 |

> **一条命令 = 一条应答**：`0x0014` / `0x0019` / `0x001A` / `0x001B` 内部串了多条子命令，
> 但**子命令的应答全部被拦下**，只回最后那份报告（上位机不用认帧）。
> 反过来，`0x0010` 的定位是"编排总览"，它的子命令应答**照常发**，最后再加一条汇总。

**⚠ 上位机必须先知道的一条**：`0x0014` / `0x0015` / `0x0016` / `0x0018` / `0x0010` 的应答状态码里，
**`0x05` = 测试做完了、判定不合格**（正常业务结果，**不是通讯错误**）；`0x00` 才是合格。
通讯层面的错误是 `0x0C 超时` / `0x08 CRC错` / `0x09 序号不一致` 等。

## 1. 链路与帧格式

| 项 | 值 |
|---|---|
| 物理层 | USB CDC 虚拟串口（Windows 下是 COM 口），**波特率设置无实际意义**（CDC 不受限），代码里写 115200 即可 |
| 帧格式 | 与另外两条链路**逐字节相同**（下面这张图） |
| 建议 | **一收一发**：收到应答（或超时）再发下一条，不要流水线并发 |

```
偏移    0     1     2     3     4     5     6     7    8 .. 8+L-1   8+L   9+L
      A5    5B   CMD_H CMD_L SEQ_H SEQ_L LEN_H LEN_L    DATA...      CRC_H  CRC_L
      └── 帧头 ──┘└─ 命令 ─┘└── 序号 ──┘└── 数据长度 ─┘└── 数据 ──┘└── CRC16 ──┘
```

| 规则 | 内容 |
|---|---|
| 帧头 | `A5 5B` |
| CMD / SEQ / LEN | 均 **2 字节大端**；LEN = **DATA 字节数**（不含头尾） |
| DATA 上限 | **256 字节**（治具侧 `FRAME_MAX_DATA`） |
| CRC16 | CRC-16/MODBUS（初值 `0xFFFF`，反射多项式 `0xA001`），**范围 = `A5` 到 DATA 末字节**，大端存放；自检 `CRC16("123456789")==0x4B37` |
| 序号 SEQ | PC 自己从 1 递增（0 保留给设备主动帧），**应答的 SEQ 与请求相同** |
| 收到不认识/CRC 错的帧 | 设备**不应答** → PC 必须靠超时 + 重试处理 |
| 重试 | 建议**同一 SEQ 重试 1 次**；仍失败就报"通讯异常" |

**状态码总表**（应答 DATA 第 0 字节）：

| 码 | 含义 | 上位机怎么处理 |
|---|---|---|
| `00` | OK / 判定合格 | 正常 |
| `01` | BUSY（正在上传/烧录/采样） | 稍后重试 |
| `05` | **测试完成但判定不合格** | **显示 FAIL，不要当通讯错误** |
| `08` | CRC 错 | 重发 |
| `09` | 序号不一致 | 重发 |
| `0B` | 参数非法 | 检查界面输入 |
| `0C` | 超时（如等 DUT 应答超时） | 提示"被测板没响应" |
| `0D` | 溢出 | 减少请求量 |
| `FF` | 命令未实现 | 固件版本不匹配 |

## 2. 烧录（把固件烧到被测板）

| 命令 | 请求 LEN | 应答 LEN | 作用 |
|---|---|---|---|
| `0x0009` FW_START | **9** | 1 | 开始上传：声明总帧数、文件大小、版本 |
| `0x000A` FW_DATA | 1~256 | 1 | 一帧原始固件数据（**按序追加**） |
| `0x000B` FW_END | 0 | 1 | 上传结束（治具校验并写入自己的 GD25Q128） |
| `0x000C` | 0 | 4 | 查**治具 Flash 里**的固件版本 |
| `0x0112` | 0 | 1 | **把 Flash 里的固件烧到被测板**（走 SWD） |

**`0x0009` 请求 DATA（9B）**

| off | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0..1 | 2 | 总帧数 | 本次要发多少个 `0x000A` |
| 2..5 | 4 | 文件大小 | 字节数（u32） |
| 6..8 | 3 | 版本 | `主 次 修订` |

**`0x000A` 请求 DATA** = 直接放原始固件字节（长度 L = 本帧字节数，≤256）。
**进度显示**：收到第 k 帧的 OK 就算 k/N 进度。

**`0x000C` / `0x000D` 应答 DATA（4B）** = `状态(1) + 版本(3)`：
- `0x000C` = 治具 Flash 里的固件版本（上传完可校验一次）
- `0x000D` = **被测板里实际跑的**固件版本（治具通过 SWD 直接读目标 Flash）

**`0x0112` 应答** = `状态(1)`：`00` 成功；其它见状态码表（`0C` = SWD 连不上/超时）。

**⚠ 顺序与前提**：必须先 `0x0009→0x000A×N→0x000B` 把固件放进治具 Flash，再发 `0x0112`。
**烧录时治具 SCK/SWD 的引脚走线还没最终确认**（`docs/15` D9），这条链路目前**只在仿真上跑过**。

## 3. ② 电压检测 —— `0x0015`（**一条命令搞定**）

请求 LEN=0，应答 **71B**。

| off | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `status` | `00` 合格 / `05` 不合格 |
| 1 | 1 | `dut_st` | 问 DUT 时的状态码（`00` = DUT 正常应答；非 0 说明 DUT 侧有问题） |
| 2..3 | 2 | `dut_ver` | DUT 报的协议版本（`0x0101`） |
| 4..5 | 2 | `adc_mask` | DUT 能上报哪些通道（bit i = 通道 i） |
| 6..7 | 2 | `sum` | 汇总位图：`01`=9 路都过了一遍 · `02`=至少一路真不合格 · `04`=至少一路没判成（DUT 没报/数据不可用） |
| 8.. | 9×7 | 每通道 | 见下 |

**每通道 7B**：`flags(1) + jig_mv(2) + dut_mv(2) + err_mv(2, 有符号)`

通道序号 **0~8 固定**：`0`=24V母线 `1`=10V驱动 `2`=5V `3`=3.3V `4`=A相电压 `5`=B相 `6`=C相 `7`=电流检测1 `8`=电流检测2

每通道 `flags`：`01`=该路判定通过 · `02`=数据不全 → **不判**（不是失败） · `08`=与 DUT 读数差超容差（真故障）

> ⚠ 没有 `04` 这个位（别照别的命令套）。
> 容差：`max(DUT值×5%, 200mV)`。DUT 没在 `adc_mask` 里声明的通道会**跳过并标 `02`（不判），不算失败**。

**用法**：进测试模式后（`0x0011` 透传 `0x0202`）直接发。它是"读 + 判"一条完成。

## 4. ③ MCU 脉冲检测 + ④ 三相输出检测

这两项**共用一次采集窗口**（`0x000F`），④ 再补一条判定。

**步骤**：

```
1) 0x0011 透传 DUT_TEST_MODE(mode=1, wdt=2000ms)     ← 进测试模式（关输出/停控制环/清编码器计数）
2) 0x0011 透传 DUT_PWM(freq, duty_a/b/c, count)      ← 让被测板输出已知 PWM
3) 0x000F mode=1                                     ← 开 200ms 捕获窗口并等结果
4) （只做 ④ 时）0x0016 mode=1 duty_a/b/c=<占空比>    ← 判 V ≈ 占空比 × 母线
5) 0x0011 透传 DUT_STOP                              ← 关输出
```

### 4.1 `0x000F` 脉冲捕获 —— 请求 1B（mode），应答 **91B**

**mode**：`00` = 只读最近一次结果（不触发）· `01` = 开一个 200ms 窗口，采完才回（**可能要等 ~250ms**）

| off | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `status` | `00` OK |
| 1..45 | 45 | **U1 的结果** | 见 4.2 |
| 46..90 | 45 | **U2 的结果** | 同上（两片测**同一组线**，用于冗余互比） |

### 4.2 单个 45B 块布局

| off | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `ver` | =1 |
| 1 | 1 | `flags` | 快照标志：`01`=数据有效 · `02`=至少一相没信号 |
| 2..3 | 2 | `window_ms` | 窗口长度（200） |
| 4 | 1 | `phase_count` | =3 |
| 5 | 1 | `rsvd` | 0 |
| 6.. | 3×13 | A/B/C 三相 | 每相：`period_ns(4) + high_ns(4) + duty_permille(2) + edges(2) + flags(1)` |

每相 `flags`：`01`=有效 · `02`=没信号 · `04`=周期超范围 · `08`=有异常间隔被丢弃 · `10`=两片不一致

> 上位机做 ③ 只需要：**`period_ns` → 频率**（`Hz = 1e9/period_ns`）、`duty_permille`、`flags`。

### 4.3 `0x0016` 三相输出判据 —— 请求 **7B**，应答 **34B**

**请求 DATA（7B）**：`mode(1) + duty_a(2) + duty_b(2) + duty_c(2)`
- `mode`：`0` = 静态电平判据（不查脉冲）· `1` = PWM 判据（同时查 ③ 的脉冲）
- `duty`：**千分比**；填 `0xFFFF` = 该相不判（高阻）

**应答 DATA（34B）**：`status(1) + sum(2) + phase_count(1)` + 每相 **10B**
（`sum`：`01`=三相都判过一遍 · `02`=至少一相真不合格）

| 每相 10B | 字段 |
|---|---|
| 0..1 | `flags`（见下） |
| 2..3 | `expect_mv` 期望相电压（占空比 × 母线） |
| 4..5 | `err_mv` 实测 − 期望（**有符号 s16**） |
| 6..7 | `tol_mv` 本次容差 |
| 8..9 | `duty_pm` 用的占空比 |

`flags`：`01`=合格 · `02`=高阻(不判) · `04`=无数据 · `08`=母线电压太低 · `10`=没脉冲信号 · `20`=偏差超容差 · `40`=占空比与 ③ 测到的不一致

> **注意**：④ 依赖 `0x000F` 已经采过一次（它用那次快照里的相电压 + 母线）。
> 如果母线没电（没接 24V），三相都会报 `VBUS_LOW` —— 这是"测不了"，不是"板子坏"。

## 5. ⑤ 编码器检测（**要 PC 编排 5 条**）

```
1) 0x0011 透传 DUT_TEST_MODE(mode=1)   ← 进测试模式（DUT 会把自己的编码器计数清零）
2) 0x0013 动作=0                        ← 让 U2 清零边沿计数
3) 0x0012（LEN=0 用默认 A=1000@5kHz / B=2000@10kHz / Z=1）  ← U1 从 CN2 的 A/B/Z 发脉冲
4) 0x0013 动作=1                        ← 读 U2 数到的边沿数
5) 0x0011 透传 DUT_GET_ENC              ← 读被测板自己数到的计数
6) 三个数在 PC 上比：意图(2×脉冲数) == U2 == DUT
7) 0x0011 透传 DUT_STOP
```

### 5.1 `0x0012` 发脉冲 —— 请求 0 或 12B，应答 **9B**

**请求 DATA（12B，LEN=0 时用默认值）**：`cnt_a(2) + cnt_b(2) + cnt_z(2) + freq_a(2) + freq_b(2) + freq_z(2)`

| 应答 9B | 字段 |
|---|---|
| 0 | `status` |
| 1 | `done_mask`：bit0=A · bit1=B · bit2=Z 已完成 |
| 2 | `aborted`：1 = 被提前中止（比如被新命令打断） |
| 3..4 | A 相实际翻转次数（u16，应 = 2×脉冲数） |
| 5..6 | B 相同上 |
| 7..8 | Z 相同上 |

### 5.2 `0x0013` 读/清 U2 的边沿计数 —— 请求 1B，应答 2B 或 16B

**请求**：`0` = 清零 · `1` = 读取

| 应答 | 内容 |
|---|---|
| 清零成功 | `状态(1) + U2状态(1)` → 2B |
| 读取成功 | `状态(1) + U2 的 15B` → 16B；15B = `status(1) + cnt_a(4) + cnt_b(4) + cnt_z(4) + lost(2)` |

> `lost` = U2 自己诊断到的丢边沿次数，正常恒为 0。

### 5.3 DUT 侧那一步

`0x0011` 透传 `0x0208 GET_ENC`；DUT 回的 14B 里 `cnt_a/cnt_b/cnt_z` 是**边沿个数**，
所以判定关系是 **`DUT 计数 == U2 计数 == 2 × 治具发的脉冲数`**（1 个完整方波 = 2 个边沿）。

## 6. ⑥ 相电流检测 —— `0x0014`（**一条命令搞定**）

**请求 LEN=0（用默认）或 8B**：

| off | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `hi_mask` | 上桥相：bit0=A / bit1=B / bit2=C |
| 1 | 1 | `lo_mask` | 下桥相（必须与 hi 不同相） |
| 2..3 | 2 | `duty_permille` | 千分比（静态通流一般 1000） |
| 4..5 | 2 | `duration_ms` | 通流时长（默认 200） |
| 6 | 1 | `ch_mask` | 要读的电流通道：bit0=电流检测1 · bit1=电流检测2（默认 `0x03` 两路都读；**不能填 0，且只许这两位**） |
| 7 | 1 | `rsvd` | 必须 `00` |

> `hi_mask` / `lo_mask` 各自**只能有 1 位**、且**必须不同相**；参数不对治具直接回 `0B`，不会发给 DUT。

**应答 22B**：`status(1) + dut_st(1) + ch_count(1) + rsvd(1)` + 每路 **9B × 2**

| 每路 9B | 字段 |
|---|---|
| 0 | `flags`（`01`=合格 · `02`=无数据 · `04`=没通流 · `08`=超差） |
| 1..2 | `jig_idle` 治具通流前的 mV |
| 3..4 | `jig_on` 治具通流中的 mV |
| 5..6 | `dut_idle` DUT 通流前的 mV |
| 7..8 | `dut_on` DUT 通流中的 mV |

> 治具比的是**变化量**（`on − idle`），所以界面直接显示这 4 个数最好排查。
> `dut_st` 非 0 = 被测板没应答/参数被拒（这时 `dut_*` 全是 0）。

## 7. ① DUT 协议自检 / 调试透传 —— `0x0011`

**请求 DATA**：`DUT命令号(2, 大端) + DUT的DATA`
**应答 DATA**：`治具状态(1) + DUT应答的DATA（原样）`

```
例：让被测板 PING 一下
  发   0x0011  DATA = 02 00 | DE AD BE EF
  收   0x0011  DATA = 00 | DE AD BE EF        ← 前面那个 00 是治具状态，后面是 DUT 的原样应答
```

> **这是上位机的万能口子**：DUT 的新命令（`0x0200~0x0208`，见 `docs/16`）**不需要治具固件改动**就能调。
> 治具只负责转发 + 把 DUT 的状态码带回来（治具状态 `00` = 转发成功；`0C` = DUT 没应答）。
> **只接受 `0x0200~0x02FF` 的命令号**，填别的直接回 `0B`（防止误发到别的命令空间）。

**常用透传组合**（给上位机做"高级/手动"页很有用）：

| 目的 | 透传内容 |
|---|---|
| 进测试模式 | `02 02` + `01` + `wdt_ms(2)` |
| 退出测试模式 | `02 02` + `00` + `wdt_ms(2)` |
| 关输出 | `02 03` |
| 发 PWM | `02 04` + `freq(2) + duty_a/b/c(2×3) + count(2)` |
| 输出静态电平 | `02 05` + `level(1) + 00` |
| 通流 | `02 06` + `mode(1) + hi(1) + lo(1) + duty(2) + dur(2) + 00` |
| 读 DUT 的 ADC | `02 07` + `ch_mask(2)` |
| 读 DUT 的编码器计数 | `02 08` |
| 读 DUT 版本/能力 | `02 01` |

## 8. 原始测量（调试用）—— `0x000E`

请求 1B（`00` 只读最近一次 / `01` 触发一次完整测量），应答 **77B**：
`status(1) + 快照(55B) + 交叉校验块(21B)`

**快照 55B**：`flags(1) + ch_count(1) + round(2) + dt_ms(2) + vdda_mv(2) + cfg_crc(2)` + 9 通道 × (`raw(2) + mv(2) + flags(1)`)
**交叉校验 21B**：`cc_flags(1) + mask(2) + 对侧9路mv(2×9)`

> ② 已经由 `0x0015` 一条命令封装好了，一般不用直接发 `0x000E`；
> 但**调试阶段**（还没接被测板时）它是最好的"治具本身准不准"的工具。

## 9. 建议的超时（按固件内部行为推算，不是猜的）

| 命令 | 建议超时 | 依据 |
|---|---|---|
| `0x0009 / 0x000A / 0x000B` | 300 ms | 只是写 Flash 页 |
| `0x000C / 0x000D` | 500 ms | `0x000D` 要走 SWD 读目标 Flash |
| `0x0112` 烧录 | **60 s** | SWD 位翻转 + F4 擦写（真板还没实测，先给大的） |
| `0x000E mode=1` | 2 s | 内部跑完测量+判定才回 |
| `0x000F mode=1` | 2 s | 固定 200 ms 窗口 + 两片交叉校验 |
| `0x0012` | 2 s | 默认脉冲串 200 ms + 收尾 |
| `0x0013` | 500 ms | 一次 U1↔U2 往返 |
| `0x0014` | 3 s | 300 ms 通流 + 稳定 + 4 次 ADC 读 + 往返 |
| `0x0015` | 2 s | 里含 INFO + GET_ADC 两次 DUT 往返 |
| `0x0016` | 300 ms | 纯计算，不采集 |
| `0x0011` | 1 s | 取决于 DUT 应答速度 |
| `0x0017` | 500 ms | 纯读，不阻塞 |
| `0x0018` | 300 ms | 纯计算 |
| `0x0010` | **60 s** | 内部 12 步、每步上限 4 s（最坏 48 s），给足富余 |
| `0x000C`（传输中） | 300 ms | 每帧一次 ACK |

## 11. 一张图看完一次完整生产流程（上位机主流程参考）

**方式 A：逐条发（可控性最好，适合调试/分项统计）**

```
上电/插治具
  └─ 0x0017 自检：治具在不在、U2 在不在     ← 1 条，任何状态都能问
  └─ 0x000C 读治具固件版本
  └─ 上传固件: 0x0009 → 0x000A×N → 0x000B
  └─ 0x000C 校验治具里的版本
  ── 治具下压、上电、顶针接触 ──
  └─ 0x0112 烧录到被测板
  └─ 0x000D 读被测板固件版本（校验烧进去的确实是这份）
  └─ 0x0011 透传 0x0202 进测试模式
  └─ 0x0015 ② 电压检测                     → 1 条
  └─ 0x0011 透传 0x0204 发 PWM
  └─ 0x000F mode=1 ③ 脉冲采集              → 2~3 条
  └─ 0x0016 mode=1  ④ 三相输出判定
  └─ 0x0011 透传 0x0202 进测试模式（重置编码器计数）
  └─ 0x0013 清零 → 0x0012 发 → 0x0013 读 → 0x0011 读 DUT   → ⑤ 5 条
  └─ 0x0018 ⑤ 三方对齐判定                  → 1 条
  └─ 0x0014 ⑥ 相电流检测                   → 1 条
  └─ 0x0011 透传 0x0203 STOP
  ── 抬治具、下料；上位机出 PASS/FAIL 报告 ──
```

**方式 B：一条命令（产线推荐，见 §14）**

```
上电/插治具
  └─ 0x0017 自检
  └─ 上传固件 + 0x0112 烧录（烧录不在 0x0010 里，见 §14 的说明）
  ── 治具下压、上电、顶针接触 ──
  └─ 0x0010 一键：进测试模式→②→③④→⑤→⑥→STOP，回一份 12 步汇总
  ── 汇总里 status=00 就 PASS，05 就 FAIL，failed_step 直接指出卡在第几步 ──
```

## 12. `0x0018` ⑤ 编码器三方对齐判定（**一条命令出结论**）

治具自己不缓存任何东西：**你把三个数喂进来，它直接回合格/不合格**。

**请求 38B**：

| off | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0..1 | 2 | `exp_a` | 治具**发的脉冲个数**（A 相），层里自行 ×2 变成边沿数 |
| 2..3 | 2 | `exp_b` | B 相脉冲数 |
| 4..5 | 2 | `exp_z` | Z 相脉冲数（默认 1） |
| 6..7 | 2 | `tol` | 允许的**边沿数**偏差，默认 `0`（干净线上应该完全相等） |
| 8..11 | 4 | `u2_a` | U2 实测边沿数（`0x0013` 读到的那 4 字节） |
| 12..15 | 4 | `u2_b` | |
| 16..19 | 4 | `u2_z` | |
| 20..21 | 2 | `u2_lost` | U2 报的丢边沿次数（`0x0013` 那 15B 的最后 2 字节） |
| 22..25 | 4 | `dut_a` | DUT 上报边沿数（`0x0011` 透传 `0x0208` 回来的 14B 里的 a） |
| 26..29 | 4 | `dut_b` | |
| 30..33 | 4 | `dut_z` | |
| 34 | 1 | `dut_dir` | DUT 报的解码方向（s8：`+1`/`-1`/`0`） |
| 35 | 1 | `avail` | `bit0` = 有 U2 数据；`bit1` = 有 DUT 数据（只认这两位，其它 → `0B`） |
| 36..37 | 2 | `rsvd` | `00 00`（非 0 → `0B`） |

**应答 29B**：`status(1) + sum(2) + ch_count(1) + u2_lost(2) + dut_dir(1) + rsvd(1)` + 3 路 × **7B**

每路 7B：`flags(1) + exp_edges(2) + u2_edges(2) + dut_edges(2)`（两边超过 65535 会饱和）

**flags（1 字节）**：

| 值 | 含义 |
|---|---|
| `0x01` | 三边一致（**只有在 U2 与 DUT 都有数据时才给**） |
| `0x02` | 数据不全 → **不判**（不是失败） |
| `0x04` | U2 实测 ≠ 意图（信号没出去 / 线被拉死 / U2 数漏） |
| `0x08` | DUT 上报 ≠ 意图（DUT 解码或计数有问题） |

**sum（2 字节）**：`0x0001` 三相都判过 · `0x0002` 至少一路不合格 · `0x0004` 至少一路缺数据 · `0x0008` U2 报丢过边沿（警告） · `0x0010` 发了脉冲但 DUT 报"方向没动"（警告）

**判据**：`意图边沿数 = 2 × 脉冲数`，要求 `|U2 − 意图| ≤ tol` 且 `|DUT − 意图| ≤ tol`。
- 只有 U2 不符 → **信号/接线问题**；
- 只有 DUT 不符 → **DUT 解码/计数问题**（常见：把它按脉冲数报了，差一倍）；
- 两个都不符 → **多半接错了**（A/B/Z 互相串）。

> 典型调用（默认参数 1000/2000/1 → 意图 2000/4000/2，两边数据都有、三边都一致 → 合格）：
> 请求 `A5 5B 00 18 00 14 00 26 03 E8 07 D0 00 01 00 00 00 00 07 D0 00 00 0F A0 00 00 00 02 00 00 00 00 07 D0 00 00 0F A0 00 00 00 02 01 03 00 00 BC 61`
> 应答 `A5 5B 00 18 00 14 00 1D 00 00 00 03 00 00 01 00 01 07 D0 07 D0 07 D0 01 0F A0 0F A0 0F A0 01 00 02 00 02 00 02 8B 36`
>
> 拆开看应答 DATA：`00`（OK）`00 00`（sum，DONE 之外没有坏）`03`（路数）`00 00`（丢沿 0）`01`（dir=+1）`00`（保留）
> 然后每路 7B：`01 07D0 07D0 07D0`（flags=OK、exp=2000、u2=2000、dut=2000）… B 相 `01 0FA0 0FA0 0FA0`、Z 相 `01 0002 0002 0002`

## 13. `0x0017` 治具自检 / 在线状态（**任何状态都能问**）

请求 LEN=0，应答 **32B**。**它不走 BUSY 闸门** —— 治具正在跑别的命令时也能问，
这正是"设备连接"页需要的行为。

| off | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `status` | `00` |
| 1 | 1 | `app_state` | 当前状态机：`0`=INIT `1`=IDLE `2`=上传中 `3`=烧录中 `4`=测量中 `5`=等DUT `6`=发编码器脉冲 `7`=等U2编码器 `8`=相电流流程 `9`=电压流程 `10`=一键流程 |
| 2 | 1 | `flags` | `bit0`=U2 在线 · `bit1`=两片链路代码版本一致 · `bit2`=内部链路正忙 · `bit3`=本固件编进了 DUT 链路 |
| 3..4 | 2 | `u2_code_ver` | U2 的链路代码版本（`0x0104`；和本机不一致说明只重烧了一片） |
| 5..6 | 2 | `u2_caps` | U2 声明的能力位图 |
| 7..8 | 2 | `u2_alive` | U2 报的存活计数 |
| 9..10 | 2 | `probe_ok` | 保活探测成功次数（自本机启动） |
| 11..12 | 2 | `probe_fail` | 保活探测超时次数 |
| 13..16 | 4 | `link_rx_frames` | U1↔U2 链路收到的帧数 |
| 17..20 | 4 | `link_rx_crc_err` | U1↔U2 链路 CRC 错次数 |
| 21..22 | 2 | `link_tx_timeout` | 请求超时次数 |
| 23..24 | 2 | `link_tx_busy` | 上一发没收尾就重发的次数 |
| 25..26 | 2 | `u1_rx_drop` | U1 链路串口接收环丢字节数 |
| 27..28 | 2 | `u1_tx_err` | U1 链路串口 HAL 拒发次数（正常恒 0） |
| 29..30 | 2 | `u2_rx_drop` | **U2 报的**接收丢字节数 |
| 31 | 1 | `rsvd` | 0 |

**上位机怎么用**：
- `flags.bit0 == 0` → **U2 不在**（此时所有用到 U2 的项都测不准，先报警）；
- `flags.bit1 == 0` → 两片固件版本不一致（只重烧了一片），要重烧；
- `app_state != 1` → 治具正忙，别发新命令（除了本命令和上传命令）；
- `probe_fail` / `link_rx_crc_err` 持续增长 → 内部串口有问题（接触不良/干扰）。

## 14. `0x0010` 一键全流程（烧录之后一条命令跑完 ②③④⑤⑥）

请求 **LEN=0**（不收参数，用下面的默认值），应答 **29B**。

**它内部按顺序做 12 步**：

| 步 | 做什么 | 用的命令 | 默认参数 |
|---|---|---|---|
| 1 | 让 DUT 进测试模式 | 透传 `0x0202` | `wdt = 4000 ms` |
| 2 | ② 电压检测 | `0x0015` | — |
| 3 | 让 DUT 输出 PWM | 透传 `0x0204` | 1 kHz、三相 50%、300 个（=300 ms） |
| 4 | ③ 脉冲采集 | `0x000F mode=1` | 200 ms 窗口 |
| 5 | ④ 三相输出判定 | `0x0016 mode=1` | 三相 500‰ |
| 6 | 再进一次测试模式（清编码器计数） | 透传 `0x0202` | — |
| 7 | U2 清零编码器计数 | `0x0013` 动作=0 | — |
| 8 | 治具发编码器脉冲 | `0x0012` | A=1000@5kHz、B=2000@10kHz、Z=1 |
| 9 | 读 U2 的计数 | `0x0013` 动作=1 | — |
| 10 | 读 DUT 的计数 + **⑤ 三方判定** | 透传 `0x0208` + 内部 `enc_chk` | 容差 0 |
| 11 | ⑥ 相电流检测 | `0x0014` | A→B、100%、200 ms |
| 12 | 关输出 | 透传 `0x0203` | — |

**应答 29B**：

| off | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `status` | `00` 全部通过 · **`05` 有步骤不合格**（不是通讯错误） |
| 1 | 1 | `steps_total` | =12 |
| 2 | 1 | `steps_done` | 实际跑完几步（正常 12） |
| 3 | 1 | `failed_step` | **第一个失败的步骤号（1 基）**；`0` = 没有失败 |
| 4..27 | 12×2 | 每步结果 | 每步 2 字节：`状态(1) + 结果码(1)` |
| 28 | 1 | `rsvd` | 0 |

每步的**状态**：`00` 没跑 · `01` OK · `02` 失败 · `03` 跳过（数据不全，不判） · `04` 超时
每步的**结果码**：该步子命令的原始状态码（`00` OK / `05` 判定不合格 / `0B` 参数错 / `0C` 超时 …），
第 10 步（⑤）放的是 `enc_chk` 的汇总低字节。

**⚠ 两件必须知道的事**：

1. **半路会先收到各子命令的应答**。`0x0010` 是"编排"，不改写子流程，所以
   `0x0015` / `0x000F` / `0x0016` / `0x0012` / `0x0013` / `0x0014` 的应答**照常发给你**（同一个 SEQ）。
   上位机可以收下显示、也可以只等 `0x0010` 那一条汇总。
2. **烧录不在里面**。`0x0112` 要跑几十秒，把它塞进一条命令会让超时和失败恢复都变复杂 ——
   推荐流程仍是"先 `0x0112` 烧录成功，再 `0x0010` 一键测试"。

**失败不中断**：某一步失败/超时，会继续跑完剩下的步（这样一次压合就能看到全貌），
汇总里用 `failed_step` + 每步状态定位。单步超时上限 **4 秒**。
