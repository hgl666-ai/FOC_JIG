# 27 上传到 SPI Flash → 启动烧录：串口命令序列

> 串口：**115200 8N1，HEX 发送，不勾"发送新行"**。
> 每帧发完**等治具的应答**（正常 10 ms 内），确认对得上再发下一帧。

---

## 0. 先认清两套固件

| 用途 | 镜像 | 帧数 |
|---|---|---|
| **治具自测（回环验证链路）** | `test/fixtures/min_boot.bin` + `min_app.bin`（各 **68 字节**） | **8 帧**，可手工发 |
| **烧真实 FOC 板** | 真实 `boot.bin`(6.3 KB) + `app1.bin`(21.6 KB) | **115 帧**，手工发不现实 |

⚠ **最小回环是"假固件"**：烧到真实 FOC 板上会把它的程序覆盖成 68 字节的桩，
板子就不干活了。**只在试治具本身时用**，别对真板子用。

> 真实固件用工具一条命令做完（它内部也是发这 115 帧）：
> ```
> python tools\foc_jig_tool.py -p COM4 burn --boot 固件\boot.bin --app 固件\app1.bin -v 1.2.3
> ```
> 想自己一帧帧发，用生成器导出清单：
> ```
> python tools\gen_upload_seq.py --boot 固件\boot.bin --app 固件\app1.bin -v 1.2.3
> python tools\gen_upload_seq.py --loopback        ← 8 帧最小回环
> ```

## 2. 三个必须知道的坑

### 坑1：槽位靠**上传顺序**决定，不是靠命令字段

固件里是这样切的（`fw_upload.c:209`）：

```c
upload_slot = (upload_slot == 0u) ? 1u : 0u;   /* 每收到一次"结束帧"就翻转 */
```

所以：

| 操作 | 落到哪 |
|---|---|
| 第 1 次上传（起始→数据→结束） | **Slot0 = Boot** |
| 第 2 次上传 | **Slot1 = App** |
| 第 3 次上传 | 又回 Slot0！ |

**后果**：如果想只换 App，单独传一次 → 它会写进 **Boot 槽**，烧出来就错位了。
**必须成对传，顺序 Boot → App。**

### 坑2：每帧要等应答

治具收到帧会回一个 8 字节 ACK。**没等到就发下一帧，帧会丢**（它没有重传）。

### 坑3：`0x0112` 要等 20~25 秒

它不是"收到就回"，是**烧完 + 全量回读校验完**才回。

| 应答 | 耗时 | 含义 |
|---|---|---|
| `00` | 20~25 s | ✅ 成功 |
| `04` | **几毫秒** | 连接失败（没供电 / SWD 线 / SWD 被占） |
| `04` | 18~25 s | 回读校验不符（线材接触不良） |
| `06` | 立刻 | 治具 SPI Flash 里没有镜像 |

## 3. 建议的顺序（含预检）

```
① 0x001E SWD 自检   A5 5B 00 1E 00 01 00 00 4B 99
   → 00 就说明 SWD 通路好，再上传/烧录；否则先查线

② 上传（8 帧或 115 帧）

③ 查镜像是否到位    A5 5B 00 0C 00 06 00 00 89 90

④ 烧录              A5 5B 01 12 00 07 00 00 9A 68

⑤ 查目标版本        A5 5B 00 0D 00 08 00 00 8A CC
```
