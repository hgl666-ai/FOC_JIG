# FOC 烧录治具 — 上板联调手册

> 适用固件：`U1/MDK-ARM/U1/U1.hex`
> 配套工具：`tools/foc_jig_tool.py`（PC 端协议工具，`selftest` 无需硬件）

---

## 0. 架构（已确认）与现场要填的空

**架构**（与测径治具同构，第 7 轮用户确认）：

```
PC ──USB CDC──▶ 治具 U1 ──SPI2(PB12)──▶ GD25Q128 存被烧固件
                    │
                    └──0x0112──▶ UART ISP (AN3155) ──▶ 外接被烧板 MCU
```

治具板 = 原理图这块（U1 主控 + U2 副控）；**被烧 MCU 是到时候外接的另一块板**（设计号不是 U1）。

| # | 事项 | 代码位置 | 当前值 | 备注 |
|---|---|---|---|---|
| Q1 | ISP 烧录用 U1 哪个串口 | `isp_config.h` → `ISP_UART_INSTANCE` | USART3 (PB10/PB11) | 用户已确认**先按此占位**，后续可能更改 |
| Q2a | 被烧板 **BOOT0** 接 U1 哪个脚 | `isp_config.h` → `ISP_BOOT0_PORT/PIN` | PB1 (pin19) | 做法参考测径治具（普通推挽 GPIO 直驱），见下 |
| Q2b | 被烧板 **RESET** 接 U1 哪个脚 | `isp_config.h` → `ISP_RESET_PORT/PIN` | PC13 (pin2) | 同上 |
| Q2c | 上述两脚是否已飞线 | `isp_config.h` → `ISP_CTRL_PINS_CONFIRMED` | `0`（不做复位时序） | 飞线后改 `1` |
| Q3 | `0x000D` 版本查询协议 | `isp_config.h` → `FOC_APP_VER_QUERY_ENABLED` | `0`（恒回 `0x0C` 失败） | 用户已明确**先不管**，以跑通烧录流程为先 |

**Q2 做法（参考测径治具）**：测径治具用 U1 的两个普通推挽 GPIO 直接驱动被烧板的 BOOT0 / RESET，
时序为 `BOOT0=H → RESET 拉低 10ms → RESET 拉高 → 等 50ms → 发 0x7F`，本工程沿用同一做法与时序。
测径治具用的是 **PA8(BOOT0) / PB15(RESET)**，但本板这两脚已占用（PA8=TIM1_CH1，PB15=SPI2_MOSI 接 U10），
因此改用 U1 上同样空闲的 **PB1 / PC13** 作占位。

**Q2c 说明**：飞线接好后把 `ISP_CTRL_PINS_CONFIRMED` 改成 `1`，固件才会执行上面的进 bootloader 时序。
保持 `0` 时治具只发 `0x7F` 握手，**需要人工先把被烧板按进 bootloader**（按住 BOOT 再点一下 RESET）。

> **被烧板型号不需要填**：擦除命令 `0x43`/`0x44` 运行时自适应（先读目标 bootloader 版本再决定，另一个作兜底）；
> 写内存对齐**统一按 8 字节补齐**，同时满足 F1(4) 与 G0(8)，两种板都能烧。

## 1. 需要的东西

| 项 | 说明 |
|---|---|
| 治具板 | 已焊好的 FOC 测试治具 |
| ST-Link | 接 U1 的 SWD（4P 排针：U1-RX1 / U1-TX1 / U1-SWD / U1-SCLK） |
| USB 线 | 接板上 USB-B 座 |
| 被烧板 + 连线 | 按 Q1/Q2 的确认结果接线 |
| PC | 装了 Keil MDK；Python（可选，用 `foc_jig_tool.py`） |

> SWD 已在固件里恢复（CubeMX 原本生成的 `__HAL_AFIO_REMAP_SWJ_DISABLE()` 会永久关掉 SWD，已改）。
> 若 U1 是空白片，也可以走 UART bootloader：H1 跳线短接 BOOT0 → 用「串口1」4P 排针的 U1-TX1/U1-RX1 进来。

## 2. 第 1 步：烧录 U1

1. Keil 打开 `U1/MDK-ARM/U1.uvprojx`，Select Target = `U1`，编译（应 **0 Error / 0 Warning**）。
2. 也可直接烧 `U1/MDK-ARM/U1/U1.hex`。
3. 烧完按 SW1 复位。

**判据**：Keil 能连上 SWD、下载成功。

---

## 3. 第 2 步：确认 USB CDC 枚举

插 USB 到 PC。

**判据**：设备管理器出现一个 COM 口（描述为 `STM32 Virtual ComPort`）。

**失败排查**：
| 现象 | 可能原因 |
|---|---|
| 完全无设备 | 板上 D+ 的 1.5k 上拉（原理图 R90）没焊；USB-B 座虚焊；D1/F1 损坏 |
| 出现「未知 USB 设备」 | USBLC6-2P6 焊接不良；PA11/PA12 到座子断线 |
| 有设备但无 COM 口 | 描述符没读到，复位后重插；确认烧进去的是 `USB_DEVICE/` 那套而不是空工程 |

---

## 4. 第 3 步：逐条命令验证（**先不接被烧板**）

用 `tools/foc_jig_tool.py`，把 `COM5` 换成实际口号。

### ① 空 Flash 查询 —— 确认帧层通了

```
python tools/foc_jig_tool.py -p COM5 query-flash
```
**期望**：`0x000C Flash 固件版本 -> ERR_NO_FW`（状态码 `0x06`）

> 收到 `06` 就说明：USB CDC 通、帧层通、CRC 通、SPI Flash **在线**（`0x0009` 才会查 Flash ID）。
> 这里**收不到任何东西** → 回到第 2 步；
> 收到 `03 ERR_FLASH` → SPI Flash（U10 GD25Q128）不在线或型号不对，查 PB12/PB13/PB14/PB15 与 U10 的焊接。

### ② 上传一段测试固件

```
python tools/foc_jig_tool.py -p COM5 upload test_boot.bin -v 1.0.0
python tools/foc_jig_tool.py -p COM5 upload test_app.bin  -v 1.0.1
```
（两轮上传会自动分别写入 Slot0 = Bootloader、Slot1 = App）

**期望**：每轮都是 `起始帧 ACK OK` → `N/N 帧` → `结束帧 ACK OK`

**失败排查**：
| 状态码 | 含义 | 排查 |
|---|---|---|
| `01 BUSY` | 非 IDLE 收到命令 | 上一轮没收尾；复位后重来 |
| `02 ERR_SIZE` | 文件大小异常 | 空文件、帧数 0、或 >65528 字节 |
| `03 ERR_FLASH` | Flash 读写失败 | U10 焊接/供电；`GD25Q_Test()` 已在上传前先查 ID |
| `07 ERR_INCOMPLETE` | 完整标志缺失 | 上一轮 END 没走完 |

### ③ 上传后查询 —— 确认版本号写对了

```
python tools/foc_jig_tool.py -p COM5 query-flash
```
**期望**：`状态 = OK`，`版本 = 4.5.6` 之类（App 槽优先；两槽都有则报 App 槽）

### ④ 测一下边界（可选但建议）

- 中途拔掉再插 → 10 s 后应自发一帧 `0x000A` + 状态 `0C ERR_TIMEOUT`
- 手改一帧 CRC 再发 → 按协议**不应答**（仅诊断）
- 发一条不存在的命令（如 `A5 5B 12 34 00 01 00 00 xx xx`）→ 应回 `FF NIY`

---

## 5. 第 4 步：接被烧板，执行烧录

### 接线
1. 按 Q1 把治具的 ISP 串口引到被烧板的 UART（**交叉**：治具 TX → 被烧板 RX）。
2. 按 Q2 把 BOOT0 / RESET 飞线接好，并把 `ISP_CTRL_PINS_CONFIRMED` 改成 `1` 重新编译烧录。
   （没飞线则**人工**按住被烧板 BOOT 再点 RESET 进 bootloader）
3. 共地。

### ★ 推荐：一键完成整个烧录流程

```
python tools/foc_jig_tool.py -p COM5 burn --boot bl.bin --app app.bin -v 1.0.0
```

它会按顺序做完并逐步报进度：
0. **`[0/4]` 预检两个固件文件**（在**开串口之前**）：文件存在非空、不超过 Bootloader `0x5000` / App `0xA000` 分区上限；
   并打印向量表的 SP / 复位向量做人工核对。不合格直接中止，**不接触任何硬件**。
1. `[1/4]` 上传 Bootloader → Slot0
2. `[2/4]` 上传 App → Slot1（自动切槽）
3. `[3/4]` 回读治具 Flash 校验版本号
4. `[4/4]` `0x0112` 烧录到被烧板（烧完才回 ACK）

成功会打印 `★ 烧录完成 OK`，失败会给到具体步骤和排查提示。

### 或者分步执行（便于定位问题）
```
python tools/foc_jig_tool.py -p COM5 upload bl.bin  -v 1.0.0   # → Slot0
python tools/foc_jig_tool.py -p COM5 upload app.bin -v 1.0.1   # → Slot1
python tools/foc_jig_tool.py -p COM5 query-flash               # 确认版本
python tools/foc_jig_tool.py -p COM5 program                   # 0x0112 烧录
```
**期望**：`0x0112 -> OK   (耗时 x.x s)`
- 协议规定 **ACK 在烧录完成后才返回**，全片擦除 + 两段写入，通常几秒到十几秒，请不要中途断开。
- 成功后治具会执行 Go 让被烧板跳转运行。

### 失败排查（都返回 `04 ERR_PROG`）
| 现象 | 可能原因 | 处理 |
|---|---|---|
| 立刻失败 | 被烧板没进 bootloader | 确认 BOOT0/RESET 接线与电平；或人工进 bootloader |
| 擦除阶段失败 | bootloader 只支持另一个擦除命令 | 固件已自适应（先读版本，`0x43`/`0x44` 互相兜底），仍失败见下 |
| 擦除一直失败 | 被烧板开了**读保护 RDP** | 需先解除读保护（会全片擦除），本固件不自动做以防误擦 |
| 写入阶段失败 | UART 交叉接错 / 波特率 / 电平不匹配 | 用串口助手直接对着被烧板发 `0x7F`，正常应回 `0x79` |
| 手上有串口助手能进 bootloader、治具进不去 | 治具 TX/RX 没交叉，或没共地 | 重点查这两个 |

> **看诊断日志**：ISP 每个关键节点都会打到**调试口 USART1**（PA9/PA10，4P 排针）115200 8N1——
> `[ISP] target BL ver=0x??`、`sync FAIL`、`erase FAIL`、`image head invalid, ABORT before erase`、`verify: DATA MISMATCH`。
> 接个 USB-TTL 到「串口1」排针就知道卡在哪一步。


> **固件内置诊断**：ISP 过程会把关键节点打到**调试口 USART1**（PA9/PA10，4P 排针）115200 8N1：
> `[ISP] target BL ver=0x??` / `[ISP] sync FAIL` / `[ISP] erase FAIL` / `[ISP] image head invalid, ABORT before erase` /
> `[ISP] verify: DATA MISMATCH`。
> 接一个 USB-TTL 到「串口1」排针就能看到卡在哪一步。

## 6. 第 5 步：`0x000D` 查询被烧板运行态版本

```
python tools/foc_jig_tool.py -p COM5 query-foc
```
**当前期望**：`状态 = ERR_TIMEOUT (0x0C)`，`版本 = 0.255.255`

## 7. 可选：打开"烧录后回读校验"

`isp_config.h` 里把 `ISP_VERIFY_ENABLED` 改成 `1` 重新编译。

打开后每写完一段镜像会用 AN3155 `0x11` 逐 256B 回读并与源镜像比对，不一致直接报 `ERR_PROG` 且**不执行 Go**。

> ⚠ 默认关闭的原因：回读时序在不同 bootloader 版本上略有差异，**格式若与实际器件不符，
> 一次成功的烧录也会被判为 ERR_PROG**。建议先把 `0x0112` 跑通再加回读，
> 若加了之后从"能烧成功"变成"报 ERR_PROG"，那就是回读格式问题，把宏改回 0 即可。

## 8. 状态码速查

| 码 | 名称 | 现场含义 |
|---|---|---|
| `00` | OK | 成功 |
| `01` | BUSY | 非 IDLE 收到命令（上一轮没收尾 / 烧录中又来命令） |
| `02` | ERR_SIZE | 文件大小异常（0 / 越界 / 帧数 0 / LEN<9） |
| `03` | ERR_FLASH | SPI Flash 读写失败 **或器件 ID 校验不过** |
| `04` | ERR_PROG | ISP 烧录失败（含回读不一致，若已开启） |
| `05` | ERR_TEST | 治具测试失败（本轮未实现测试功能） |
| `06` | ERR_NO_FW | 固件不存在（槽为空 / 大小越界） |
| `07` | ERR_INCOMPLETE | 固件不完整（完整标志 `0xA5` 缺失） |
| `08` | ERR_CRC | 帧 CRC 错误（仅诊断，不回 ACK） |
| `09` | ERR_SEQ | 帧序号非递增（仅警告，不拒绝） |
| `0A` | ERR_COUNT | 上传字节数与声明不符（**不写完整标志**） |
| `0B` | ERR_PARAM | 参数错误 |
| `0C` | ERR_TIMEOUT | 上传 10s 无新数据 / `0x000D` 未配置 |
| `0D` | ERR_OVERFLOW | 上传溢出（锁存，后续 DATA 帧一直回此码） |
| `FF` | NIY | 命令未实现 |

## 9. 联调完成后要做的收尾

1. 把 Q1/Q2/Q3 的实际值回填进 `isp_config.h` 注释，并把 `ISP_CTRL_PINS_CONFIRMED` 定为 `1`。
2. 拿到 Q4 后实现 `0x000D`。
3. 确认 `0x0112` 稳定后，考虑打开 `ISP_VERIFY_ENABLED`。
4. 把真实固件（Bootloader + App）用 `upload` 两轮灌进治具 Flash，再跑 `program` 做一次完整验证。
