# FOC 烧录治具 — 上板联调手册

> 适用固件：`U1/MDK-ARM/U1/U1.hex` **和** `U2/MDK-ARM/U2/U2.hex` —— **两片都要烧**，缺一片只有一半功能。
> 配套工具：`tools/foc_jig_tool.py`（PC 端协议工具；`selftest` 不需要硬件）。
>
> 本文只讲"上板现场怎么一步步调通"。设计细节与当前数字在别的文档：
> `docs/02`（现状与验证数字）、`docs/09`（SWD 烧录）、`docs/10`（四路串口与内部链路）、
> `docs/07` + `docs/06`（ADC 测量与分压）、`docs/12`（脉冲捕获）。

---

## 0. 现在这块板是什么样

```
                 ┌──────────── U1（主控，接 PC）────────────┐
PC ──USB CDC──►  │ USART1 PA9/PA10  ── 被测板串口（已接好，协议还没定）
                 │ USART3 PB10/PB11 ── 内部链路 ──► U2（测量副控）
                 │ SWD: PB1(SWCLK)/PB3(SWDIO) ──► 被烧 FOC 板（STM32F405）
                 │ SPI2 PB12..PB15  ──► GD25Q128（存要烧的固件）
                 └─────────────────────────────────────────┘

被测信号 ─┬─ 9 路模拟量：24V / 10V / 5V / 3.3V / A相 / B相 / C相 / 电流1 / 电流2
          └─ 3 路相位脉冲：MA / MB / MC
   这两组信号**同时**进 U1 和 U2，两边各测一遍再互相比对（对不上就是有问题的那个）
```

- **烧录**：SWD 两线，**不用 BOOT0 / 不用 RESET**（细节见 `docs/09`）。
- **测量**：电压走 `0x000E`，脉冲走 `0x000F`，两条命令各管各的、可以单独调。
- **判定**：调试模式只报数据、不判失败；生产模式才按门限判（见 §9）。

## 0.1 上板前要现场确认的 6 件事

| # | 事项 | 代码位置 | 现在是什么值 | 怎么处理 |
|---|---|---|---|---|
| Q1 | SWD 两个脚的真实接线 | `U1/Core/Inc/swd_config.h` | 占位 **PB1=SWCLK / PB3=SWDIO**，`SWD_PINS_CONFIRMED 0` | ⚠ **2026-10 复查治具原理图后升级为阻塞项**：全图只有 `U1-SWD/U1-SCLK`（接在 **U1 自己的 PA13/PA14**）→ 4 脚调试座，**没有任何网络通向被测板的 SWD**；而占位用的 **PB1/PB3 在图上标的是"叉形未连接、没有铜箔"**。⇒ 按这张图，治具没有把 SWD 打到被测板上的通路。**必须找硬件确认走哪两个脚**，三种可能与取舍见 `docs/15` §13 D9 |
| Q2 | 被烧板两个分区地址 | `U1/Core/Inc/flash_map.h` | Boot `0x08000000`+0x8000、App `0x08008000`+0xF8000（**占位**） | 等 FOC 工程链接脚本确定 |
| Q3 | `0x000D` 读版本的偏移 | `flash_map.h` → `DUT_VER_OFFSET` | `0x20`（**占位**） | 等 FOC 工程确认 |
| Q4 | 被烧板运行态串口协议 | `docs/15_DUT通讯协议规格.md` | ✅ **规格已定稿**（9 条命令 `0x0200~0x0208`），**等 FOC 固件团队实现**；`0x000D` 仍走 SWD 直读目标 Flash，不依赖它 |
| Q5 | 判定门限与电流标定 | `measure.c` → `k_lim_min/k_lim_max` | 规格门限，只有生产模式生效 | 按真实板标定 |
| Q6 | ~~相电压进 MCU 脚的电压~~ **已撤销，不用测** | — | — | **2026-10 更正**：原以为 `MA0_OUT` 只经 3kΩ 串阻进 MCU 引脚。实际那组 3kΩ 是**编码器座 CN2 的上拉**；`MA0_OUT` 走的是 140k/20k 分压（24 V → 3.0 V），**安全**。详见 `docs/00` §3.5 |
| Q7 | 编码器座 CN2 的 A/B/Z 是否也接到被测板的编码器输入 | 夹具线束 | 原理图上这三根线只连到 U1/U2 的 PB8/PB7/PB6 | ✅ **2026-10 用户实地确认**：FOC 板 CN2 位置有 **4 个测试点 = `5V / A / B / Z`**；供电那个点是**治具给被测板供电**（= 治具 CN2 第 1 脚，正常接）；**地没做测试点**（板子别处共地，治具与被测板本来就靠 SWD 共地）。⇒ 顶针把这 3 个信号点并到 CN2 的 A/B/Z 即可（A/B/Z 接错也能查出来：三条线脉冲个数故意不同）。**还剩一个未知：被测板的编码器高电平门限**（`docs/15` D5）——若是 5V 逻辑且门限 3.5V，治具侧把 A/B/Z 改成开漏输出即可 |

## 2. 第 1 步：把 U1、U2 都烧上固件

1. Keil 打开 `U1/MDK-ARM/U1.uvprojx` → Select Target `U1` → Build（应 **0 Error / 0 Warning**）→
   用 ST-Link 烧 `U1/MDK-ARM/U1/U1.hex`（U1 自己的下载口是 PA13/PA14，就在 4P 排针上）。
2. 同样烧 `U2/MDK-ARM/U2/U2.hex`。
3. 顺手跑一次全量回归（含两片 Keil 重建 + "两片重复文件是否逐字节相同"）：
   ```
   test\run_all_tests.cmd
   ```
   **判据**：两片都烧成功；回归最后一行 `ALL PASS`。

> ⚠ **两片永远一起重烧**：`jig_mode.h`、`measure.*`、`meas_pack.*`、`pulse_cap.*`、`pulse_pack.*`、
> `uart_port.*`、`uart_link.*`、`protocol_frame.*` 这些文件在两片工程里是**逐字节副本**（回归会比对）。
> 改了其中任何一个，两片都必须重新编译、重新烧；否则链路版本号对不上，U1 不会采信 U2 的数据。

## 3. 第 2 步：USB 插上，确认 CDC 枚举

插 USB 到 PC。

**判据**：设备管理器出现一个 COM 口（描述为 `STM32 Virtual ComPort`）。波特率随便填，USB CDC 忽略它。

| 现象 | 可能原因 |
|---|---|
| 完全无设备 | 板上 D+ 的 1.5k 上拉（原理图 R90）没焊；USB-B 座虚焊；D1/F1 损坏 |
| 出现「未知 USB 设备」 | USBLC6-2P6 焊接不良；PA11/PA12 到座子断线 |
| 有设备但无 COM 口 | 描述符没读到，复位后重插；确认烧进去的是 `USB_DEVICE/` 那套而不是空工程 |

> PC 与治具之间**只有 USB 这一条通道**，下面所有命令都走它，不占用任何串口线。

## 4. 第 3 步：先不接被烧板、不接信号，验证静态功能

命令形式：`python tools\foc_jig_tool.py -p COM5 <动作>`（`COM5` 换成实际口号）。

### ① 空 Flash 查询 —— 帧层 + SPI Flash 是否通

```
python tools\foc_jig_tool.py -p COM5 query-flash
```
**期望**：`ERR_NO_FW`（状态码 `06`）。

> 收到 `06` 就说明：USB 通、帧头/CRC 通、SPI Flash **在线**。
> 收不到任何东西 → 回第 2 步；
> 收到 `03 ERR_FLASH` → U10（GD25Q128）焊接/供电/型号，查 PB12/PB13/PB14/PB15。

### ② 上传两段测试固件

```
python tools\foc_jig_tool.py -p COM5 upload test_boot.bin -v 1.0.0
python tools\foc_jig_tool.py -p COM5 upload test_app.bin  -v 1.0.1
```
（两轮上传会自动分别写进 Slot0 = Bootloader、Slot1 = App）

**期望**：每轮 `起始帧 ACK OK` → `N/N 帧` → `结束帧 ACK OK`。

| 状态码 | 含义 | 排查 |
|---|---|---|
| `01 BUSY` | 非 IDLE 收到命令 | 上一轮没收尾；复位后重来 |
| `02 ERR_SIZE` | 文件大小异常 | 空文件、帧数 0、或超过分区上限 |
| `03 ERR_FLASH` | Flash 读写失败 | U10 焊接/供电 |
| `07 ERR_INCOMPLETE` | 完整标志缺失 | 上一轮的 END 没走完 |

### ③ 读一次电压（`0x000E mode=0`，只读、不触发测试）

```
python tools\foc_jig_tool.py -p COM5 raw A5 5B 00 0E 00 01 00 01 00 6A 88
```
**期望**：一帧 **77 字节**应答（`SEQ=0001`）：`DATA[0]=00 OK` + 55B 电压快照 + 21B 交叉校验块。
布局见 `docs/07` §3。没接信号时读数应接近 0（相位/电流脚有下拉）。

> 工具目前只有 `raw`，**给的是整帧（含 CRC）**；换了 SEQ 或数据就要重算 CRC——
> `python tools\foc_jig_tool.py demo` 会打印一批示例帧，可以照着抄。

### ④ 读一次脉冲（`0x000F mode=0`）

```
python tools\foc_jig_tool.py -p COM5 raw A5 5B 00 0F 00 01 00 01 00 BB 89
```
**期望**：一帧 **91 字节**应答：`DATA[0]=00` + 45B（本片 U1）+ 45B（U2）。布局见 `docs/12` §6。
没接信号时每相的 `flags` 里"无信号"位应为 1。

### ⑤ 边界（可选但建议做一次）

- 发一条不存在的命令（如 `A5 5B 12 34 00 01 00 00 xx xx`）→ 回 `FF NIY`；
- 故意改坏 CRC 再发 → **不应答**（协议规定 CRC 错只做诊断）；
- 上传到一半拔掉再插 → 10 s 后治具自发一帧 `0x000A` + 状态 `0C ERR_TIMEOUT`。

## 5. 第 4 步：确认 U1 ↔ U2 的内部链路通了

两片之间是 **USART3**（U1 的 PB10/PB11 ↔ U2，115200 8N1，**TX/RX 要交叉、要共地**）。

怎么看通没通 —— 看 `0x000E mode=1`（或 `0x000F mode=1`）应答里的交叉校验块 `cc_flags`：

| 位 | 名字 | 现场含义 |
|---|---|---|
| bit0 | `DONE` | 这次确实做过交叉校验 |
| bit1 | `MISMATCH` | U2 答了，但至少一路超差（具体哪路看 21B 块里的**掩码**，一位一路） |
| bit2 | `NO_PEER` | **U2 没应答** —— 这是链路自检的关键位 |

**判据**：`DONE=1` 且 `NO_PEER=0` → 链路通。

U2 没应答时的排查顺序：
1. U2 有没有烧固件、有没有上电（ST-Link 连一下最能说明问题）；
2. PB10/PB11 有没有接反、有没有共地；
3. 两片固件是不是**同一次**编出来的（链路代码版本不一致 → U1 不采信 U2 的数据）；
4. 串口中断是否使能（`docs/05` §2.3：`usart.c` 的 `USER CODE` 区里那两句 NVIC 配置，CubeMX 再生成会丢）。

> 调试模式（默认）**不会**因为 U2 缺席而判测试失败（只置 `NO_PEER`）；
> 切到生产模式后 U2 缺席 = `05 ERR_TEST`。

## 6. 第 5 步：接被烧板，跑 SWD 烧录（`0x0112`）

### 6.1 先做最便宜的冒烟测试：`0x000D`

```
python tools/foc_jig_tool.py -p COM5 query-foc
```
它只做"连上目标 + 读 4 个字节"，不用上传任何固件：

| 应答 | 含义 |
|---|---|
| `00 OK` + 版本号 | 链路、读写全通 ✅ |
| `06 ERR_NO_FW`（读到全 FF） | **连上了**，只是 App 区是空的 ✅ 同样说明链路通 |
| `0C ERR_TIMEOUT` | 连不上 ❌ 看 6.4 |

### 6.2 接线

| 治具 U1 | 被烧 FOC 板 | 说明 |
|---|---|---|
| SWCLK = **PB1** | PA14 (SWCLK) | 飞线/顶针较长时串 22~100 Ω |
| SWDIO = **PB3** | PA13 (SWDIO) | 同上 |
| GND | GND | **必须共地** |
| —— | （不用 NRST） | 烧完靠目标的 `AIRCR.SYSRESETREQ` 复位运行 |

### 6.3 一键烧录

```
python tools/foc_jig_tool.py -p COM5 burn --boot bl.bin --app app.bin -v 1.0.0
```
它会按顺序做完并逐步报进度：
0. `[0/4]` **预检两个固件文件**（在开串口之前）：文件存在非空、不超过分区上限，并打印向量表的 SP / 复位向量供人工核对；
1. `[1/4]` 上传 Bootloader → Slot0；
2. `[2/4]` 上传 App → Slot1（自动切槽）；
3. `[3/4]` 回读治具 Flash 校验版本号；
4. `[4/4]` `0x0112` 烧录到被烧板。

**期望**：`0x0112 -> OK (耗时 x.x s)`。
协议规定 **ACK 在烧录完成之后才返回**，擦除 + 写入通常十几秒到几十秒，**中途不要拔线、不要连发命令**。

分步执行（便于定位问题）：
```
python tools\foc_jig_tool.py -p COM5 upload bl.bin  -v 1.0.0   # → Slot0
python tools\foc_jig_tool.py -p COM5 upload app.bin -v 1.0.1   # → Slot1
python tools\foc_jig_tool.py -p COM5 query-flash               # 确认版本写对了
python tools\foc_jig_tool.py -p COM5 program                   # 0x0112 烧录
```

### 6.4 失败排查（`0x0112` 失败一律回 `04 ERR_PROG`）

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 立刻失败 / `0C 连不上` | 目标没供电、没共地、SWD 两脚接反 | 量目标 VDD，确认 SWCLK/SWDIO 没接错 |
| 连不上，但接线都对 | 目标程序把 PA13/PA14 当普通 IO 用了，或进了 STOP/Standby | 该板需要 `NRST`：把 `swd_config.h` 的 `SWD_USE_NRST` 置 1 并填引脚（`swd_phy.c` 里时序已写好） |
| 连不上，目标开了读保护 | RDP 会拒绝 AP 访问 | 需要先整片擦除（本固件**不自动做**，防止误擦量产板） |
| 擦除/写入阶段失败 | 目标 Flash 问题或供电跌落 | 用 `SWDP_LastOffset()/LastSwdError()` 或调试打印定位 |
| 回 `02 ERR_SIZE` / `07 ERR_INCOMPLETE` | 治具 Flash 里的镜像不完整/超限 | 重新 `upload` |
| 回 `03 ERR_FLASH` | 治具自己的 GD25Q128 读失败 | 查 U10 |

### 6.5 诊断打印（可选）

U1 的调试串口是 **USART1（PA9/PA10，4P 排针）** 115200 8N1，会打 `[SWD] idcode=...` / `[SWD] FAIL step=...`。

打开条件：**调试模式** + Keil Define `JIG_HAS_DEBUG_UART=1`（U1 工程里已经定义）。
> ⚠ 这个口和"被测板串口"是**同一个 USART1**，调试打印和接被测板**二选一**：
> 同时开会把调试字符灌到被测板的串口线上。

## 7. 第 6 步：接被测信号，测电压和脉冲

### 7.1 电压（`0x000E mode=1`，触发一次完整测量）

```
python tools\foc_jig_tool.py -p COM5 raw A5 5B 00 0E 00 01 00 01 01 AA 49
```
流程：等 9 路都稳定（连续 `MEAS_STABLE_N` 次）→ 取快照 → 与 U2 交换比对 → 回 77B（整个过程约十几毫秒）。

怎么判读：
- `DATA[0]` 是**命令状态**，调试模式下恒为 `00 OK`（只表示"测量跑完了"）；
- 真正"9 路是否合格"看 55B 快照里的 flags 的 `ALL_OK` 位；
- 哪一路不对看 21B 交叉校验块里的**掩码**（一位一路）和 9 路 mV 值。

拿可调电源逐个往被测点加电压，对照 `docs/06` 的换算表：
24 V 点加 24 V → 读数 ≈ 24 V（ADC 码 ≈ 3773）；10 V 点加 10 V → ≈ 1572 码；5 V / 3.3 V 点 → ≈ 3723 码。

### 7.2 相位脉冲（`0x000F mode=1`，开一次 200 ms 捕获窗口）

```
python tools\foc_jig_tool.py -p COM5 raw A5 5B 00 0F 00 01 00 01 01 7B 48
```
流程：开 200 ms 捕获窗口 → 两片各算 MA_IN/MB_IN/MC_IN 三相结果 → 交换 → 回 91B。

接线：
- **两片都测驱动输入端**：MA_IN / MB_IN / MC_IN → PB5 / PB4 / PA8（U1 和 U2 接的是同一组信号）；
- **电机输出端（MA0_OUT / MB0_OUT / MC0_OUT）没有定时器通路**，只进 ADC
  （140k/20k 分压 → U1 的 IN8/IN7/IN6、U2 的 IN4/IN3/IN2）。
  想测电机输出端只能走 `0x000E` 看相电压平均值，或者把 U1 的 PA6/PA7/PB0 改成 TIM3 输入捕获
  （代价是 U1 失去三相电压读数，当前不做）。详见 `docs/12` §1 与 §10。
- 编码器座 CN2 的 A/B/Z → U1/U2 的 PB8/PB7/PB6（TIM4），**本命令不使用**。

**判据**：`period_ns` 与信号源一致（1 kHz → `1000000` ns），`duty_permille` 与设定一致（50% → `500`）；
两端周期差应 < 1%（`PULSE_PEER_TOL_PPM`）。
测量范围 **10 Hz ~ 60 kHz**，超出范围会置"超范围"标志而不是给个假数。

### 7.3 上真实 FOC 板

1. 先只上电不转：看 24 V / 10 V / 5 V / 3.3 V 读数是否正常（这一步最值钱，能立刻发现接线错）；
2. 低速转动：看三相电压是否大致对称、三相脉冲频率是否与设定一致；
3. 最后才跑 `0x000E mode=1` + `0x000F mode=1` 做判定。

> 三相电压是"对功率地"采样的，治具 GND 必须与被测板的**功率地 P-GND** 连在一起，否则读数没有意义（`docs/06` §5）。

### 7.4 功能测试命令（① ② ③ ④ ⑤ ⑥ 对应的那几条）

> **前提**：这些命令都要 **U1 的 Keil Define 里有 `JIG_DUT_LINK=1`**（并且 `dut_proto.c` 在工程里）。
> 默认是 0 —— 那时它们一律回 `FF NIY`，而 USART1 留给调试打印。
> 打开之后调试打印会自动让位（`jig_mode.h` 里有 `#error` 互锁）。
> **每次改这个开关，两片都要重编重烧**（`jig_mode.h` 是两片副本）。

**⑤ 编码器检测（不用被测板也能先自测一遍）**

```
0x0012                       → U1 从 CN2 发默认脉冲串（A=1000@5kHz / B=2000@10kHz / Z=1）
                               应答 9B：状态 + 完成掩码 + 超时位 + A/B/Z 实际翻转次数
0x0013 action=0              → 让 U2 把编码器计数器清零（发脉冲之前）
0x0013 action=1              → 读 U2 数到的边沿数（应答 16B = jig 状态 + U2 的 15B）
```
**判据**：U2 的 A 相计数应当 ≈ `2 × 1000 = 2000`、B ≈ `4000`、Z ≈ `2`。
**先用示波器看一眼 CN2 的三根线**（PB8=A / PB7=B / PB6=Z）——没有示波器就看 U2 的计数对不对。
三路个数故意各不相同，所以对不上时能立刻看出是哪一路。

**② 电压检测（要和被测板比）**

```
0x0015                       → 问 DUT 的 INFO 拿能力位图 → 按位图问 GET_ADC → 9 路逐通道判定
                               应答 71B = 头 8B + 每路 7B × 9
```

**③④ 三相输出与输出检测**

```
0x0011 + 数据(02 04 + PWM 参数)  → 透传 DUT_PWM，让被测板输出已知 PWM（如 1kHz/50%/300 个）
0x000F mode=1                    → 开窗采集（含 ARM 两端同窗）
0x0016 mode=1 duty_a=500 duty_b=500 duty_c=500
                                 → 判定；应答 34B = 状态 + 汇总 + 每相 10B
```
**判据**：`expect_mv` 应 ≈ 占空比 × 母线电压（1kHz/50%、母线 24V → 期望 12000mV）；
`flags` 为 `OK` 或带 `DEVIATION`。`duty = 0xFFFF` 的相作"高阻不判"。

**⑥ 相电流检测**

```
0x0014                       → 一条命令跑完整流程（读基线 → 通流 → 等 → 再读 → 判定）
                               应答 22B = 头 4B + 每路 9B（flags + jig_idle/on + dut_idle/on）
```
**前提**：`P1` 上要接负载（小电机或三相假负载），否则电流流不起来 → 会判 `NOSIGNAL`。

> ⚠ 这几条命令的**详细字段布局**见 `docs/15` §7（DUT 侧）与 `docs/02` §7.28~§7.32（治具侧设计）。
> `tools/foc_jig_tool.py` 目前只有 `raw`，要发这些命令得自己按上面的 LEN 组帧（CRC 用工具里的 `demo` 对着抄）。

## 8. 状态码速查

| 码 | 名称 | 现场含义 |
|---|---|---|
| `00` | OK | 成功 |
| `01` | BUSY | 非 IDLE（上传中 / 烧录中 / 测试中）又收到命令 |
| `02` | ERR_SIZE | 固件大小异常（0 / 越界 / 帧数 0） |
| `03` | ERR_FLASH | 治具 SPI Flash 读写失败 **或** 器件 ID 校验不过 |
| `04` | ERR_PROG | **SWD 烧录失败**（连不上 / 擦写 / 校验失败） |
| `05` | ERR_TEST | **测试判定失败**（电压超差 / 脉冲两端对不上 / 生产模式下 U2 缺席） |
| `06` | ERR_NO_FW | 槽里没有固件（或 App 区读到全 FF） |
| `07` | ERR_INCOMPLETE | 固件不完整（完整标志 `0xA5` 缺失） |
| `08` | ERR_CRC | 帧 CRC 错误（仅诊断，不回 ACK） |
| `09` | ERR_SEQ | 帧序号非递增（仅警告，不拒绝） |
| `0A` | ERR_COUNT | 上传字节数与声明不符（不写完整标志） |
| `0B` | ERR_PARAM | 参数错误（例如 `mode` 不是 `00`/`01`） |
| `0C` | ERR_TIMEOUT | 上传 10 s 无新数据 / `0x000D` 连不上目标 |
| `0D` | ERR_OVERFLOW | 上传溢出（锁存，后续 DATA 帧一直回此码） |
| `FF` | NIY | 命令未实现 |

## 9. 调试模式 ↔ 生产模式（只改一个宏）

统一入口是 `Core/Inc/jig_mode.h`（**两片是同一个文件，改了两片都要重编重烧**）：

| 项 | 调试（默认） | 生产 | 生产打开后会发生什么 |
|---|---|---|---|
| `JIG_MODE` | `JIG_MODE_DEBUG` | `JIG_MODE_PRODUCTION` | 下面三项自动全开 |
| `MEAS_THRESHOLDS_ENABLED` | 0 | 1 | 电压按规格门限判（调试模式用全量程，只报数不判） |
| `MEAS_CC_REQUIRED` | 0 | 1 | U2 不应答 → 判 `05 ERR_TEST` |
| `PULSE_JUDGE_ENABLE` | 0 | 1 | 两端脉冲对不上 / 两端都没信号 → 判 `05 ERR_TEST` |
| `MEAS_PRINT_ENABLE` | 调试模式且 `JIG_HAS_DEBUG_UART=1` | 关 | 调试打印（会占用 USART1） |

板级差异只写在**各工程的 Keil Define** 里（目前只有 U1 有 `JIG_HAS_DEBUG_UART=1`），不在 `jig_mode.h` 里改。

> 现场建议：**先全用调试模式**把数据看对，再切生产模式看判定，别一上来就判失败、分不清是硬件错还是门限错。

## 10. 联调完成后要做的收尾

1. **Q1**：SWD 接线核对无误 → `swd_config.h` 里 `SWD_PINS_CONFIRMED` 改 `1`。
2. **Q3 / Q4**：`DUT_VER_OFFSET` 填真值，`0x000D` 读到的版本号才有意义；被测板串口协议拿到后再实现对应命令。

6. 把 SWD 速率往上调（`SWD_DELAY_LOOPS` 8 → 4 → 2），每档都复测一次烧录（见 `docs/09` §4）。
