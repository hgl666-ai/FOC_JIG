# 07 测量功能固件框架（设计 + 实现记录）

> 依据：`docs/06_测量通道分压逆推.md`（分压比与通道映射全部来自原理图追踪）
> 状态：**U1/U2 双片已实现并通过验证**（宿主单测 95 + 764 项全过、两片 Keil 0 Error 0 Warning、
> 10 个重复文件副本一致）。数据包/命令定义见 §3，U1↔U2 交叉校验见 §4。

## 1. 这一版做了什么

把治具的 9 路模拟量接进固件，并且**把结果用一条命令交给 PC**：

```
ADC 采样 → 换算成电压 → EMA 平均 → 稳定性判定 → 打包成 55B 快照
    → ① PC: 0x000E 测量命令应答(77B)  ② U2: MEAS_XCHK 交换快照供 U1 交叉校验
```

| 文件 | 作用 | 两片关系 |
|---|---|---|
| `Core/Src/adc.c` | ADC1 配成 **10 通道扫描 + DMA1_CH1 循环搬运**（9 路 + VREFINT） | **各写各的**：信号→通道号不同（见 §2 表） |
| `Core/Inc/measure.h` / `Src/measure.c` | 信号表（k/门限/容差）、码值→电压换算、EMA、稳定性判定、测试握手、交叉校验比对、快照 | **逐字节副本** |
| `Core/Inc/meas_pack.h` / `Src/meas_pack.c` | 定长线格式编解码：快照 55B / 交叉校验块 21B / 应答 77B | **逐字节副本** |
| `U1/Core/Src/app.c` | `0x000E` 命令 + 测试状态机 + 与 U2 的 XCHK 编排 + 判定 | U1 独有 |
| `U2/Core/Src/u2_app.c` | 从机：`MEAS_XCHK` 交出自己的 55B 快照（**不做判定**） | U2 独有 |
| `test/measure_test.c` | 宿主单测（灌码值 → 断言换算/滤波/判定/快照/比对/打包） | — |

副本一致性由回归脚本第 7 阶段（`fc /b` 比对 10 个文件）机械保证，改一份忘另一份会直接判失败。

## 2. 决策记录（已确认）

| 项 | 决定 | 说明 |
|---|---|---|
| 谁采样 | **两片都采全部 9 路**（U1 检测 / U2 验证） | 硬件上是两套独立链路，交叉校验用得上 |
| 谁判定 | **只有 U1 判**（门限 + 交叉校验 + 汇总） | U2 只交数据，避免两套判定逻辑漂移 |
| 门限 | **当前是全量程 = 先不判**（用户 2026-10 决定） | 先保证"能采、能打包、能比对"；收紧只改 `measure.c` 的 `k_cfg[]` |
| 相电压 | **取平均值** | 长窗口 EMA（1/256 ≈ 10 ms）把 PWM 平均掉，见 §5 |
| 电流 | 先只报 mV | 换成安培需要被测板的采样电阻/放大倍数 |
| 结果出口 | **新增命令 `0x000E`**（mode=0 只读 / mode=1 测试） | 见 §3；`0x000F` 预留给 ④ 脉冲捕获 |
| 数据包风格 | **定长布局，不用 TLV** | 一条命令一套布局，PC 按下标取值，版本用外层 LEN 判定 |

## 3. 数据包与命令（定长，大端）

### 3.1 `0x000E` 测量

请求 DATA = **1 字节 mode**：`0x00` 只读最近一批（调试用，不触发测试）、`0x01` 触发一次测试。
应答 DATA = **77 字节**（ADC 只管 ADC；**脉冲捕获是另一条命令 `0x000F`**，见 `docs/12` §6）：

| off | size | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | 命令状态 | `0x00` OK / `0x05` ERR_TEST / `0x0C` ERR_TIMEOUT / `0x0B` ERR_PARAM |
| 1 | 55 | **快照** | 见 3.2 |
| 56 | 21 | **交叉校验块** | 见 3.3 |

### 3.2 快照（55B，`meas_pack.h`）

| off | size | 字段 |
|---|---|---|
| 0 | 1 | flags：bit0 有效 / bit1 VDDA 已校准 / bit2 溢出 / **bit3 9 路全部合格** |
| 1 | 1 | ch_count = 9 |
| 2..3 | 2 | round：采集回合号（每完成一轮扫描 +1） |
| 4..5 | 2 | dt_ms：距上一回合的毫秒数 |
| 6..7 | 2 | vdda_mv：本回合使用的 VDDA |
| 8..9 | 2 | cfg_crc：门限/容差表的指纹（追溯"判定用的哪套配置"） |
| 10..54 | 45 | 9 × 5B：`raw u16`（码值，诊断分压/饱和）+ `mv u16`（输入侧 mV）+ `flags u8`（bit0 ok / bit1 sat 贴边） |

### 3.3 交叉校验块（21B）

| off | size | 字段 |
|---|---|---|
| 0 | 1 | cc_flags：bit0 做过校验 / bit1 有超差 / **bit2 对侧(U2)无应答** |
| 1..2 | 2 | mask：超差掩码（bit0..8 对应信号序号） |
| 3..20 | 18 | U2 的 9 路 mv（便于现场判断"是 U1 测错还是 U2 测错"） |

### 3.4 U1↔U2 链路：`0x0103 MEAS_XCHK`

请求 DATA = U1 的 **55B 快照**；应答 DATA = U2 的 **55B 快照**。一次往返完成"交换"，
**比对由 U1 做**（`MEAS_Compare`，逐通道容差）：DC 通道 150~300 mV，相电压 2000 mV
（PWM 斩波 + 两片采样时刻差几十毫秒，容差必须放宽），电流 200 mV。

## 4. 测试流程（0x000E mode=1，非阻塞状态机）

```
PC ──0x000E mode=1──► U1
   APP_STATE_TESTING:
     ① MEAS_TestBegin()  : 清掉 9 路稳定计数（判定必须基于触发后的新数据）
     ② 等 MEAS_STABLE_N(=8) 次连续在门限内；超时 200ms → ERR_TIMEOUT
     ③ MEAS_Snapshot()   : 取本片 55B 快照
     ③b PULSE_CfgStart(200ms)：开脉冲捕获窗口，窗口结束取三相时序（见 docs/12）
     ④ Link_RequestStart(MEAS_XCHK, 快照) → 等 U2 的 55B（60ms 超时）
          ├─ 拿到 → MEAS_Compare() 逐通道比对 → cc_flags/mask + U2 的 9 路 mv
          └─ 没拿到 → cc_flags |= NO_PEER（默认**不因此判失败**，见 MEAS_CC_REQUIRED）
     ④b Link_RequestStart(PULSE_XCHK, 45B) → 等 U2 的 45B → 逐相比对两端频率
     ⑤ 判定: 9 路合格 且 无超差 → OK；否则 ERR_TEST
     ⑥ 回一帧 77B 应答（SEQ = 受理序号），状态回 IDLE，清接收侧半截帧
```

- 全程非阻塞：一次测试在 1 kHz 主循环里推进约 10~20 ms，
  期间 USB 侧仍能收到 BUSY 应答。
- 运行期间其它命令一律回 BUSY（与 `0x0112` 烧录时同一套不变量 I3）。
- 产线要"U2 不在就判失败"时，把 `measure.h` 的 `MEAS_CC_REQUIRED` 置 1。

## 5. 数据通路与时间预算

```
被测板信号 ──分压/直连──> 电压跟随器 ──100Ω+1nF+SMF3.3A──> ADC1 引脚
   ADC1 扫描 10 通道 ──DMA1_CH1 循环──> s_dma[10]
   MEAS_Poll(): 码值 → µV(Q4 定点) → EMA → 稳定计数 → ok/sat
   MEAS_Snapshot() → meas_pack(55B) ─┬─ 0x000E 应答(77B) ──► PC (USB)
                                     └─ MEAS_XCHK ──► U2 ──► U1 比对
```

每通道 13.5 周期采样（1.125 µs @ADCCLK 12 MHz），VREFINT 额外给 239.5 周期
（数据手册要求 ≥5.1 µs），**一轮 10 通道约 40 µs（≈25 kHz）**。
滤波窗口按扫描节拍计：直流 64 轮 ≈ 2.6 ms，相电压 256 轮 ≈ 10 ms。
55B 快照在 115200 链路上约 5 ms；PC 侧 77B 应答走 USB，可忽略。

## 6. 三个踩过的坑（都写进代码注释了）

### 6.1 整数 EMA 的死区（单测抓出来的）

`avg += (x - avg) >> shift` 在 `|x-avg| < 2^shift` 时增量被截断成 0。
若以**毫伏**为单位：shift=6 死区 ±63 mV（3.3V 通道上相当于 1.9%！），
shift=8 更是 ±255 mV。→ 改成**内部一律用微伏**，死区降到 64 µV / 256 µV。

### 6.2 滤波更新频率不能跟着主循环走

主循环频率远高于 25 kHz 的扫描率。若每次 `MEAS_Poll()` 都更新一次 EMA，
等效平均样本数会大幅减少且时间常数随环路频率漂移。
→ 用 `DMA1_Channel1->CNDTR` 回卷判断"完成了一轮扫描"，**一轮只更新一次**。

### 6.3 `*outlen` 一身二职导致静默拷 0 字节（UART 那轮踩的，链路侧同源）

链路请求的应答拷贝一开始把 `*outlen` 当"容量+长度"两个用途，调用方传 0 时
**返回成功但一个字节没拷**。→ 改成固定容量契约（缓冲必须 ≥ `LINK_MAX_PAYLOAD`）。
这次 `meas_pack` 的所有接口都按"长度显式传入 + 失败返回 0"设计，不留这个坑。

## 8. 没做 / 待确认

1. **真实门限与判据**：现在是全量程（= 不判）。需要被测板规格：24V/10V/5V/3.3V 的合格范围、
   相电压的判据（平均值还是峰峰值、与 PWM 是否同步）、两路电流的合格范围。
2. **电流换算成安培**：需要被测板的采样电阻/放大倍数（现在只报 mV）。
3. **相电压的物理含义**：运行时平均值 ≈ 占空比 × 母线；要确认相电压分压节点是否有大电容
   （没有的话全靠固件长窗口平均）。
4. **交叉校验容差需要上板标定**：现在 DC 150~300 mV、相电压 2000 mV 是估算值；
   上板后按实测的两片差值收紧，并把 `MEAS_CC_REQUIRED` 打开。
5. **VDDA 校准**：默认写死 3300 mV（LDO ±1%，比 F103 内部 VREFINT 的 ±3% 更准）。
   要跟踪漂移：标定本板 VREFINT 真实值 → 填 `MEAS_VREFINT_MV` → `MEAS_USE_VREFINT=1`。
6. **上电等待**：分压节点 100 nF，源阻抗 4.1k~17.5k → RC 0.4~1.8 ms。被测板上电更慢时
   读数会在门限边缘抖动；实测抖动就把 `MEAS_STABLE_N` 调大。
7. **DMA 撕裂读**：目前直接读 `s_dma`，理论上可能读到跨轮次混合值（40 µs 一轮，概率低且被 EMA 吸收）。
   实测异常就改成双缓冲 + 半传输标志快照。
8. **④ 脉冲捕获**：`0x000F` 已预留；MA0_OUT/MB0_OUT/MC0_OUT 走 U1 的 TIM4 输入捕获，
   MA_IN/MB_IN/MC_IN 走 U2 的 TIM3/TIM1。设计时**只需再加一种定长布局**，不用动 `0x000E`。
9. **产线可用性**：板上没有指示灯，判定结果目前只能靠 PC 命令看（已可用）。
