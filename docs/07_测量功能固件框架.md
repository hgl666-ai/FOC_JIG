# 07 测量功能固件框架（设计 + 实现记录）

> 依据：`docs/06_测量通道分压逆推.md`（分压比与通道映射全部来自原理图追踪）
> 状态：**已实现并通过验证**（宿主单测 37 项全过、Keil 0 Error 0 Warning）

## 1. 这一版做了什么

把治具的 9 路模拟量接进固件：ADC 采样 → 换算成电压 → 滤波 → 门限判定 → 串口打印。

| 文件 | 作用 |
|---|---|
| `U1/Core/Src/adc.c` | ADC1 配成 **10 通道扫描 + DMA1_CH1 循环搬运**（9 路 + VREFINT） |
| `U1/Core/Inc/measure.h` / `Src/measure.c` | 通道表、码值→电压换算、EMA 滤波、门限判定、调试打印、交叉校验接口 |
| `U1/Core/Src/main.c` | `MEAS_Init()` 在上电初始化末尾，`MEAS_Poll()` 在主循环 |
| `test/measure_test.c` | 宿主单测（灌码值 → 断言电压/滤波/判定/打印） |

**U1 与 U2 共用同一份 `measure.c`**：硬件上是两套完全独立的链路（各自的运放、ADC、引脚），
所以将来要开交叉校验时，U2 直接用这个模块即可，不需要另写一份。

## 2. 决策记录（已确认）

| 项 | 决定 | 说明 |

## 3. 数据通路

```
被测板信号 ──分压/直连──> 电压跟随器 ──100Ω+1nF+SMJ3.3A──> U1 ADC1 引脚
                                                              │
   ADC1 扫描 10 通道 ──DMA1_CH1 循环──> s_dma[10]
                                                              │
        MEAS_Poll(): 码值 → µV → EMA 滤波 → 门限 → ok/fault
                                                              │
                     MEAS_Print() ──USART1(PA9)──> 每秒一行
```

时间预算：每通道 13.5 周期采样（1.125 µs @ADCCLK 12 MHz），VREFINT 额外给 239.5 周期
（数据手册要求内部基准采样时间 ≥5.1 µs），加转换时间——
**一轮 10 通道约 40 µs（≈25 kHz）**。
滤波窗口按**扫描节拍**计：直流 64 轮 ≈ 2.6 ms，相电压 256 轮 ≈ 10 ms。

## 4. 两个踩过的坑（都写进代码注释了）

### 4.1 整数 EMA 的死区（单测抓出来的）

`avg += (x - avg) >> shift` 在 `|x-avg| < 2^shift` 时增量被截断成 0。
若以**毫伏**为单位：shift=6 死区 ±63 mV（3.3V 通道上相当于 1.9%！），
shift=8 更是 ±255 mV。→ 改成**内部一律用微伏**，死区降到 64 µV / 256 µV，
折算到输入侧 < 2 mV，可以忽略；顺带把显示精度也提上去了。

### 4.2 滤波更新频率不能跟着主循环走

主循环频率远高于 25 kHz 的扫描率。若每次 `MEAS_Poll()` 都更新一次 EMA，
**等效平均的样本数会大幅减少**（噪声抑制变差），而且窗口的时间常数随环路频率漂移。
→ 用 `DMA1_Channel1->CNDTR` 回卷判断"完成了一轮扫描"，**一轮只更新一次**。

## 5. 验证

- **宿主单测 37 项全过**（`test/measure_test.c`，被测的是真源码）：
  9 路换算精度（±1%+3 mV）、图上 24V/10V/7V 三个点的复算、
  EMA 从阶跃收敛（600 轮内到 4.000 V）、门限+连续稳定判据、饱和标记、
  满量程映射（24V 通道 26.05 V / 3.3V 通道 3.63 V / 电流 3.3 V）、
  打印格式、越界与空指针安全、交叉校验未启用状态。
- **Keil MDK：0 Error / 0 Warning**，`Code=25844 RO=624 RW=472 ZI=9208`
  → ROM 26.3 KB / 64 KB（41%），RAM 9.7 KB / 20 KB（47%）。
  测量模块本身只占约 2.5 KB Flash、约 220 B RAM（EMA 每通道只有 4 字节状态）。
- 全量回归：宿主 466 项断言全过（协议 61 + ISP 52/61/76 + 全链路 161 + 测量 37 + Python 18）。

## 6. 没做 / 待确认

1. **交叉校验未启用**：`MEAS_CrossCheck()` 现在直接返回 `MEAS_CC_DISABLED`。
   启用要做三件事：U2 用同一份 `measure.c` 采样 → 经 PB9↔PA11 上报（每秒十几字节，够用）
   → U1 比对，容差取 2~3%（两片 ADC 基准是同一路 3.3V，不必要求相等）。
2. **相电压判据**：现在只给全量程门限。运行时"平均值"的物理含义（占空比×母线）
   与合格范围要按被测板规格定；另外要确认相电压分压节点是否有大电容
   （没有的话全靠固件的长窗口平均，见 §3）。
3. **电流换算成安培**：需要被测板的采样电阻/放大倍数。
4. **门限标定**：现在的默认值不是产线判据；建议后续存进板上那颗 16 MB 外部 Flash。
5. **VDDA 校准**：默认写死 3300 mV（LDO ±1%，比 F103 内部 VREFINT 的 ±3% 还准）。
   若要跟踪漂移：标定出本板 VREFINT 真实值 → 填 `MEAS_VREFINT_MV` → `MEAS_USE_VREFINT=1`。
6. **上电等待**：分压节点有 100 nF，源阻抗 4.1k~17.5k → RC 时间常数 0.4~1.8 ms。
   固件启动很快（<5 ms）就出数，若被测板上电更慢，读数会在门限边缘抖动——
   实测发现抖动就把 `MEAS_STABLE_N` 调大。
7. **DMA 撕裂读**：目前直接读 `s_dma`，理论上可能读到跨轮次的混合值（40 µs 一轮，
   概率低且被 EMA 吸收）。若实测有异常，改成双缓冲 + 半传输标志快照。
8. **频率/占空比测量**（MA0_OUT/MB0_OUT/MC0_OUT 走 U1 的 TIM4 输入捕获，
   MA_IN/MB_IN/MC_IN 走 U2 的 TIM3/TIM1）——属于另一个模块，还没设计。
9. **协议上报**：xlsx 里没有测量命令，且板上**没有指示灯**，所以判定结果目前只能靠
   调试串口看。要产线可用，得扩协议或加指示灯。
