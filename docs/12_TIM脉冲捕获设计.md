# 12 TIM 输入捕获：测三相 PWM 的频率 / 占空比（设计 + 实现记录）

> ⚠⚠ **2026-10 重大更正：本文的"测什么"是错的，硬件上不成立。**
> 原版认为 **U1 用 TIM4 捕获电机输出端 MA0_OUT/MB0_OUT/MC0_OUT**。
> 经原理图文字坐标逐脚复核（`docs/00` §3.5/§3.6），实际接线是：
>
> | | 事实 |
> |---|---|
> | `PB6/PB7/PB8`（TIM4_CH1/2/3） | 接的是**编码器座 CN2** 的 A/B/Z，带 3kΩ 上拉到 3.3V + TVS。**不是电机输出端。** |
> | `MA0_OUT/MB0_OUT/MC0_OUT` | **只到 ADC**（140k/20k 分压 → 缓冲 → 100Ω+1nF+TVS）。**没有任何定时器通路。** |
> | `MA_IN/MB_IN/MC_IN` | U1 和 U2 **都**接（PB5/PB4/PA8），路径上无任何元件 |
>
> 后果：**改之前代码里 `0x000F` 的两端对比没有物理意义** —— 它拿"U1 采到的编码器 A/B/Z"
> 和"U2 采到的 MCU 驱动信号"互判"两端一致"，这两组是毫不相干的信号。
> **✅ 已于 2026-10 修好（见 §10）**：两片现在测**同一组**信号、做真冗余互比。
> 时序捕获的**算法层、线格式、ARM 同步窗口全都没动**，只改了"哪片测哪组"的绑定。

> 用户已批准的四个决定（2026-10）：
> ① ~~U1 测**电机输出端**，U2 测**主控驱动信号**~~ → **见上面的更正，改为两片测同一组**；
> ② 频率范围做宽（10 Hz ~ 60 kHz）；③ 结果并入 `0x000E`，一次测试自动含脉冲捕获；
> ④ 三相上桥 PWM（3 路独立），不判死区。

## 1. 测什么（物理含义）

```
被测板 MCU ──PWM──►[MA_IN/MB_IN/MC_IN]──► 栅极驱动 ──►[MA0_OUT/MB0_OUT/MC0_OUT]──► 电机
                        │                                    │
              U1 和 U2 都接（TIM3/TIM1）                  只到 ADC（无 TIM 通路）
                                                       （140k/20k，见 docs/00 §3.5）

编码器 ──A/B/Z──►[CN2]──► U1 和 U2 都接（TIM4_CH3/CH2/CH1，3kΩ 上拉 3.3V + TVS）
```

| 谁测 | 测哪个点 | 引脚/通道 | 能验证什么 |
|---|---|---|---|
| **U1** | 主控驱动信号 MA_IN/MB_IN/MC_IN | TIM3_CH2(PB5) / TIM3_CH1(PB4) / TIM1_CH1(PA8) | 被测板 MCU **有没有发出 PWM**、频率/占空比对不对 |
| **U2** | **同一组** MA_IN/MB_IN/MC_IN | TIM3_CH2(PB5) / TIM3_CH1(PB4) / TIM1_CH1(PA8) | 同上 —— 两片测同一个信号 = **真冗余互比**（和 9 路 ADC 一套哲学） |
| （不被本命令使用） | 编码器 A/B/Z | TIM4_CH3/CH2/CH1(PB8/PB7/PB6) | 留给编码器检测（⑤）。**两片都挂在这三根线上，可做"一片发、另一片收"的回环** |

**为什么改成两片测同一组**：两条信号的物理含义是"输入端 vs 输出端"，而**输出端没有定时器通路**，
原来那个"同一相两端"的对比在硬件上无法成立。改成两片测同一组之后，
`PulsePack_Compare` 的"两端周期一致"才真正是"治具自己可信"的证据（与 `0x000E` 的交叉校验同构）。

**电机输出端（④）改走 ADC**：相电压那一路有 140k/20k 分压，U1 读平均值。
于是 ③ 和 ④ 的联系变成一条更硬的判据：

```
③ 给出占空比 D（U2 捕获 MA_IN 组）  →  V_相电压平均值 ≈ D × 母线电压  ←  ④ 给出相电压（ADC，k=0.125）
```

它同时验证了驱动级有没有正常工作**和**母线电压采样对不对。
**这条判据已经实现**：`U1/Core/{Inc,Src}/phase_chk.c`（纯函数 + 62 项宿主单测），
"静态电平"只是它的 `D=0 / D=1000` 两个端点，不用另写一套。
（变通方案：U1 的 `PA6/PA7/PB0` 恰好也是 `TIM3_CH1/CH2/CH3` 复用脚，改成输入捕获就能直接测
电机输出端的周期 —— 代价是 U1 失去三相电压读数。**当前决定不做**，见 `docs/00` §3.5。）

## 2. ⚠ 一并修掉的硬件隐患

改之前 `tim.c`（两片）把 TIM4 / TIM3 / TIM2 都配成了 **PWM 输出**（`HAL_TIM_MspPostInit` 把
PB6/PB7/PB8、PB4/PB5、PA8 等配成 `AF_PP` 推挽），虽然从没调用 `HAL_TIM_PWM_Start`，
但引脚是**输出态且输出常低**：

- **PB6/PB7/PB8 是编码器座 CN2 的 A/B/Z**（2026-10 更正：原版写成"经 3kΩ 接被测板的三相输出节点"，错）。
  这三个脚**U1 和 U2 都接着**，线上还有 3kΩ 上拉、TVS，以及可能插着的编码器（集电极开路输出）。
  两片再各加一个**推挽输出常低** → 同一根线上三个驱动源，编码器信号被压死，
  编码器输出级还可能被灌电流。
- PB4/PB5/PA8 是 `MA_IN/MB_IN/MC_IN`，**同样 U1 和 U2 都接**，且线上没有任何元件；
  两片都推挽输出常低就是把被测板 MCU 的 PWM 输出往下拽。

改法（`docs/05` §2.5 有再生成须知）：目标通道改**输入捕获**，用不到的定时器引脚一律配成
`GPIO_MODE_INPUT + PULLDOWN`（下拉还有个好处：被测板不在时读到 0 → 干净地判"没信号"）。

> **后续做 ⑤ 编码器激励时的约束**（别把上面这个坑再踩一遍）：
> 要驱动 CN2 的 A/B/Z，**同一时刻只能有一片把它配成输出**，另一片必须保持输入；
> 发完脉冲要把脚**收回输入态**。这条必须写进内部链路协议（`docs/13`）与 DUT 协议（`docs/15`）。

## 3. 测量方法选型

| 方案 | 说明 | 结论 |
|---|---|---|
| A. 硬件 PWM 输入模式 | 精度最高，但**每个信号占 2 个捕获通道** | ❌ U1 的 TIM4 只有 4 通道，3 相要 6 个 |
| B. **单通道双边沿捕获 + 软件算** | 1 相占 1 通道 | ✅ 选用，两片同一套代码 |
| C. DMA 搬 CCR | 更省中断 | ⏸ 暂不考虑。当初的否决理由是"U1 的 TIM4_CH1 只能映射到 DMA1_CH1，而它被 ADC 占了"（`docs/07` §2：ADC1 用 DMA1_CH1）；绑定改到 TIM3/TIM1 之后这个理由要重新核一遍，但方案 B 已经够用 |

**时基**：PSC=0 → 72 MHz → **1 tick = 125/9 ns ≈ 13.888 ns**
- 20 kHz → 一周期 3600 tick → 占空比分辨率 **0.03%**
- 16 位计数器 910 µs 溢出一次 → 中断里扩展成 **32 位时间戳**（诊断：溢出与捕获的相对
  顺序有讲究，见 §5）
- 可测范围：**10 Hz ~ 60 kHz**（下限由"窗口内至少要 2 个周期"决定；上限由
  `PULSE_MIN_PERIOD_TICK` 与中断负载决定），超出范围会置 `PULSE_F_RANGE` 标志

**CPU 负载**：20 kHz × 3 相 × 2 边沿 = **12 万次中断/秒**，中断里只存时间戳（约 40~60 周期）
≈ 5~10%。所以：
- **U1 是"按需窗口"**：只在 `0x000E mode=1` 的测试里开 200 ms，平时**零负载**；
- **U2 是"滚动窗口"**：一个 200 ms 窗口接一个地跑（U2 没别的活），这样 U1 一问就有
  ≤200 ms 的新鲜结果，不需要事先打招呼；
- 捕获中断优先级 **4**（USB=0、串口=3、捕获=4）→ 不影响 USB / 串口 / SWD 烧录。

## 4. 分层与文件

| 文件 | 作用 | 两片关系 |
|---|---|---|
| `Core/Inc` + `Core/Src` 里的 `pulse_cap.{h,c}` | **算法层**：边沿时间戳 → 周期/高电平/占空比。不认识定时器/引脚/HAL | **逐字节副本** |
| `Core/Inc` + `Core/Src` 里的 `pulse_pack.{h,c}` | **线格式**：45B 一组三相结果 + 两端对比判据 | **逐字节副本** |
| `Core/Src/pulse_cfg.c` | **硬件层**：相位→(定时器,通道) 绑定、精简捕获中断、极性翻转、溢出扩展、窗口开关 | 各写各的 |
| `Core/Src/tim.c` | CubeMX 生成：通道配输入捕获、引脚配输入、NVIC | 各写各的 |
| `U1/Core/Src/app.c` | 测试流程里插入脉冲窗口 + 与 U2 交换 + 判定 + 组装 91B 应答（`0x000F`） | U1 独有 |
| `U2/Core/Src/u2_app.c` | `PULSE_XCHK` 应答（交出自己的 45B）+ 滚动窗口 | U2 独有 |

```
应用层   app.c（测试流程里的脉冲窗口）/ u2_app.c（交出结果）
   ↑↓ 结构体 pulse_snapshot_t / PulsePack_*
打包层   pulse_pack.c   45B 定长：头部6B + 3相×13B
   ↑↓ 边沿时间戳
算法层   pulse_cap.c    环形缓冲(每相32个边沿) + 分组中位数剔离群 + 分组平均
   ↑↓ PULSE_OnEdge(相, tick)
硬件层   pulse_cfg.c    TIM 寄存器：SR/CCR/CCER、溢出扩展、极性翻转
   ↑↓ 电平边沿
硬件     U1: TIM3 CH2/CH1 + TIM1 CH1 ← MA_IN/MB_IN/MC_IN（与 U2 同一组信号）
         U2: TIM3 CH2/CH1 + TIM1 CH1 ← MA_IN/MB_IN/MC_IN
         （两片的 TIM4 CH3/CH2/CH1 = PB8/PB7/PB6 接的是编码器座 CN2，本命令不用）
```

**算法约定（决定了能不能算对）**：每个边沿捕获后**翻转极性** → 从窗口开始算，
第 0、2、4… 个边沿是上升沿，第 1、3、5… 是下降沿 → 相邻间隔交替是
"高电平时间"和"低电平时间"。

## 5. 实现里三个关键点（都是踩过或差点踩的）

1. **占空比不能用"高电平总和 / 总时间"**：高低两组的样本数可能差 1（最后一个区间不完整），
   直接相除会让占空比整体偏移 —— 20 kHz/50% 会算成 **34.7%**（单测抓出来的）。
   正确做法：**高、低各自取平均，再合成** `duty = avg_high / (avg_high + avg_low)`。
2. **离群剔除要"分组"做**：毛刺/丢沿会产生异常区间，用中位数剔除；但必须**高、低两组各自**
   取中位数 —— 占空比 10% 时高电平段天生比低电平段短得多，用全体中位数会把正常的高电平段
   全当异常丢掉。规则：偏离本组中位数 1/2~3/2 之外就丢，并置 `PULSE_F_DIRTY`。
3. **溢出与捕获的相对顺序**：中断里先读 SR（同时拿到"哪个通道捕获了"和"有没有溢出"），
   再读 CCR（读动作清标志）。若 **UIF 置位且 CCR < 0x8000** → 说明"先溢出、后捕获"，
   这一拍必须按 `溢出次数+1` 记，否则时间戳少 65536 tick，区间直接算错。

## 6. 数据格式与命令（定长，不用 TLV）

脉冲走**独立的一条命令 `0x000F`**（用户 2026-10 决定：不糅进 `0x000E`，ADC 与 TIM 各一条命令）：
请求 DATA = 1 字节 mode（`00` 只读最近一个窗口 / `01` 触发一次 200ms 捕获），应答 DATA = **91 字节**：

| off | size | 段 |
|---|---|---|
| 0 | 1 | 命令状态（00 OK / 05 ERR_TEST / 0B ERR_PARAM） |
| 1 | **45** | **本片（U1）脉冲结果 —— 测 MA_IN/MB_IN/MC_IN 组** |
| 46 | **45** | **对侧（U2）脉冲结果 —— 同一组信号，用于冗余互比** |

ADC 那边是另一条命令 `0x000E`（应答 77B = 状态 + 55B 快照 + 21B 交叉校验块，见 `docs/07` §3），
两条命令互不影响、可单独调用；PC 想"一次测全"就连发两条。

45B 脉冲段布局：头部 6B（ver/flags/window_ms/phase_count/rsvd）+ **3 相 × 13B**：

| off | size | 字段 |
|---|---|---|
| 0..3 | 4 | `period_ns` 周期（纳秒，0 = 没测到） |
| 4..7 | 4 | `high_ns` 高电平时间（纳秒） |
| 8..9 | 2 | `duty_permille` 占空比 ×1000（500 = 50.0%） |
| 10..11 | 2 | `edges` 窗口内边沿总数 |
| 12 | 1 | flags：bit0 有效 / bit1 没信号 / bit2 超范围 / bit3 有离群 / bit4 与对侧不一致 |

链路侧：`LINK_CMD_PULSE_XCHK (0x0104)` —— 请求 = U1 的 45B，应答 = U2 的 45B（≤64B 单帧）。
链路代码版本曾随本节升到 `LINK_CODE_VER = 0x0103`（2026-10 更正：原版写 `0x0102`，是旧值）；
**现在以 `uart_link.h` 为准，当前值 `0x0104`**（v1.4 新增 `0x0109` ENC_XCHK，见 `docs/13` §5.10）。
**两片都要重烧**，否则 STATUS 比对会报不一致。

## 7. 测试流程（`0x000F` mode=1）

> 2026-10 更新：流程前面**加了 `0x0105` ARM 同步触发**（见 `docs/13` §5.5/§6.2）——
> U1 先喊一声"开始"，两端在**同一个时间窗**里各采 200ms，然后再交换结果。
> 在此之前两片是"各采各的"（U1 按需、U2 滚动），交换回来的可能是两段不同时刻的波形。

```
PC ──0x000F mode=1──► U1
  ⓪ ARM(session, 200ms) → U2 收到即开窗；U1 同时开自己的窗（错位 < 2ms）
  ① 等 9 路电压稳定（MEAS_STABLE_N 次）        ≈ 10 ms
  ② PULSE_CfgStart(200ms)：开捕获窗口          ≈ 200 ms
  ③ 窗口结束 → PULSE_Snapshot（本片 = U1 的 MA_IN 组结果）
  ④ MEAS_XCHK 交换 55B 电压快照 → 逐通道比对
  ⑤ PULSE_XCHK 交换 45B 脉冲结果 → 逐相比对
  ⑥ 汇总判定 → 回一帧 **91B** 应答（`0x000F`，SEQ = 受理序号）
```

**判定（默认先不判，与 ③ 同一套哲学）**：
- `PULSE_JUDGE_ENABLE = 0`（默认）：只把结果和差异标记放进应答，不因脉冲问题判失败；
- 置 1 后判失败的两条：**两端对不上**（一端有信号另一端没有 / 周期差 > `PULSE_PEER_TOL_PPM` = 1%）、
  **两端都没信号**；
- **占空比只记录不判**：死区、驱动延时会让输入/输出两端的占空比天然不同，拿它当判据会误报。

## 9. 没做 / 待确认

1. **上板标定**：频率读数是"数出来的"，很可信；但容差（1%）和"两端占空比不判"这两条
   要按实测再定，然后打开 `PULSE_JUDGE_ENABLE`。
2. **死区**：按用户确认，这 3 路是三相上桥 PWM，不判死区（要判的话得再接 3 路下桥信号）。
3. ~~**硬件复核建议**：`MA0_OUT` 是 24V 级信号，原理图上只看到 3kΩ 串阻 + SMF3.3A 进 MCU 引脚，
   TVS 钳位电压可能高于引脚允许的 3.6 V~~ —— **2026-10 撤回**。
   那条推断基于"PB6/PB7/PB8 接电机输出端"这个错误前提；实际那组 3kΩ 是**编码器 CN2 的上拉**。
   真正的相电压那一路有 140k/20k 分压（24 V → 3.0 V），**安全，不需要硬件确认**。
4. **U2 的滚动窗口**：现在 200 ms 一个窗口不间断地跑。若将来 U2 加了别的重活，可以改成
   "U1 先打招呼再采"（多一次链路往返）。
5. **60 kHz 以上**：中断负载会超过 30%，需要改成 DMA 或降低窗口内的相数，暂不支持。

## 10. 把"哪片测哪组"改对（**✅ 2026-10 已完成**）

算法层（`pulse_cap.c`）、线格式（`pulse_pack.c`）、ARM 同步窗口、45B 布局**全都没动**，
只改了两片的**相位→通道绑定**，并把 `pulse_cfg.{c,h}` 做成两片**逐字节副本**：

| 文件 | 改前 | 改后 |
|---|---|---|
| `U1/Core/Src/pulse_cfg.c` | 相位 A/B/C → `TIM4` CH3/CH2/CH1（= CN2 编码器线） | 相位 A/B/C → `TIM3_CH2(PB5)` / `TIM3_CH1(PB4)` / `TIM1_CH1(PA8)`，与 U2 完全一致 |
| `U1/Core/Src/tim.c` | TIM1 = OC 输出、TIM3 = PWM 输出、TIM4 = 输入捕获 | TIM1/TIM3 改**输入捕获**；TIM4 引脚保持输入（留给 ⑤） |
| `U1/Core/Inc/pulse_cfg.h` | U1 版（TIM4） | 与 U2 **逐字节相同**（回归副本阶段 11/12 的 `fc /b` 比对） |
| `pulse_pack.c` / `pulse_cfg.c` 注释 | 写着"U1 测电机输出端" | 改成"两片都测 MA_IN 组，互为冗余" |

**验证**：两片 Keil **0 Error / 0 Warning**；U1 ROM 反而小了 **1160 B**
（去掉 OC/PWM 那条初始化路径：`HAL_TIM_Base_Init` + `HAL_TIM_ConfigClockSource` +
`HAL_TIMEx_ConfigBreakDeadTime`），RAM +8 B；回归 **ALL PASS**，17 对副本逐字节一致。

两个曾经担心过的约束，结论都是**没问题**：

1. **U1 要采 `MA_IN/MB_IN` 必须走 `PB4/PB5`，不能走默认的 `PA6/PA7`**（那是 U1 的 A/B 相 ADC 脚）。
   `PB4/PB5` 是 `TIM3_CH1/CH2` 的**部分重映射**脚，原理图上 U1/U2 的 PB4/PB5 都标着 `TIM3_CH1/CH2`，
   **U2 本来用的就是这两个脚** → U1 直接照抄 U2 的 `tim.c` 即可，**没有牺牲任何 ADC 通道**。
2. `TIM1_CH1 = PA8` 与 `MC_IN` 一致，无冲突。
