# 12 TIM 输入捕获：测三相 PWM 的频率 / 占空比（设计 + 实现记录）

> 用户已批准的四个决定（2026-10）：
> ① U1 测**电机输出端** MA0_OUT/MB0_OUT/MC0_OUT，U2 测**主控驱动信号** MA_IN/MB_IN/MC_IN；
> ② 频率范围做宽（10 Hz ~ 60 kHz）；③ 结果并入 `0x000E`，一次测试自动含脉冲捕获；
> ④ 三相上桥 PWM（3 路独立），不判死区。

## 1. 测什么（物理含义）

```
被测板 MCU ──PWM──►[MA_IN/MB_IN/MC_IN]──► 栅极驱动 ──►[MA0_OUT/MB0_OUT/MC0_OUT]──► 电机
                        │                                    │
                   进 U2（TIM3/TIM1）                    进 U1（TIM4，经 3kΩ）
```

| 谁测 | 测哪个点 | 引脚/通道 | 能验证什么 |
|---|---|---|---|
| **U2** | 主控驱动信号 MA_IN/MB_IN/MC_IN | TIM3_CH2(PB5) / TIM3_CH1(PB4) / TIM1_CH1(PA8) | 被测板 MCU **有没有发出 PWM**、频率/占空比对不对 |
| **U1** | 电机接口 MA0_OUT/MB0_OUT/MC0_OUT | TIM4_CH3(PB8) / CH2(PB7) / CH1(PB6) | 驱动级**有没有把 PWM 变成输出波形** |

**与 ③ 的区别（别混）**：③ 里两片测的是**同一个信号**（互验治具自己）；
④ 里两片测的是**同一相的两端**（输入端 vs 输出端）→ 验证被测板通路：
"输入端有 PWM、输出端就该有对应波形；输出端没有 = 驱动级或接线问题"。

U1 的 TIM4 脚与它的相电压 ADC 脚接的是**同一个节点** → ③ 给"电压/平均值"，④ 给"频率/占空比"，互补。

## 2. ⚠ 一并修掉的硬件隐患

改之前 `tim.c`（两片）把 TIM4 / TIM3 / TIM2 都配成了 **PWM 输出**（`HAL_TIM_MspPostInit` 把
PB6/PB7/PB8、PB4/PB5、PA8 等配成 `AF_PP` 推挽），虽然从没调用 `HAL_TIM_PWM_Start`，
但引脚是**输出态且输出常低**：

- PB6/PB7/PB8 经 3kΩ 接被测板的**三相输出节点** → 会把节点往下拉，
  **连带把 ③ 的相电压读数拉低**；
- 等于治具的输出脚和被测板的输出脚**对打**。

改法（`docs/05` §2.5 有再生成须知）：目标通道改**输入捕获**，用不到的定时器引脚一律配成
`GPIO_MODE_INPUT + PULLDOWN`（下拉还有个好处：被测板不在时读到 0 → 干净地判"没信号"）。

## 3. 测量方法选型

| 方案 | 说明 | 结论 |
|---|---|---|
| A. 硬件 PWM 输入模式 | 精度最高，但**每个信号占 2 个捕获通道** | ❌ U1 的 TIM4 只有 4 通道，3 相要 6 个 |
| B. **单通道双边沿捕获 + 软件算** | 1 相占 1 通道 | ✅ 选用，两片同一套代码 |
| C. DMA 搬 CCR | 更省中断 | ❌ U1 的 TIM4_CH1 只能映射到 DMA1_CH1，而它被 ADC 占了 |

**时基**：PSC=0 → 72 MHz → **1 tick = 125/9 ns ≈ 13.888 ns**
- 20 kHz → 一周期 3600 tick → 占空比分辨率 **0.03%**
- 16 位计数器 910 µs 溢出一次 → 中断里扩展成 **32 位时间戳**（诊断：溢出与捕获的相对
  顺序有讲究，见 §5）
- 可测范围：**10 Hz ~ 60 kHz**（下限由"窗口内至少要 2 个周期"决定；上限由
  `PULSE_MIN_PERIOD_TICK` 与中断负载决定），超出范围会置 `PULSE_F_RANGE` 标志

**CPU 负载**：20 kHz × 3 相 × 2 边沿 = **12 万次中断/秒**，中断里只存时间戳（约 40~60 周期）
≈ 5~10%。所以：
- **U1 是"按需窗口"**：只在 `0x000E mode=1` 的测试里开 200 ms，平时**零负载**；
- **U2 是"滚动窗口"**：一个 200 ms 窗口接一个地跑（U2 没别的活），这样 U1 一问就有
  ≤200 ms 的新鲜结果，不需要事先打招呼；
- 捕获中断优先级 **4**（USB=0、串口=3、捕获=4）→ 不影响 USB / 串口 / SWD 烧录。

## 4. 分层与文件

| 文件 | 作用 | 两片关系 |
|---|---|---|
| `Core/Inc|Src/pulse_cap.{h,c}` | **算法层**：边沿时间戳 → 周期/高电平/占空比。不认识定时器/引脚/HAL | **逐字节副本** |
| `Core/Inc|Src/pulse_pack.{h,c}` | **线格式**：45B 一组三相结果 + 两端对比判据 | **逐字节副本** |
| `Core/Src/pulse_cfg.c` | **硬件层**：相位→(定时器,通道) 绑定、精简捕获中断、极性翻转、溢出扩展、窗口开关 | 各写各的 |
| `Core/Src/tim.c` | CubeMX 生成：通道配输入捕获、引脚配输入、NVIC | 各写各的 |
| `U1/Core/Src/app.c` | 测试流程里插入脉冲窗口 + 与 U2 交换 + 判定 + 组装 91B 应答（`0x000F`） | U1 独有 |
| `U2/Core/Src/u2_app.c` | `PULSE_XCHK` 应答（交出自己的 45B）+ 滚动窗口 | U2 独有 |

```
应用层   app.c（测试流程里的脉冲窗口）/ u2_app.c（交出结果）
   ↑↓ 结构体 pulse_snapshot_t / PulsePack_*
打包层   pulse_pack.c   45B 定长：头部6B + 3相×13B
   ↑↓ 边沿时间戳
算法层   pulse_cap.c    环形缓冲(每相32个边沿) + 分组中位数剔离群 + 分组平均
   ↑↓ PULSE_OnEdge(相, tick)
硬件层   pulse_cfg.c    TIM 寄存器：SR/CCR/CCER、溢出扩展、极性翻转
   ↑↓ 电平边沿
硬件     U1: TIM4 CH1/2/3 ← MA0/MB0/MC0_OUT（3kΩ）
         U2: TIM3 CH1/2 + TIM1 CH1 ← MB/MA/MC_IN
```

**算法约定（决定了能不能算对）**：每个边沿捕获后**翻转极性** → 从窗口开始算，
第 0、2、4… 个边沿是上升沿，第 1、3、5… 是下降沿 → 相邻间隔交替是
"高电平时间"和"低电平时间"。

## 5. 实现里三个关键点（都是踩过或差点踩的）

1. **占空比不能用"高电平总和 / 总时间"**：高低两组的样本数可能差 1（最后一个区间不完整），
   直接相除会让占空比整体偏移 —— 20 kHz/50% 会算成 **34.7%**（单测抓出来的）。
   正确做法：**高、低各自取平均，再合成** `duty = avg_high / (avg_high + avg_low)`。
2. **离群剔除要"分组"做**：毛刺/丢沿会产生异常区间，用中位数剔除；但必须**高、低两组各自**
   取中位数 —— 占空比 10% 时高电平段天生比低电平段短得多，用全体中位数会把正常的高电平段
   全当异常丢掉。规则：偏离本组中位数 1/2~3/2 之外就丢，并置 `PULSE_F_DIRTY`。
3. **溢出与捕获的相对顺序**：中断里先读 SR（同时拿到"哪个通道捕获了"和"有没有溢出"），
   再读 CCR（读动作清标志）。若 **UIF 置位且 CCR < 0x8000** → 说明"先溢出、后捕获"，
   这一拍必须按 `溢出次数+1` 记，否则时间戳少 65536 tick，区间直接算错。

## 6. 数据格式与命令（定长，不用 TLV）

脉冲走**独立的一条命令 `0x000F`**（用户 2026-10 决定：不糅进 `0x000E`，ADC 与 TIM 各一条命令）：
请求 DATA = 1 字节 mode（`00` 只读最近一个窗口 / `01` 触发一次 200ms 捕获），应答 DATA = **91 字节**：

| off | size | 段 |
|---|---|---|
| 0 | 1 | 命令状态（00 OK / 05 ERR_TEST / 0B ERR_PARAM） |
| 1 | **45** | **U1 脉冲结果（三相输出端）** |
| 46 | **45** | **U2 脉冲结果（三相驱动输入端）** |

ADC 那边是另一条命令 `0x000E`（应答 77B = 状态 + 55B 快照 + 21B 交叉校验块，见 `docs/07` §3），
两条命令互不影响、可单独调用；PC 想"一次测全"就连发两条。

45B 脉冲段布局：头部 6B（ver/flags/window_ms/phase_count/rsvd）+ **3 相 × 13B**：

| off | size | 字段 |
|---|---|---|
| 0..3 | 4 | `period_ns` 周期（纳秒，0 = 没测到） |
| 4..7 | 4 | `high_ns` 高电平时间（纳秒） |
| 8..9 | 2 | `duty_permille` 占空比 ×1000（500 = 50.0%） |
| 10..11 | 2 | `edges` 窗口内边沿总数 |
| 12 | 1 | flags：bit0 有效 / bit1 没信号 / bit2 超范围 / bit3 有离群 / bit4 与对侧不一致 |

链路侧：`LINK_CMD_PULSE_XCHK (0x0104)` —— 请求 = U1 的 45B，应答 = U2 的 45B（≤64B 单帧）。
链路代码版本随之升到 `LINK_CODE_VER = 0x0102`（**两片都要重烧**，否则 STATUS 比对会报不一致）。

## 7. 测试流程（`0x000F` mode=1）

```
PC ──0x000F mode=1──► U1
  ① 等 9 路电压稳定（MEAS_STABLE_N 次）        ≈ 10 ms
  ② PULSE_CfgStart(200ms)：开捕获窗口          ≈ 200 ms
  ③ 窗口结束 → PULSE_Snapshot（本片 = 输出端）
  ④ MEAS_XCHK 交换 55B 电压快照 → 逐通道比对
  ⑤ PULSE_XCHK 交换 45B 脉冲结果 → 逐相比对
  ⑥ 汇总判定 → 回一帧 **91B** 应答（`0x000F`，SEQ = 受理序号）
```

**判定（默认先不判，与 ③ 同一套哲学）**：
- `PULSE_JUDGE_ENABLE = 0`（默认）：只把结果和差异标记放进应答，不因脉冲问题判失败；
- 置 1 后判失败的两条：**两端对不上**（一端有信号另一端没有 / 周期差 > `PULSE_PEER_TOL_PPM` = 1%）、
  **两端都没信号**；
- **占空比只记录不判**：死区、驱动延时会让输入/输出两端的占空比天然不同，拿它当判据会误报。

## 9. 没做 / 待确认

1. **上板标定**：频率读数是"数出来的"，很可信；但容差（1%）和"两端占空比不判"这两条
   要按实测再定，然后打开 `PULSE_JUDGE_ENABLE`。
2. **死区**：按用户确认，这 3 路是三相上桥 PWM，不判死区（要判的话得再接 3 路下桥信号）。
3. **硬件复核建议**：`MA0_OUT` 是 24V 级信号，原理图上只看到 **3kΩ 串阻 + SMF3.3A** 进 MCU 引脚。
   若确实没有分压网络，TVS 钳位电压可能高于引脚允许的 3.6 V —— 请硬件确认（ADC 那一路有
   140k/20k 分压，TIM 这一路没看到分压）。
4. **U2 的滚动窗口**：现在 200 ms 一个窗口不间断地跑。若将来 U2 加了别的重活，可以改成
   "U1 先打招呼再采"（多一次链路往返）。
5. **60 kHz 以上**：中断负载会超过 30%，需要改成 DMA 或降低窗口内的相数，暂不支持。
