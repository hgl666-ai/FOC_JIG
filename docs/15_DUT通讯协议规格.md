## 0. 先读这一节：被测板要扮演什么角色

> **先把"功率"这件事说准**（2026-10 补充）：
> 治具**是给被测板供电的** —— 顶针下压时由治具 CN2 第 1 脚送 **5V** 给被测板（板子自己的 3.3V 由它自己产生）。
> 治具**没有的是"功率级"**：它没有 **24V 母线**、没有**三相逆变桥**、不能推三相电流、不能驱动电机。
> 所以 ③④⑥ 说的"激励"（PWM / 相电压 / 相电流）**只能由被测板自己的功率级产生**；
> 而④⑥ 要真的动起来，还需要被测板的 **24V（和 10V 栅极驱动）母线带电** ——
> 这一路治具**既没有输入口、也只测不供**（原理图上 24V 那路是"被测点输入"，经 32.4k/4.7k 分压进 ADC）。
> **产线工位那 24V 由谁供，是 §13 D10 待确认项**，它直接决定 ④⑥ 能不能在产线上跑。

硬件上治具**唯一能向外驱动信号的引脚**是编码器座 CN2 的 A/B/Z 三根 3.3V 逻辑线，
其余接板外的脚（9 路模拟量、相电压、电流检测）**全是输入**。

所以整个测试的分工是：**被测板出激励（电压/电流/PWM），治具测量并判定；只有 ⑤ 反过来。**

> **测试时被测板不接电机**（2026-10 用户确认：产线只是看它自己这几路输出对不对）。
> 这条对四项的影响不一样，**别想当然**：
> - **③ 完全不受影响**：治具量的是 MCU 引脚上的 PWM。
> - **④ 不受影响、但母线必须带电**：④ 量的是**桥臂输出端的电压本身**（经 140k/20k 分压进 ADC，
>   开关节点在高/低之间切换，其平均值 = 占空比 × 母线电压），与有没有电机无关；
>   但**没有母线电压就是全 0**，所以仍要 §13 D10 那一路 24V。
> - **⑥ 受影响，而且很关键**：静态通流靠的是
>   `母线 → 上管A → A 相出线 →（电机）→ B 相出线 → 下管B → 采样电阻 → 地`。
>   **不接电机 = 这条回路断开 = 没有电流**，电流检测链路（采样电阻 + 放大器 + 增益）
>   就**测不到**，只能量到放大器的零点/基准。怎么办见 §13 D11。
> - **⑤ 完全不受影响**：治具自己发脉冲。
>
> 另外一个好处：进了测试模式控制环是停的，**不会因为"没接电机"而报过流/缺相/失速**跑飞。

| 任务 | 激励（脉冲/电压/电流）谁发 | 治具怎么收 | 被测板要做什么 | 治具侧现在 |
|---|---|---|---|---|
| ① 通讯协议本身 | —（命令/应答，不是脉冲） | — | 按本文实现从机 | ✅ 已实现 |
| ② 电压检测 | **被测板**（它自己的 24V/10V/5V/3.3V 母线） | ADC 读 9 路 | 上报自己采的同一批电压（`0x0207`） | ✅ `0x0015` |
| ③ MCU 脉冲检测 | **被测板**（FOC 的 PWM 输出 `MA_IN/MB_IN/MC_IN`） | TIM 输入捕获（周期/占空比） | 进测试模式 + 输出已知 PWM（`0x0204`） | ✅ `0x000F` |
| ④ 三相输出检测 | **被测板**（它自己的三相功率输出） | ADC 读相电压 + 用③的占空比判 `V ≈ D × 母线` | 输出指定 PWM 或**静态电平**（`0x0204`/`0x0205`） | ✅ `0x0016` |
| ⑤ 编码器检测 | **治具**（U1 用 TIM4 在 CN2 的 A/B/Z 上发） | U2 在**同一组线**上旁听（回环自证） | 进测试模式（**清编码器计数**）+ 上报计数（`0x0202`/`0x0208`） | ✅ `0x0012`+`0x0013` |
| ⑥ 相电流检测 | **被测板**（它自己**静态通流**，不是 PWM） | ADC 读电流检测 1/2 | 产生电流 + 上报自己采的值（`0x0206`/`0x0207`） | ✅ `0x0014` |

> **两个容易误解的地方**（早期需求里写成"发脉冲给 FOC 检测"，实现时按物理能力定了）：
> 1. **③④ 的脉冲是被测板自己发的**，治具只负责"收 + 判"。治具能驱动的只有 CN2 那三根线，
>    接不到 FOC 的定时器输入或功率级 —— 想让治具"给 FOC 发脉冲让它检测"在硬件上做不到。
>    ④ 想要的"简单点、直接探测高低电平"**已支持**：`0x0205 LEVEL` 让被测板输出静态高/低/高阻，
>    治具用 `0x0016 mode=0`（静态判据）量电压。
> 2. **⑥ 用的是静态直流通流**，不是 PWM 脉冲：让被测板在指定两个桥臂间通一个恒定电流
>    （如 A→B、100%、200 ms），治具读电流采样放大器的输出。用直流不用 PWM 的原因：
>    PWM 下电流是脉动的、两边采样时刻对不齐，比出来的数没有意义。

## 1. 这份协议要解决什么

治具要在**烧完固件之后**对 FOC 板做功能测试，其中几件事必须由被测板自己配合：

| 任务 | 治具能做的 | **必须由 DUT 配合的** |
|---|---|---|
| ③ FOC MCU 脉冲检测 | 采 `MA_IN/MB_IN/MC_IN` 的频率/占空比 | **输出一段已知的 PWM** |
| ④ 三相输出检测 | 读三相电压平均值（ADC）+ 读静态电平 | 输出指定的 PWM 或**静态电平** |
| ⑤ 编码器检测 | 发定量脉冲 + 回环采集 | **上报它自己数到的 A/B/Z 计数** |
| ⑥ 相电流检测 | 采 `电流检测1/2` | **产生电流** + **上报它自己采到的值** |

② **电压检测**：治具自己就能测（9 路模拟量直接读），
但**和被测板自己报的值对比**要用到 `DUT_INFO`（拿能力位图）+ `DUT_GET_ADC`（§7.2 / §7.8）。

> **治具侧已经实现**：PC 一条命令 `0x0015` 就做完
> "问 INFO 拿能力位图 → 按位图问 `GET_ADC` → 与治具 9 路逐通道判定 → 出报告"。
> 被测板**没在 `adc_mask` 里声明的通道会被跳过并如实报告，不会判失败** ——
> 所以只实现一部分通道也完全可以用。

**设计原则**：
1. **不啰嗦** —— 只定义测试真正需要的最小命令集，一共 9 条。
2. **默认安全** —— 上电、复位、通讯失联，任何情况下三相输出都是关断的。
3. **帧格式与另外两条链路完全一致** —— 治具的链路层代码是现成的，双方共用同一套规则，不用重新发明。
4. **能优雅降级** —— 用能力位图（caps）声明支持哪些命令，治具按对端能力决定测哪些项，不会因为对端版本旧就卡死。

## 2. 物理层与接线

| 项 | 值 |
|---|---|
| 链路 | **UART，TTL 3.3V** |
| 治具侧引脚 | U1 的 **USART1：PA9 = TX，PA10 = RX**（引到 4P 排针「串口1」） |
| **被测板侧引脚** | ⏳ **待定（占位）** —— 等 FOC 板原理图确认用哪两个脚、是不是 USART1（见 §13 D1） |
| 波特率 | **115200，8N1，无流控**（治具侧 `usart.c` 现状；若被测板只能跑别的波特率，请提出，改治具侧一处配置即可） |
| 电气 | **必须共地**；排针上无串阻、无保护，两边都是 3.3V CMOS 直连 |
| 方向 | 治具 **TX → 被测板 RX**，被测板 **TX → 治具 RX**（**交叉**） |

电平兼容性没问题：治具是 STM32F103（PA9/PA10 为 3.3V 且 5V 容忍），被测板是 STM32F405（IO 为 3.3V），
两边直连即可，不需要电平转换。

> ⚠ **治具的调试打印也占用 USART1**。治具侧已有开关（`jig_mode.h` 的 `MEAS_PRINT_ENABLE`），
> 生产/测试时它必须关闭，否则调试字符会灌到被测板的串口线上。这是治具侧的责任，DUT 不用管。
>
> ⚠ **别把 TX/RX 接到 SWD 上**：治具的串口座旁边还有一路 `SWD/SWCLK`（治具烧录被测板用的）。
> 烧录走 SWD、测试走串口，二者互不干扰，但接线时别接错脚。

### 2.1 ⑤ 编码器那三根线的接线（已确认，2026-10）

| 治具 CN2（XH-5PA） | 信号 | 接到被测板 |
|---|---|---|
| 1 | **5V** | 治具 CN2 测试点（**治具给被测板供电**，正常接） |
| 2 | **A** = U1 的 PB8 / TIM4_CH3 | 被测板 CN2 的 **A** 测试点 |
| 3 | **B** = U1 的 PB7 / TIM4_CH2 | 被测板 CN2 的 **B** 测试点 |
| 4 | **Z** = U1 的 PB6 / TIM4_CH1 | 被测板 CN2 的 **Z** 测试点 |
| 5 | **GND** | 被测板地（板子上没做地的测试点，走 SWD 那条线共地即可） |

- 用户已实地确认：**FOC 板 CN2 位置有 4 个测试点 = `5V / A / B / Z`**，**顶针下压会接 A/B/Z**。
- **A/B/Z 接错也不怕**：治具故意让三条线发的脉冲个数不同（A 发 1000 个、B 发 2000 个、Z 只发 1 个），
  接错了一眼就能看出是哪根。
- ⏳ **唯一还没定的是电平**：治具是 **3.3V 推挽**输出。若被测板那三个脚上拉到 5V、
  且输入门限按 5V 逻辑算（例如 5V 供电的施密特，VIH≈3.5V），**会被判成低电平**。
  量法：只给被测板上电，量 A/B/Z 三个点对地电压 —— **3.3V 或 0V → 直接接；5V → 先别接**
  （治具侧可改成开漏输出，让被测板自己的上拉拉高）。见 §13 D5。

## 3. 帧格式

**与 PC↔治具、U1↔U2 两条链路逐字节相同**（`protocol_frame.c` / `uart_link.c`）。

| 字段 | 帧头 F | 命令 C | 帧序号 N | 数据长度 L | 数据 D | CRC16 |
|---|---|---|---|---|---|---|
| 字节数 | 2 | 2 | 2 | 2 | * | 2 |

```
偏移   0    1    2    3    4    5    6    7    8 .. 8+L-1   8+L   9+L
     A5   5B  CMD_H CMD_L SEQ_H SEQ_L LEN_H LEN_L  DATA...   CRC_H CRC_L
```

- **帧头**：固定 `0xA5 0x5B`。
- **字节序**：**所有多字节字段一律大端**（高字节在前）。
- **命令 C**：2 字节，本协议用 `0x0200` ~ `0x02FF`（见 §6）。
- **数据长度 L**：2 字节，DATA 的字节数。**单帧 DATA 上限 = 64 字节**
  （治具的链路层 `LINK_MAX_PAYLOAD` 就是 64；超了按非法帧丢弃）。
- **CRC16**：**MODBUS** 变体。参数与范围如下，照抄即可：

| 项 | 值 |
|---|---|
| 算法 | CRC-16/MODBUS（反射多项式 `0xA001`） |
| 初值 | `0xFFFF` |
| 逐字节 | `crc ^= byte;` 然后 8 次：`if (crc & 1) crc = (crc >> 1) ^ 0xA001; else crc >>= 1;` |
| 计算范围 | **从帧头 `0xA5` 开始，到 DATA 最后一个字节**（含帧头、命令、序号、长度；**不含** CRC 本身） |
| 存放 | 大端：先高字节后低字节 |
| **自检值** | `CRC16("123456789") == 0x4B37` —— **请务必先跑通这一条再调链路** |

CRC 错误的帧：**直接丢弃，不应答**（与另外两条链路一致）。

## 4. 帧序号、应答、超时与重传

- **帧序号 N**：主机（治具）每发一帧 +1，从 `1` 开始，到 `0xFFFF` 回卷到 `1`。
  **序号 `0` 保留给"从机主动帧"**，正常的请求/应答都不用它。
- **应答规则**：收到请求 → 处理后回一帧，**应答的 N 与请求的 N 完全相同**（原样回显）。
  治具靠 N 匹配"这是我等的那一发"，不匹配的合法帧会被丢弃（防止迟到的旧应答污染下一次请求）。
- **超时**（治具侧设定，DUT 只需保证及时应答）：

| 命令类型 | 命令 | 治具等待上限 |
|---|---|---|
| 控制类 | PING / INFO / TEST_MODE / STOP | **50 ms** |
| 动作类 | PWM / LEVEL / CURRENT | **50 ms**（**收到即应答，不等动作做完**，见 §7.5） |
| 数据类 | GET_ADC / GET_ENC | **50 ms** |

- **重传**：治具在超时后**最多重传 1 次，且沿用同一个 N**。
  **所有命令都必须是幂等的**（下面每条都注明了重传时的行为）。
- **半截帧保护**：治具侧规则是"开始收帧后，若相邻两字节间隔 **> 5 ms** 就丢弃并重新同步"。
  被测板可以照抄，也可以更宽松；**但不要用长延时把帧拆开发**（比如用阻塞式发送、中间插 `HAL_Delay`）。
- **应答速度**：收到完整帧后 **≤ 5 ms** 内开始回帧。**不要在中断里做业务**，
  按"中断收字节 → 主循环组帧处理 → 主循环发应答"的常规结构做即可。

## 5. 状态码

**与另外两条链路共用同一张表**。应答 DATA 的**第 0 字节**就是状态码（PING 除外，它原样回显）。

| 码 | 名称 | 什么时候用 |
|---|---|---|
| `0x00` | OK | 成功 |
| `0x01` | BUSY | 上一次请求还没收尾 / 正在执行不能打断的动作 |
| `0x0B` | ERR_PARAM | 参数非法（长度不对、频率超范围、占空比 > 1000、保留位非 0 等） |
| `0x0C` | ERR_TIMEOUT | 动作等待超时（例如等电流稳定超时） |
| `0xFF` | NIY | 命令未实现（**必须回这个，不能静默丢弃**） |

> 完整表（含 `02 ERR_SIZE` / `03 ERR_FLASH` / `04 ERR_PROG` / `05 ERR_TEST` / `06 ERR_NO_FW` /
> `07 ERR_INCOMPLETE` / `08 ERR_CRC` / `09 ERR_SEQ` / `0A ERR_COUNT` / `0D ERR_OVERFLOW`）
> 见 `INFO/命令大全.txt` §0.5。本协议目前用不到那么多，但**取值不要自己另发明**。

**参数校验必须先于动作**：参数非法时回 `0B` 且**不能有任何输出动作**。

## 7. 逐条命令

### 7.1 `0x0200` DUT_PING —— 回环自检 / 保活

| 项 | 内容 |
|---|---|
| 请求 DATA | 任意 0~64 字节 |
| 应答 DATA | **把请求 DATA 原样回显**（**没有状态码字节**） |

**用途**：治具用它判断"对面在不在、链路通不通、有没有丢字节"。治具会周期性发（建议 500 ms 一次），
并在连续 3 次超时后判定链路故障、进入重连流程。

**重传行为**：纯回显，天然幂等。

> 例（请求 DATA = `DE AD BE EF`，SEQ=1）：
> `A5 5B 02 00 00 01 00 04 DE AD BE EF C5 14`
> 应答**与请求逐字节相同**（含 SEQ 和 CRC）。

### 7.2 `0x0201` DUT_INFO —— 版本与能力

| 项 | 内容 |
|---|---|
| 请求 DATA | 空（LEN=0） |
| 应答 DATA | **16 字节** |

应答 DATA 布局：

| off | size | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `status` | `00` OK |
| 1..2 | 2 | `dut_ver` | **本协议版本**，当前 **`0x0101`**（v1.1）。治具用它判断对面按哪版规格实现 |
| 3..5 | 3 | `fw_ver` | 被测板固件版本 `[主][次][修订]` |
| 6..7 | 2 | `caps` | **能力位图**，见 §8 |
| 8..9 | 2 | `pwm_freq_min_hz` | 支持的 PWM 最低频率 |
| 10..11 | 2 | `pwm_freq_max_hz` | 支持的 PWM 最高频率 |
| 12..13 | 2 | `adc_mask` | DUT 能上报哪些 ADC 通道（bit i = 支持通道 i，编号见 §7.8） |
| 14..15 | 2 | `rsvd` | 保留，填 `00 00` |

**用途**：治具在测试开始时读一次，据此决定"这次能测哪几项"。**不支持的项会被跳过并如实报告，
不会因为对面版本旧就判失败。**

> 例（SEQ=2，协议 1.1、固件 1.0.0、caps=`0x03FF`、100~20000 Hz、支持 ch0/ch1）：
> 请求 `A5 5B 02 01 00 02 00 00 6B FD`
> 应答 `A5 5B 02 01 00 02 00 10 00 01 01 01 00 00 03 FF 00 64 4E 20 00 03 00 00 6F 8B`

### 7.3 `0x0202` DUT_TEST_MODE —— 进入 / 退出测试模式

| 项 | 内容 |
|---|---|
| 请求 DATA | **3 字节**：`mode(1) + wdt_ms(2, 大端)` |
| 应答 DATA | 1 字节 `status` |

请求 DATA 布局：

| off | size | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `mode` | `0` = **退出**测试模式（回到正常电机控制）<br>`1` = **进入**测试模式（**先关断输出**，再交给治具指挥） |
| 1..2 | 2 | `wdt_ms` | **失联看门狗**超时，`200` ~ `10000` ms。见 §9 |

**进入测试模式时必须做的事**（顺序不能错）：

1. **立即关断三相输出**（把桥臂全部关掉，不要留任何"正在驱动"的状态）；
2. 停掉正常的电机控制环路（FOC 电流环 / 速度环）；
3. **把编码器 A/B/Z 计数清零**（⑤ 要靠"进入后累计的计数"来判定，不清零就没法比）；
4. 复位看门狗计时；
5. 回 `00 OK`。

**退出测试模式**（`mode=0`）：关断输出、重新使能正常控制、看门狗失效。

**重传行为**：幂等。重复收到同一 `mode` 只回 OK，**不做任何附加动作**
（特别是**不能在已经进入测试模式时再关一次输出又清零计数**——那会把正在测的计数抹掉）。

> 例（SEQ=3，进入，超时 1000 ms）：
> 请求 `A5 5B 02 02 00 03 00 03 01 03 E8 3E AE`
> 应答 `A5 5B 02 02 00 03 00 01 00 DE AA`

### 7.4 `0x0203` DUT_STOP —— 三相输出全关（安全命令）

| 项 | 内容 |
|---|---|
| 请求 DATA | 空 |
| 应答 DATA | 1 字节 `status` |

**任何状态下都必须能执行**（包括没进测试模式、正在发 PWM、正在通流）。
执行内容：关断全部桥臂、停止 PWM 输出、停止通流。

**这是治具的"刹车"**：测试流程出错、PC 掉线、治具复位前，都会先发它。

**重传行为**：幂等（关两次和关一次结果一样）。

> 例（SEQ=4）：请求 `A5 5B 02 03 00 04 00 00 AA 64`，应答 `A5 5B 02 03 00 04 00 01 00 7B AA`

### 7.5 `0x0204` DUT_PWM —— 三相 PWM（③④）

| 项 | 内容 |
|---|---|
| 请求 DATA | **10 字节** |
| 应答 DATA | 1 字节 `status` |

请求 DATA 布局：

| off | size | 字段 | 说明 |
|---|---|---|---|
| 0..1 | 2 | `freq_hz` | PWM 频率，单位 Hz |
| 2..3 | 2 | `duty_a` | A 相占空比，**千分比**（`500` = 50.0%），0~1000 |
| 4..5 | 2 | `duty_b` | B 相同上 |
| 6..7 | 2 | `duty_c` | C 相同上 |
| 8..9 | 2 | `count` | 脉冲个数：`>0` = 发这么多就停；**`0` = 连续输出直到收到 `DUT_STOP` / 看门狗超时** |

**应答语义（重要）**：**收到就回 `00 OK`，不等脉冲发完**。
理由与内部链路的 ARM 机制一致 —— 让治具能在同一时刻开自己的捕获窗口，两端时间对齐。

**治具侧的配合规则**（写在这里让双方都清楚）：
> 治具发完 `DUT_PWM` 后**立刻**开自己的 200 ms 捕获窗口。
> 所以 **burst 时长必须 ≥ 治具窗口 + 50 ms 余量**，即 `count / freq_hz ≥ 0.25 s`。
> 例如 `1 kHz + count=300` → burst 300 ms ✔；`1 kHz + count=200` → 只有 200 ms，**窗口会截到尾巴** ✘。

**参数校验**：`freq_hz` 必须在 INFO 里声明的范围内、`duty_*` ≤ 1000、否则回 `0B ERR_PARAM` 且**不输出**。

**重传行为**：**幂等** —— 收到与上一次**完全相同**的 `DUT_PWM` 请求时，
**沿用当前这一轮输出，不要重新起一轮**（否则治具的捕获窗口会对不上）。
实现建议：记住最近一次的 `freq/duty/count` 组合 + 是否还在输出，相同就直接回 OK。

> 例（SEQ=5，1 kHz、三相 50%、300 个）：
> `A5 5B 02 04 00 05 00 0A 03 E8 01 F4 01 F4 01 F4 01 2C D8 7A`

### 7.6 `0x0205` DUT_LEVEL —— 三相静态电平（④）

| 项 | 内容 |
|---|---|
| 请求 DATA | **2 字节**：`level(1) + rsvd(1)` |
| 应答 DATA | 1 字节 `status` |

`level` 是**三相各 2 bit** 的位图：

| 位 | 相 | 取值 |
|---|---|---|
| bit1..0 | **A 相** | `00`=输出低 · `01`=输出高 · `10`=**高阻/关断** · `11`=保留（回 `0B`） |
| bit3..2 | **B 相** | 同上 |
| bit5..4 | **C 相** | 同上 |
| bit7..6 | — | 保留，必须为 `00`（否则回 `0B ERR_PARAM`） |

> 例：A=高、B=低、C=高阻 → `level = 0b00_10_00_01 = 0x21`

**语义**：三相各自输出一个**静态**电平（不开关、不 PWM）。
⚠ **注意**：这是"把输出钉在某个电平"，不是"让电机转"。如果三相同时输出高，就是短路，
**DUT 侧必须做互锁**：同一个桥臂的上下管不能同时导通。

建议的互锁规则（DUT 侧负责实现）：
- 某一相选"输出高"= 上桥常通、下桥关断；
- 某一相选"输出低"= 下桥常通、上桥关断；
- 某一相选"高阻"= 上下桥全关（**三相全高阻是安全的默认态**）；
- **允许的相间组合由 DUT 自己按母线短路风险判断**，不允许的组合回 `0B ERR_PARAM`。

**重传行为**：幂等。

> 例（SEQ=6）：请求 `A5 5B 02 05 00 06 00 02 21 00 EF 0C`，应答 `A5 5B 02 05 00 06 00 01 00 A5 AB`

### 7.7 `0x0206` DUT_CURRENT —— 相电流激励（⑥）

| 项 | 内容 |
|---|---|
| 请求 DATA | **8 字节** |
| 应答 DATA | 1 字节 `status` |

请求 DATA 布局：

| off | size | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `mode` | `0` = **静态通流**（直流，⑥ 推荐用这个）<br>`1` = 低频 PWM 通流<br>其余 → `0B ERR_PARAM` |
| 1 | 1 | `hi_mask` | **上桥相掩码**：bit0=A, bit1=B, bit2=C（**只允许 1 位为 1**，否则回 `0B`） |
| 2 | 1 | `lo_mask` | **下桥相掩码**：同编码。**必须与 `hi_mask` 不同相**，否则 = 同桥臂直通短路 → `0B` |
| 3..4 | 2 | `duty_permille` | 千分比 0~1000。`mode=0` 时按 1000 处理（全通）；`mode=1` 时是 PWM 占空比 |
| 5..6 | 2 | `duration_ms` | 持续时间 ms（`0` = 保持到 `DUT_STOP` / 看门狗） |
| 7 | 1 | `rsvd` | 保留 = `00` |

**语义**：把电流从上桥相**推**到下桥相，流过电机（或假负载），
使被测板的**采样电阻 → 放大器 → ADC** 整条链路上产生真实信号。

**为什么建议用 `mode=0` 静态通流**（这是治具的推荐做法，理由请一并了解）：
> ⑥ 要把"治具读到的电流"和"DUT 自己读到的电流"做对比，
> 而治具和被测板之间**没有采样同步线**（`U1↔U2` 那根 PB9↔PA11 不连被测板）。
> 静态直流下电流稳定，两边各读一个稳定值就能直接比；
> PWM 下电流有纹波，两边采样时刻差一点读数就对不上，判据不可信。

**治具侧怎么比（被测板了解这个，就知道该报什么）**：
> 治具**不直接比绝对值**，而是比**"通流前 → 通流中"的变化量**：
> `Δ治具 = 通流中 mV − 通流前 mV`，`ΔDUT` 同理，要求 `|Δ治具 − ΔDUT| ≤ 容差`。
>
> 这么做是为了**不依赖放大器的零点拓扑**：中点偏置（零电流输出 1.65V）和零电流输出 0V
> 这两种设计，比差值都能统一处理（偏置被减掉了）。
>
> 所以被测板报 `mv` 时**只要如实报它自己 ADC 换算出来的信号侧电压**即可，
> **不需要**做任何零点处理 —— 治具会把两边的基线各减一次。

**超时**：`duration_ms` 到点后 DUT **自行关断输出**（不需要治具再发 STOP），并更新内部状态。
治具会在 `duration_ms` 之后发 `GET_ADC` 取值，所以**值要保留**（关断后不要清掉采样缓存）。

**重传行为**：幂等（同样的参数重复收到 → 回 OK，不重新起一轮计时）。

> 例（SEQ=7，静态通流 A→B、100%、200 ms）：
> `A5 5B 02 06 00 07 00 08 00 01 02 03 E8 00 C8 00 12 5E`

### 7.8 `0x0207` DUT_GET_ADC —— 读 DUT 自己采到的模拟量（②⑥）

| 项 | 内容 |
|---|---|
| 请求 DATA | **2 字节** `ch_mask`（大端 u16）：bit i = 1 表示要通道 i 的值 |
| 应答 DATA | `status(1)` + n × 5 字节，n = 请求里为 1 的位数（**n ≤ 12**，受单帧 64B 限制） |

> **为什么请求掩码用 2 字节**：通道号是 0~8 共 **9 路**，1 个字节只能表达 0~7，
> 会把第 8 路（电流检测 2）漏掉。这条是治具侧实现时发现的，**v1.1 定稿即按 2 字节**。

**通道编号 —— 故意和治具的 9 路信号序号完全一致**，这样 PC 拿到两边数据可以直接逐通道比，
不用再做映射表（治具侧定义见 `docs/07` §2.1）：

| 通道 | 信号 | 治具侧同序号通道 |
|---|---|---|
| 0 | 24V 母线 | ✔ |
| 1 | 10V 驱动供电 | ✔ |
| 2 | 5V 电源 | ✔ |
| 3 | 3.3V 电源 | ✔ |
| 4 | A 相电压 | ✔ |
| 5 | B 相电压 | ✔ |
| 6 | C 相电压 | ✔ |
| 7 | 电流检测 1 | ✔ |
| 8 | 电流检测 2 | ✔ |
| 9..15 | 保留 | — |

每个通道 5 字节：

| off | size | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `ch` | 通道号 |
| 1..2 | 2 | `raw` | **DUT 自己的 ADC 原始码值**（0~4095 / 0~65535，按自己的分辨率） |
| 3..4 | 2 | `mv` | **DUT 自己换算出的 mV** |

> **为什么要 `raw` 和 `mv` 两个都给**：⑥ 的对比要能分辨"是放大器/采样电阻的问题"
> 还是"固件换算系数写错了"。只给 mV 的话这两种情况分不开。
>
> `mv` 的**参考点要和治具一致**：治具报的是"输入侧 mV"（已经按分压比折回信号侧，见 `docs/06`）。
> 如果 DUT 报的是"ADC 引脚上的 mV"，那么**相电压那几路会比治具小 8 倍**（治具侧 k=0.125）。
> 请统一成 **"信号侧 mV"**（即折回分压之前的值），并在实现里注释清楚。

**重传行为**：幂等（只读）。

> 例（SEQ=8，要 ch0/ch1）：请求 `A5 5B 02 07 00 08 00 02 00 03 BF 1E`
>
> 例（SEQ=11，只要第 8 路也就是电流检测 2）：请求 `A5 5B 02 07 00 0B 00 02 01 00 2E 1B`
> 应答 `A5 5B 02 07 00 08 00 0B 00 00 08 1A 01 2C 01 08 30 01 38 B5 E8`
> （status=00，ch0 raw=0x081A mv=300，ch1 raw=0x0830 mv=312）

### 7.9 `0x0208` DUT_GET_ENC —— 读 DUT 自己数到的编码器计数（⑤）

| 项 | 内容 |
|---|---|
| 请求 DATA | 空 |
| 应答 DATA | **14 字节** |

应答 DATA 布局：

| off | size | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `status` | `00` OK |
| 1..4 | 4 | `cnt_a` | **A 相累计跳变（边沿）个数**，u32 大端 |
| 5..8 | 4 | `cnt_b` | B 相同上 |
| 9..12 | 4 | `cnt_z` | Z（索引）同上次数 |
| 13 | 1 | `dir` | 最近一次正交解码得到的方向：`+1` / `-1` / `0`=没动（**s8，有符号**） |

**计数语义（必须一致，否则比不了）**：
- 计数**在进入测试模式时清零**（见 §7.3 第 3 步），之后**只增不减**；
- 数的是**边沿个数**（上升沿 + 下降沿），不是"解码后的位置增量"；
  这样治具发的"多少个脉冲"和 DUT 数的"A 相多少个边沿"是同一个量纲。
  > 治具每发 1 个完整方波脉冲 = 2 个边沿（上升 + 下降）。
  > 治具侧会把"我发了 N 个脉冲"折算成 **2N 个边沿** 再和 `cnt_a` 比。
- `dir` 只是"最近一次解码方向"，**不参与计数**，用来验证正交解码的正负号对不对。

**重传行为**：幂等（只读；但注意计数在变，两次读到的值可能不同——这是正常的）。

> 例（SEQ=9，A=1000、B=2000、Z=1、dir=+1）：
> 请求 `A5 5B 02 08 00 09 00 00 A8 50`
> 应答 `A5 5B 02 08 00 09 00 0E 00 00 00 03 E8 00 00 07 D0 00 00 00 01 01 45 6E`

## 8. 能力位图 `caps`

| bit | 命令 | bit | 命令 |
|---|---|---|---|
| 0 | `0x0200` PING | 5 | `0x0205` LEVEL |
| 1 | `0x0201` INFO | 6 | `0x0206` CURRENT |
| 2 | `0x0202` TEST_MODE | 7 | `0x0207` GET_ADC |

## 9. 状态机与安全（**这一节最要紧，请重点实现**）

### 9.0 为什么必须有"测试模式"（先讲清目的，再谈怎么实现）

测试模式（`0x0202`）是**把被测板从"自己跑电机"切到"听治具指挥"的总开关**，
它同时是一个**安全闸**和一个**测量基准**。③④⑤⑥ 四项**全都以它为前提**。四条理由：

1. **不停控制环，量出来的数没有意义。**
   正常上电后 FOC 是要跑电机的（电流环/速度环在工作）。治具要的是"**我给一个已知占空比，
   量出来的电压对不对**"。控制环还在跑的话，它会立刻把治具设的输出覆盖掉 ——
   量到的既不是治具给的值、也不是稳态值，**没法判**。
2. **防"电机一直转"（这条最要紧）。**
   场景：治具正发 PWM 让电机转，**PC 崩了 / USB 拔了 / 治具复位了**。
   没有看门狗的话，**电机会一直转下去** —— 这是产线上不能接受的。
   所以超时必须由被测板自己判（见 §9.2），不能只靠治具那边"记得发 STOP"。
3. **把"计数/测量的起点"对齐。**
   进测试模式时必须做且顺序不能错：**先关断三相输出 → 停控制环 → 把编码器 A/B/Z 计数清零**。
   ⑤ 的判定基准就是"**进测试模式之后累计的计数**"；不清零没法比，
   控制环自己也在读编码器、会污染这个数。
4. **准入门槛 + 上电默认安全。**
   没进测试模式时收到 `PWM`/`LEVEL`/`CURRENT` 一律回 `01 BUSY`（PC 发错命令也不会突然动起来）；
   上电/复位后三相输出必须关断且不进测试模式，**不允许"上电就按上次参数继续输出"**。

> 一句话给实现的人：**`0x0202` 和 `0x0203` 应该最先实现，比 `0x0204 PWM` 还靠前** ——
> 没有这两条，③④⑥ 根本没法安全地测（见 §11 的实现顺序建议）。

### 9.1 DUT 侧状态机

```
       上电 / 复位 / 看门狗复位
              │
              ▼
        ┌───────────┐   TEST_MODE(mode=1)   ┌────────────┐
        │  APP_MODE │ ────────────────────► │ TEST_IDLE  │  输出全关
        │ 正常跑电机 │                       │ 等治具指挥  │  编码器计数=0
        └───────────┘ ◄──────────────────── └────────────┘
              ▲        TEST_MODE(mode=0)          │
              │                          PWM / LEVEL / CURRENT
              │                                   ▼
              │                          ┌──────────────────┐
              │        STOP / 看门狗超时  │ TEST_ACTIVE      │
              └──────────────────────────│ 正在输出         │
                                         └──────────────────┘
```

规则：
1. **`APP_MODE` 下收到 `PWM`/`LEVEL`/`CURRENT` → 回 `01 BUSY`**（没进测试模式不允许动输出）。
2. `TEST_ACTIVE` 下收到新的 `PWM`/`LEVEL`/`CURRENT` → **允许**（覆盖上一轮动作，先关断再起新的）。
3. `STOP` 在**任何状态**都执行，执行完回到 `TEST_IDLE`（若在测试模式）或 `APP_MODE`。
4. **`mode=0` 退出测试模式时，先关断输出再恢复控制**，顺序不能反。

### 9.2 失联看门狗（必须实现）

> 场景：治具在发 PWM 让电机转的时候，PC 崩了 / USB 拔了 / 治具复位了。
> 如果没有看门狗，**电机就会一直转下去**。这是必须防住的。

- 进入测试模式时由 `wdt_ms` 设定超时（`200`~`10000` ms）；
- **每收到一帧合法请求就重置计时**（不只 PWM，任何命令都算"对面还在"）；
- 超时到达 → **立即关断三相输出**，回到 `TEST_IDLE`（不退出测试模式，等治具回来）；
- 若 `wdt_ms = 0` 或越界 → 回 `0B ERR_PARAM`（**不允许关掉看门狗**）。

### 9.3 上电默认

**上电 / 复位后，三相输出必须是关断状态**，并且**不进入测试模式**。
不允许"上电就按上次的参数继续输出"。

## 10. 配合 ②③④⑤⑥ 的调用时序

> 每节末尾都标了**治具侧现在的状态**（PC 用哪条命令做、还等被测板实现什么）。
> 治具侧的联调命令清单在 `docs/04` §7.4。

### ② 电压检测

```
治具                                     DUT
  │  INFO（拿 caps + adc_mask）────────►
  │  ◄────────────────────────────── dut_ver / fw_ver / adc_mask
  │  GET_ADC(mask = 按 adc_mask 取) ────►
  │  ◄────────────────────────────── 每通道 raw + mv（DUT 自己采的）
  │  与治具自己 9 路逐通道比对（容差 max(DUT值×5%, 200mV)）
```

②**不需要测试模式**（只读数据、无输出动作）。被测板只实现 `0x0201` + `0x0207` 就能参与比对。

> **治具侧已经实现**：PC 一条命令 `0x0015` 做完全流程（问 INFO → 按位图问 GET_ADC → 比对 → 出 71B 报告）。
> 没在 `adc_mask` 里声明的通道**跳过并如实报告，不判失败**。

### ③④ 三相 PWM 与输出检测
```
治具                                     DUT
 │  TEST_MODE(mode=1, wdt=2000ms)  ────►  关断输出、停控制环、编码器计数清零
 │  ◄────────────────────────────── 00 OK
 │  PWM(freq=1000, 50%@三相, count=300) ─► 收到即回
 │  ◄────────────────────────────── 00 OK
 │  ┌ 治具立刻开 200ms 捕获窗口（③：采 MA_IN/MB_IN/MC_IN 的频率/占空比）
 │  └ 同时读相电压 ADC（④：V_相电压平均值 ≈ 占空比 × 母线电压）
 │  （300 ms 后 DUT 自行停止）
 │  STOP ─────────────────────────────►
 │  ◄────────────────────────────── 00 OK
```

**③④ 的判定**：③ 给出占空比 D，④ 给出相电压平均值 V，**理论关系 `V ≈ D × V_母线`**。
这条判据同时验证了驱动级是否正常工作、以及母线电压采样对不对。

> ⚠ **不接电机时（产线的实际做法）**：④ **照样能测** —— 它量的是**桥臂输出端的电压本身**
> （开关节点在高/低之间切换，分压后的平均值 = D × 母线电压），不需要电机。
> 但**母线必须带电**，否则三相全读到 0 → 治具会判 `VBUS_LOW`（"这条测不了"），不会误判成不合格。
> 母线电流很小（空载，只有板子自身耗电 + 开关损耗），工位一个小 24V 电源就够。

> **治具侧已经实现**：PC 按顺序发三条就把 ③④ 做完 ——
> `0x0011`（透传 `DUT_PWM` 让被测板输出已知 PWM）→ `0x000F mode=1`（开窗采集）
> → `0x0016 mode=1 duty=<占空比>`（判定，判据是 `V ≈ D × 母线`）。
> 被测板要实现 `0x0202`（进测试模式）+ `0x0204`（PWM）即可；走"静态电平"那条简化路径则用 `0x0205` + `0x0016 mode=0`。

### ⑤ 编码器检测

```
治具                                         DUT
 │  TEST_MODE(mode=1)  ──────────────────►  编码器计数清零
 │  ◄──────────────────────────────────── 00 OK
 │  ┌ U1 在 CN2 的 A/B/Z 上发定量脉冲：
 │  │   A = 1000 个脉冲 @5kHz    → 2000 个边沿
 │  │   B = 2000 个脉冲 @10kHz   → 4000 个边沿
 │  │   Z = 1 个脉冲             → 2 个边沿
 │  │ 同时 U2 用 TIM4 采集同一组线（回环，证明"真发出去了"）
 │  └
 │  GET_ENC  ────────────────────────────►
 │  ◄──────────────────────────────────── cnt_a / cnt_b / cnt_z / dir
 │  STOP
```

**三方对齐才算过**：`治具意图 == U2 实测 == DUT 上报`。
任何一环断了都知道是哪一环的问题（信号没出去 / 治具采集错 / DUT 解码错）。

> 为什么 A/B/Z 的**个数故意各不相同**：一次就能确定"是哪一路接错了"。
>
> **治具侧已经实现（两段）**：
> - U1 发：`0x0012`（默认 A=1000@5kHz / B=2000@10kHz / Z=1，可带参数改）；
> - U2 采：`0x0013`（清零 / 读取两次调用，转成内部链路 `0x0109`）。
>
> **所以 ⑤ 现在缺的只有两件**：①**接线**（顶针下压接被测板 CN2 的 A/B/Z，见 §2.1，已确认能做）；
> ②**被测板实现 `0x0202`（进测试模式时清零编码器计数）+ `0x0208`（上报计数）**。
> 接线那条线还差一个"电平门限"要量（§13 D5）。
>
> **PC 侧的编排**（暂时按顺序发，将来可合成一条治具命令）：
> `0x0011`(透传 `TEST_MODE`) → `0x0013`(U2 清零) → `0x0012`(U1 发脉冲)
> → `0x0013`(U2 读数) → `0x0011`(透传 `GET_ENC`) → 三个数摆一起比。

### ⑥ 相电流检测

```
治具                                     DUT
 │  TEST_MODE(mode=1)  ──────────────►
 │  CURRENT(mode=0, hi=A, lo=B, 100%, 200ms) ─► 收到即回，开始通流
 │  ◄────────────────────────────── 00 OK
 │  ┌ 等 200ms + 稳定余量（比如再等 20ms）
 │  ├ 治具读自己的 ADC（电流检测1/2）
 │  └ GET_ADC(mask=bit7|bit8) ─────────►
 │  ◄────────────────────────────── raw + mv（DUT 自己的）
 │  比对：治具 mV  vs  DUT mv；治具 raw 换算 vs DUT raw
 │  STOP
```

**判定**：两边 mV 在容差内一致 → 电流采样链路（采样电阻 + 放大器 + ADC + 换算系数）正常。
不一致时，`raw` 和 `mv` 两个都给出来，就能分辨是**模拟链路**的问题还是**固件换算系数**的问题。

> ⚠ **不接电机时，⑥ 的电流是"零"**：静态通流靠的是
> `母线 → 上管A → A 相出线 →（**电机**）→ B 相出线 → 下管B → 采样电阻 → 地`，
> **回路没有负载就是断的**。这时两边读到的都是放大器零点（≈ VREF/2）——
> 能验证"放大器没坏 + 基准对 + 两边换算一致"，**验不了采样电阻和增益**。
> 想真的验，夹具上要提供一条回路（**两相短接**，或串一个小电阻/假负载），见 §13 D11。
> 治具侧在"只测到零点"时**会如实标注**，不会把它当成"电流链路合格"。

> **治具侧已经实现了这一步**：PC 一条命令 `0x0014` 就做完
> "读基线（本片 + DUT）→ 让 DUT 通流 → 等 → 再读（本片 + DUT）→ 判定 → 出报告"。
> 被测板只要把 `DUT_CURRENT`（§7.7）和 `DUT_GET_ADC`（§7.8）实现出来即可。

## 11. DUT 侧实现要点

### 11.1 实现顺序建议（先做哪几条）

按"最少必要"排的，**建议照这个顺序做**：

| 顺序 | 命令 | 为什么排这个位置 |
|---|---|---|
| 1 | `0x0200` PING + 帧层（CRC/SEQ/重同步） | 先能通、能自检；`CRC16("123456789")==0x4B37` 必须先过 |
| 2 | `0x0201` INFO | 治具靠 `caps` 决定"这次测哪几项"，早做早省事 |
| 3 | **`0x0202` TEST_MODE** + **`0x0203` STOP** | **比 PWM 还靠前**：没有它们，③④⑥ 没法安全地测（理由见 §9.0） |
| 4 | `0x0204` PWM | ③④ 的激励 |
| 5 | `0x0206` CURRENT + `0x0207` GET_ADC | ⑥ 的激励 + ②⑥ 的"被测板自己那一半"数据 |
| 6 | `0x0208` GET_ENC | ⑤ 的第三个数（治具侧已全部就绪，只等这一条） |
| 7 | `0x0205` LEVEL | ④ 的"静态电平"简化路径，可以最后做 |

**只做前 3 条也能用**：治具会按 `caps` 跳过没实现的项并**如实报告"对面没实现"**，不会判失败。

### 11.2 编码注意

1. **不需要重写链路层**。帧格式、CRC、SEQ 配对、半截帧保护都是标准做法，
   照 §3/§4 实现即可；如果被测板工程里已经有类似的 UART 协议框架（比如移植过 OTA），
   直接在本协议上复用同一套组帧/解帧函数最省事。
2. **接收用中断 + 环形缓冲，处理放主循环**。不要在 UART 中断里做业务（尤其是 PWM 配置）。
3. **组帧要有超时重同步**：收到 `A5 5B` 后如果长时间收不齐，要能丢弃并重新找帧头，
   否则一次噪声会让后面所有帧都错位。
4. **参数校验先于动作**，非法参数回 `0B` 且**绝不产生输出**。
5. **看门狗放主循环里判断**，不要依赖某个具体命令触发。
6. **应答不要阻塞**：`PWM`/`CURRENT` 是"立即应答 + 后台动作"，
   别用 `HAL_Delay` 把发应答推迟到动作做完。
7. **所有动作都是可被 `STOP` 打断的**：主循环里检查 STOP 请求标志，不要写成阻塞的死等循环。

| 内容 | 帧 |

| PING 请求/应答（DATA=`DE AD BE EF`，SEQ=1） | `A5 5B 02 00 00 01 00 04 DE AD BE EF C5 14` |
| INFO 请求（SEQ=2） | `A5 5B 02 01 00 02 00 00 6B FD` |
| INFO 应答（协议 1.1、固件 1.0.0、caps=0x03FF、100~20000 Hz、adc_mask=3） | `A5 5B 02 01 00 02 00 10 00 01 01 01 00 00 03 FF 00 64 4E 20 00 03 00 00 6F 8B` |
| TEST_MODE 进入（wdt=1000 ms，SEQ=3） | `A5 5B 02 02 00 03 00 03 01 03 E8 3E AE` |
| TEST_MODE 应答 OK | `A5 5B 02 02 00 03 00 01 00 DE AA` |
| STOP（SEQ=4） | `A5 5B 02 03 00 04 00 00 AA 64` |
| STOP 应答 OK | `A5 5B 02 03 00 04 00 01 00 7B AA` |
| PWM：1 kHz、三相 50%、300 个（SEQ=5） | `A5 5B 02 04 00 05 00 0A 03 E8 01 F4 01 F4 01 F4 01 2C D8 7A` |
| PWM 应答 OK | `A5 5B 02 04 00 05 00 01 00 30 AA` |
| LEVEL：A=高、B=低、C=高阻（SEQ=6） | `A5 5B 02 05 00 06 00 02 21 00 EF 0C` |
| LEVEL 应答 OK | `A5 5B 02 05 00 06 00 01 00 A5 AB` |
| CURRENT 静态通流 A→B、100%、200 ms（SEQ=7） | `A5 5B 02 06 00 07 00 08 00 01 02 03 E8 00 C8 00 12 5E` |
| CURRENT 应答 OK | `A5 5B 02 06 00 07 00 01 00 6A AA` |
| GET_ADC 请求 ch0+ch1（SEQ=8） | `A5 5B 02 07 00 08 00 02 00 03 BF 1E` |
| GET_ADC 应答 2 路 | `A5 5B 02 07 00 08 00 0B 00 00 08 1A 01 2C 01 08 30 01 38 B5 E8` |
| GET_ENC 请求（SEQ=9） | `A5 5B 02 08 00 09 00 00 A8 50` |
| GET_ENC 应答 A=1000 B=2000 Z=1 dir=+1 | `A5 5B 02 08 00 09 00 0E 00 00 00 03 E8 00 00 07 D0 00 00 00 01 01 45 6E` |
| 未实现命令 `0x0209` 请求（SEQ=10） | `A5 5B 02 09 00 0A 00 00 68 9D` |
| 未实现命令应答 `FF NIY` | `A5 5B 02 09 00 0A 00 01 FF 79 E8` |

**校验方法**：`CRC16("123456789")` 必须等于 `0x4B37`；
然后对上面任一行，对"帧头到 DATA 末字节"算 CRC，应与最后两字节一致。
治具侧的实现已经通过这套自检（`test/protocol_test.c`）。

| **D11** | **（⑥ 能不能测出真东西）** 测试时**不接电机**，⑥ 的电流回路从哪来？ | ⑥ 的激励是"静态通流"：`母线 → 上管A → A 相出线 →（**电机**）→ B 相出线 → 下管B → 采样电阻 → 地`。**不接电机，这条回路是断的 → 一次侧根本没电流**。这时治具和 DUT 读到的都是放大器的**零点/基准**（约 VREF/2）—— 能验证"放大器没坏、基准对、两边换算一致"，但**验不了采样电阻和增益**（也就是"满量程对应多少安"这条最关键的量还没验） | ⏳ **请你定产线怎么做**，三选一：<br>(a) **夹具上把两相短接**（或串一个小电阻/假负载）→ ⑥ 能测到真电流，链路验得全；<br>(b) 工位接"假电机"（电阻/电感负载）→ 同上，但夹具复杂、有发热；<br>(c) **什么也不加** → ⑥ 降级成"零点/基准一致性检查"，我会在报告里**如实标成"只验了零点"**，不当成"电流链路合格" |

> **⑤ 的接线**：见 §2.1（治具 CN2 `1=5V / 2=A / 3=B / 4=Z / 5=GND` → 被测板 CN2 的 4 个测试点 + 地）。
> A/B/Z 接错也不怕：治具故意让三条线的脉冲个数不同（A=1000、B=2000、Z=1），接错一眼看得出来。

## 15. 数据字段速查（按块写，可直接贴给别人看）

> 全部**大端**；`{}` 里就是帧的 DATA 段。应答第 0 字节统一是状态码
> （`00` OK / `01` BUSY / `0B` 参数错 / `FF` 未实现）。

**0x0200 PING**
```
请求数据 : {任意 0~64 字节}
应答数据 : {请求数据原样回显}          ← 注意：PING 的应答**没有**状态码字节
```

**0x0201 INFO**
```
请求数据 : {}
应答数据 : {1 字节   ：状态码
            2 字节 u16：dut_ver（固定 0x0101）
            3 字节    ：fw_ver [主][次][修订]
            2 字节 u16：caps 能力位图（bit i = 支持 0x0200+i）
            2 字节 u16：PWM 最低频率 Hz
            2 字节 u16：PWM 最高频率 Hz
            2 字节 u16：adc_mask（bit i = 能上报通道 i）
            2 字节    ：保留 00 00}                      共 16 字节
```

**0x0202 TEST_MODE**
```
请求数据 : {1 字节   ：mode（00 退出 / 01 进入）
            2 字节 u16：wdt_ms 失联看门狗（200~10000）}
应答数据 : {1 字节：状态码}
```

**0x0203 STOP**
```
请求数据 : {}
应答数据 : {1 字节：状态码}
```

**0x0204 PWM**
```
请求数据 : {2 字节 u16：freq_hz
            2 字节 u16：duty_a 千分比（0~1000）
            2 字节 u16：duty_b
            2 字节 u16：duty_c
            2 字节 u16：count 脉冲个数（0 = 一直发到 STOP）}   共 10 字节
应答数据 : {1 字节：状态码}        ← **收到就回**，不等脉冲发完
```

**0x0205 LEVEL**
```
请求数据 : {1 字节：level（A=bit1..0，B=bit3..2，C=bit5..4；
                          每相 00 低 / 01 高 / 10 高阻 / 11 保留；bit7..6 必须 00）
            1 字节：保留 00}
应答数据 : {1 字节：状态码}
```

**0x0206 CURRENT**
```
请求数据 : {1 字节   ：mode（00 静态通流 / 01 低频 PWM）
            1 字节   ：hi_mask 上桥相（bit0=A bit1=B bit2=C，只许 1 位）
            1 字节   ：lo_mask 下桥相（只许 1 位，必须与上桥不同相）
            2 字节 u16：duty_permille
            2 字节 u16：duration_ms（0 = 保持到 STOP）
            1 字节   ：保留 00}                          共 8 字节
应答数据 : {1 字节：状态码}
```

**0x0207 GET_ADC**
```
请求数据 : {2 字节 u16：ch_mask（bit i = 要通道 i）}
应答数据 : {1 字节：状态码
            n × {1 字节   ：通道号（必须回原通道号）
                 2 字节 u16：raw 原始码值
                 2 字节 u16：mv 信号侧电压}}            共 1 + 5n 字节
```

**0x0208 GET_ENC**
```
请求数据 : {}
应答数据 : {1 字节   ：状态码
            4 字节 u32：cnt_a A 相**边沿**个数
            4 字节 u32：cnt_b
            4 字节 u32：cnt_z
            1 字节 s8 ：dir 最近一次解码方向（+1/-1/0）}   共 14 字节
```

> **治具侧（PC → 治具）的命令**不在本文范围：`0x0010`~`0x001B` 的逐字段说明见
> `INFO/命令大全.txt` §1.22「数据字段速查」，上位机视角见 `docs/17`。
