# 中断安全与并发分析（U1 / U2 固件）

> 触发来源：`logicprobe_concurrency_scan` 对"该环形缓冲是中断安全的 / 不存在数据竞争"这两条绝对断言标记为 **error（需要专门验证）**。本文给出显式证明与残余风险，替代模糊断言。
>
> **2026-10 复核**：四块功能（四路串口 / SWD 烧录 / ADC 测量 / TIM 脉冲捕获）接进来之后，
> 共享对象从"1 个帧环 + USB `TxState`"扩到 **7 类**。逐文件重核了一遍，
> 结论是：**协议层与串口收环仍然干净，但查出 6 处真实缺陷**（§4 的 D1~D6）。其中 **D1~D3 已修**（2026-10，两片都已改），**D4~D6 仍是待办**。

## 3. 环形缓冲的显式正确性论证

记 `N = 512`，掩码 `M = N-1`，`H = ring_head`（生产者指针，仅 ISR 写），`T = ring_tail`（消费者指针，仅主循环写）。
所谓"存活区间"是环形区间 `[T, H)`；不变式 **INV：生产者永不写存活区间内的槽位**。

### 3.1 生产者不会覆盖未被读取的槽位

生产者序：`t ← T`（快照）→ `next ← (H+1) & M` → 若 `next == t` 则丢弃；否则 `ring[H] ← byte` → `H ← next`。

- **`T` 只会单调前进**（只由消费者推进）。因此生产者读到的 `t` 至多是"真实 T 的旧值"，
  用旧 `t` 判断"满"只会**更容易判满**（把可用空间算少），方向保守 → 最多多丢一个字节，不会误以为有空位。
- **写入的槽位是 `ring[H]`，消费者读的是 `ring[T]`。** 空时 `H == T` 且 `next ≠ H`，生产者写 `ring[H]` 而消费者此时不读任何槽；
  非空时 `H ≠ T`，故 `ring[H] ≠ ring[T]`。⇒ 生产者写入的槽位**永远不是**消费者正在读的那一个。∎

### 3.2 消费者不会读到写了一半的数据

- 生产者的可见顺序是 `ring[H] ← byte` **之后**才 `H ← next`；`H` 是 `volatile`，编译器不会重排。
  消费者只有在观察到 `H` 前进后才可能取到新字节。∎
- 消费者序：`b ← ring[T]` → `T ← (T+1)&M`。中断可能插在两条指令之间推进 `H`，但不会影响 `ring[T]`（由 3.1 保证），
  也不会撕裂 `T`（见 3.3）。∎

### 3.3 指针读写不会撕裂

Cortex-M3 上对**自然对齐的 16 位对象**的读写是单条 `LDRH`/`STRH`，中断只能在指令边界插入。
故 `H`、`T`、`uwTick` 的每次读写都是原子的；`TxState`、`tx_busy`、`s_running` 是 `uint8_t`，同理。∎

### 3.4 消费者读到"过期的 H"是安全的

主循环读 `H` 时被中断打断、中断推进了 `H`，则主循环用的是旧 `H`：循环提前结束，本轮少取几个字节，
**下一轮 `APP_Frame_Poll()` 会继续取**。方向安全。∎

### 3.5 结论与前提

在上述前提（**恰好一个生产者、恰好一个消费者、各指针单一写者、单核、指针自然对齐且为 volatile**）下，
环形缓冲**不需要关中断、不需要互斥锁**。

> ⚠ **2026-10 复核：前提已被破坏一处** —— `APP_Frame_Init()` 会写 `ring_head`（`app_frame.c:125`），
> 而它是 ISR 的写变量（`app_frame.c:138`），调用点 `app.c:265/712/772` 都在主循环。
> 于是 §3 的证明对当前代码**不再成立**，这就是 **D1**。修法见 §4。
>
> ⚠ 另外，一旦有人把 `APP_Frame_Feed` 从主循环调用（变成两个生产者），或把 `APP_Frame_Poll` 放进中断，
> 本证明同样立即失效。代码注释里已标注"仅 ISR 调用 / 仅主循环调用"。

`uart_port.c` 的**收环**（256B/路）与本节同型（ISR 单写 head、主循环单写 tail），因此同样不需要临界区。

## 4. 缺陷与残余风险（按严重度排序）

> **D1~D6 是逐文件复核发现的真实缺陷：D1~D3 已修（下表「修法」栏标了 ✅），D4~D6 仍待办**；D7 起是已知的、有意的降级或概率极低的窗口。

| # | 位置 | 后果 | 触发条件 | 修法（建议） |
|---|---|---|---|---|
| **D1** | `ring_head` 双写者：`app_frame.c:125` vs `:138`，调用点 `app.c:265/712/772` | 丢字节 / head-tail 错位 / 重解析已消费的旧字节（偶发半截帧、CRC 错） | 主循环清环的同一瞬间 USB 收到字节（PC 刚发下一条命令时） | ✅ **已修**：`APP_Frame_Init()` 不再写 `ring_head`，改成"把 tail 追到 head"（`ring_tail = ring_head`，主循环独占的变量），语义一样（丢弃未处理字节）且无竞态 |
| **D2** | `tx_buf`（`app.c:43`）主循环写、USB ISR 读后续包；只靠 `TxState` + 50 ms 超时 | **帧内容混叠/被截断**（77B、91B 应答必然是多包） | 上次发送超过 50 ms 未完成时又发下一帧 | ✅ **已修**：`APP_SendFrame()` 在 `Frame_Build(tx_buf, …)` **之前**先 `APP_WaitTxDone()`；等到还忙就**直接丢掉这一帧不发**（宁可让 PC 超时重试，也不发混叠帧） |
| **D3** | `TIM4->CCER` 跨上下文读-改-写：ISR `pulse_cfg.c:116/123/130` `^=` vs 主循环 `:69` `&=` | 一次极性翻转丢失 → 该相**高低电平判反 → 占空比 ≈ 1−duty**（会周期性复现） | 主循环清极性位时被捕获中断打断 | ✅ **已修**：新增影子 `s_ccer`（U2 为 `s_ccer3`/`s_ccer1`），中断与主循环都只对影子做 `^=`/`&=` 再整字写回 CCER；主循环那段用 `__disable_irq()/__enable_irq()` 包住 |
| **D4** | `s_ovf` 主循环清零（`pulse_cfg.c:53/65`）vs ISR 自增（`:134`）；关 DIER 挡不住已 pending 的 NVIC 请求 | 时间戳高位差 65536 tick（≈0.91 ms）→ 单次区间/周期错值 | 开窗口/关窗口的瞬间正好有溢出中断 | 清计数前先 `NVIC_DisableIRQ(TIM4_IRQn)` + `NVIC_ClearPendingIRQ()`，清完再使能（U2 的 `s_ovf3/s_ovf1` 同样处理） |
| **D5** | `s_ph[]` 复位（`pulse_cap.c:95-97`）vs ISR 追加（`:128-134`）；`head`/`count` 非原子成对 | 边沿序号错 → `phase_settle` 的起始索引/奇偶判错 → **周期/占空比错值** | 同上。**U2 每 200 ms 复位一次滚动窗口，是高发侧**（U1 只在 `0x000F mode=1` 时复位一次） | 与 D4 同一处临界区一起处理：关中断 → 清环与计数 → 清 pending → 开中断 |
| **D6** | `uart_port.c` 的 TX：ISR 用"当前 `tx_head`"倒推已发长度（`:202-209`）；`tx_busy` 由主循环（`:68/:70`）与 ISR（`:210`）共同写 | 极端情况下 `tx_tail` 越过未发送字节 → **静默丢字节**（对端见半截帧/CRC 错）；`HAL_BUSY` 回退会造出"busy=0 但传输在飞"的窗口 | 传输途中主循环继续 push 新字节 / HAL 返回 BUSY | ISR 在启动一段发送时**快照本段长度**（发送前读一次 `tx_head` 存进 `tx_len`），完成时按它推进 tail；`kick` 里把"置 busy + 调 HAL + 失败回退"放进关中断的几拍 |
| D7 | ADC DMA 无同步点（`measure.c:94/236`） | 一次快照可能混入两轮扫描的值（不是撕裂读，但内部不一致）；主循环慢于一个扫描周期会漏轮 | 主循环被 USB 发送/打印阻塞时 | 现状可接受（`CNDTR` 回卷判轮 + EMA 才 1/64 权重）；要更稳可改双缓冲（半传输中断） |
| D8 | 调试打印阻塞：`MEAS_Print` 每秒一次走 `HAL_UART_Transmit`（`bsp_uart.c:31`，超时 100 ms） | 主循环最多停摆 100 ms（USB 帧处理、链路探测被推迟） | 调试模式（`BSP_DBG_ENABLE=1`，U1 默认开） | 只影响调试模式；生产模式自动关（`jig_mode.h`）。要更干净可改成中断发送 |
| D9 | USB 枚举/复位会重写 CDC 的 `TxBuffer/TxState`（`usbd_cdc_if.c:154`、`usbd_cdc.c:523`） | 正在发的帧被换指针/清忙 → 漏发或重发 | 主机复位/重新枚举（PC 侧点重启时） | 概率极低；协议层有 SEQ + 超时重试兜底，暂不处理 |
| D10 | `s_lost`（`pulse_cfg.c:38`）全工程无自增点 | 诊断量恒为 0，排障时会被误当作"没丢过边沿"的证据 | —— | 要么在标志被覆盖时自增，要么删掉这个字段 |
| R-A | 帧环满时丢弃的是**最新**字节（不是最旧） | 丢的是当前帧尾部 | PC 持续猛发 | 属安全降级方向（不覆盖已收数据）；CRC + `frame_resync()` 兜底 |
| R-B | USB 未枚举时 `hUsbDeviceFS.pClassData` 为 NULL | 解引用会 HardFault | 枚举前就发数据 | `APP_WaitTxDone()` 显式判 NULL 返回；发送只发生在收到帧之后 |
| R-C | 中断优先级：USB=0 / 串口=3 / 捕获=4 / SysTick=15 | 捕获中断不会挡 USB 与串口；SWD 烧录是主循环位翻转，会被串口/USB 打断但不会丢时序（每个位之间有延时循环） | —— | 本节论证不依赖优先级；结论只依赖"单核 + 单写者 + 原子读写" |
| R-D | `volatile` 只能阻止编译器重排，不提供内存屏障 | —— | —— | 单核同上下文可见，无需屏障；将来上 RTOS/双核要重新评估 |
