# 中断安全与并发分析（U1 / U2 固件）

> 触发来源：`logicprobe_concurrency_scan` 对"该环形缓冲是中断安全的 / 不存在数据竞争"这两条绝对断言标记为 **error（需要专门验证）**。本文给出显式证明与残余风险，替代模糊断言。
>
> **2026-10 复核**：四块功能（四路串口 / SWD 烧录 / ADC 测量 / TIM 脉冲捕获）接进来之后，
> 共享对象从"1 个帧环 + USB `TxState`"扩到 **7 类**。逐文件重核了一遍，
> 结论是：**协议层与串口收环仍然干净，但查出 6 处真实缺陷**（§4 的 D1~D6）。
> **D1~D6 已全部修完**（2026-10，两片都已改）：D1~D3 是第 20~22 轮修的，
> D4~D6 是第 29 轮修的（`docs/02` §7.33 有那一轮的完整记录，本文件 §6 是回归证据）。

## 3. 环形缓冲的显式正确性论证

记 `N = 512`，掩码 `M = N-1`，`H = ring_head`（生产者指针，仅 ISR 写），`T = ring_tail`（消费者指针，仅主循环写）。
所谓"存活区间"是环形区间 `[T, H)`；不变式 **INV：生产者永不写存活区间内的槽位**。

### 3.1 生产者不会覆盖未被读取的槽位

生产者序：`t ← T`（快照）→ `next ← (H+1) & M` → 若 `next == t` 则丢弃；否则 `ring[H] ← byte` → `H ← next`。

- **`T` 只会单调前进**（只由消费者推进）。因此生产者读到的 `t` 至多是"真实 T 的旧值"，
  用旧 `t` 判断"满"只会**更容易判满**（把可用空间算少），方向保守 → 最多多丢一个字节，不会误以为有空位。
- **写入的槽位是 `ring[H]`，消费者读的是 `ring[T]`。** 空时 `H == T` 且 `next ≠ H`，生产者写 `ring[H]` 而消费者此时不读任何槽；
  非空时 `H ≠ T`，故 `ring[H] ≠ ring[T]`。⇒ 生产者写入的槽位**永远不是**消费者正在读的那一个。∎

### 3.2 消费者不会读到写了一半的数据

- 生产者的可见顺序是 `ring[H] ← byte` **之后**才 `H ← next`；`H` 是 `volatile`，编译器不会重排。
  消费者只有在观察到 `H` 前进后才可能取到新字节。∎
- 消费者序：`b ← ring[T]` → `T ← (T+1)&M`。中断可能插在两条指令之间推进 `H`，但不会影响 `ring[T]`（由 3.1 保证），
  也不会撕裂 `T`（见 3.3）。∎

### 3.3 指针读写不会撕裂

Cortex-M3 上对**自然对齐的 16 位对象**的读写是单条 `LDRH`/`STRH`，中断只能在指令边界插入。
故 `H`、`T`、`uwTick` 的每次读写都是原子的；`TxState`、`tx_busy`、`s_running` 是 `uint8_t`，同理。∎

### 3.4 消费者读到"过期的 H"是安全的

主循环读 `H` 时被中断打断、中断推进了 `H`，则主循环用的是旧 `H`：循环提前结束，本轮少取几个字节，
**下一轮 `APP_Frame_Poll()` 会继续取**。方向安全。∎

### 3.5 结论与前提

在上述前提（**恰好一个生产者、恰好一个消费者、各指针单一写者、单核、指针自然对齐且为 volatile**）下，
环形缓冲**不需要关中断、不需要互斥锁**。

> ⚠ **2026-10 复核：前提已被破坏一处** —— `APP_Frame_Init()` 会写 `ring_head`（`app_frame.c:125`），
> 而它是 ISR 的写变量（`app_frame.c:138`），调用点 `app.c:265/712/772` 都在主循环。
> 于是 §3 的证明对当前代码**不再成立**，这就是 **D1**。修法见 §4。
>
> ⚠ 另外，一旦有人把 `APP_Frame_Feed` 从主循环调用（变成两个生产者），或把 `APP_Frame_Poll` 放进中断，
> 本证明同样立即失效。代码注释里已标注"仅 ISR 调用 / 仅主循环调用"。

`uart_port.c` 的**收环**（256B/路）与本节同型（ISR 单写 head、主循环单写 tail），因此同样不需要临界区。

## 4. 缺陷与残余风险（按严重度排序）

> **D1~D6 是逐文件复核发现的真实缺陷，2026-10 已全部修完**（下表「修法」栏标 ✅ 的六条）；
> D7 起是已知的、有意的降级或概率极低的窗口。
>
> ⚠ **D4 的诚实结论（别当成"修掉了一个必然发生的错值"）**：读完代码后的结论是 ——
> "关 DIER 挡不住已排队的 NVIC 请求"这个**机制**是真的，但老代码里**没有可复现的错值路径**：
> `PCFG3_TIM->SR = 0`（清 UIF）在 `s_ovf3 = 0` **之前**执行，而"计数器刚被 CNT=0 复位后
> 又要溢出"需要 0.91 ms，所以排队的那一发中断进来时读到的 SR 里已经没有 UIF 了。
> 也就是说老代码是**靠一个偶然的语句顺序**躲过去的，而不是靠同步手段。
> 本次修复把这条保证变成显式的（关 NVIC + 清 pending 之后才动状态），
> 不再依赖那个顺序。D5 不一样 —— **D5 是可触发的**（见下表"触发条件"）。

## 5. 与逻辑探针结论的对应
