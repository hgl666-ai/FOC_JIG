# 25 上板测试步骤（新增功能：ASCII 控制台 + 六步流程）

> 面向台架实测。烧录方式沿用你现有 ISP 流程，本文件只讲**新增功能的验证顺序**。
> 原则：**先证明治具自己活着 → 再证明控制台能转发 → 最后跑流程**。
> 任何一步不过就停在那一步，别往下猜。

---

## 0. 烧哪份固件

| 场景 | 烧哪个 | PC 口 |
|---|---|---|
| **台架（用串口助手/工具）** | `U1/MDK-ARM/U1_DUT/U1_DUT.hex` | USART1（PA9/PA10，USB-TTL） |
| 产品形态（PC 走 USB） | `U1/MDK-ARM/U1/U1.hex` | USB CDC（当前 D+/D- 反着，先别用） |

**现在做台架测试 → 烧 `U1_DUT.hex`**。烧法（你现成的流程）：H1/BOOT0 拉高 → 复位 → USART1 烧 → BOOT0 拨回 → 复位。

## 1. 接线检查清单

| 线 | 从 | 到 | 备注 |
|---|---|---|---|
| PC↔治具 | USB-TTL TXD | 治具 **PA10** | |
| | USB-TTL RXD | 治具 **PA9** | |
| | GND | 治具 GND | |
| 治具↔FOC | 治具 **PB10**（TX） | FOC **RX** | 交叉，别接反 |
| | 治具 **PB11**（RX） | FOC **TX** | |
| | GND | FOC GND | **必须共地** |
| 跳线 | H3 / H4 | **拔掉** | 台架形态 U2 让位给 FOC |

动力：24 V 母线上电（**手放在电源开关上** —— 流程会让电机转起来）。

---

## 2. 第一步：治具自己活着吗

上电后串口助手（115200 8N1）应该能收到治具的**横幅**（`JIG` 开头几行）。

| 发（HEX 模式） | 期望 | 不过说明 |
|---|---|---|
| `A5 5B 00 17 00 01 00 00 4A 45` | 回 32 字节，第 3 个数据字节 `flags` 的 **bit3 = 1** | 烧错固件了（烧成 `U1_UART`？）或串口没通 |

> ⚠ 串口助手**别勾"发送新行"**（帧尾多两个字节 → CRC 错 → 治具静默丢弃）。

---

## 3. 第二步：ASCII 控制台能转发吗

**先不接 FOC**（或 FOC 还没实现 AS 命令时）：

| 发（文本） | 期望 | 说明 |
|---|---|---|
| `AS:Bb` | `[JIG] no reply from FOC` | 治具收到了、转出去了、没人回 —— **控制台是好的** |

**接上 FOC 之后**：

| 发 | 期望 | 不过说明 |
|---|---|---|
| `AS:Bb` | `AS:V1.2.3\r\n` | FOC 没实现 / 波特率不对 / TX-RX 接反 |
| `AS:S0` | 无回字（或 `AS:OK`） | 电机停 |
| `AS:CS` | `AS:A0`~`AS:A3`（≤5 秒） | 见 §6 故障表 |

> 回车可有可无：不带回车时**静默 50 ms** 就发出去。
> 治具**不会**替你加 `\r\n` —— 与已验证可用的 `AS:S800`/`AS:S0` 一致。

## 4. 第三步：六步流程

### 4.1 用工具（推荐，能直接把报告翻成人话）

```
python tools\foc_jig_tool.py -p COM4 flow6
```

### 4.2 用串口助手手工发

```
发: A5 5B 00 22 00 02 00 00 4E 39
```

**全绿时应答（21 字节，共 31 字节帧）**：

```
A5 5B 00 22 00 02 00 15 | 00 06 00 | 01 00FF | 01 0000 | 01 0000 | 00 0000 | 00 0000 | 01 0000 | 91 FA
                          状态 步数 失败步  ①ADC    ②存活    ③自检    ④三相    ⑤编码器  ⑥收尾
```

**自检报 A3（相位缺失）时应答**（会走第 4 步采三相）：

```
A5 5B 00 22 00 02 00 15 | 05 06 03 | 01 00FF | 01 0000 | 01 0003 | 01 0007 | 00 0000 | 01 0000 | DF 60
                          状态 步数=6 失败步=3  ADC    存活     自检=A3   三相=7(全有)  编码跳过   收尾
```

---

## 4.3 报告里的 detail 怎么记（2 字节，大端）

```
步1 adc_bad_ch = FF → 六路全好 / 0~8 → 那一路坏
步2 alive_tries = 0 → 通了 / >0 → 问了几次都没回（上限 15）
步3 cs_code     = 0 A0 全好 · 1 A1 ADC坏 · 2 A2 编码器坏 · 3 A3 缺相 · FF 超时
步4 pwm_mask    = 7 → 三相都有 · 0 → 都没有 · 1/2/4 → 只有 A/B/C
步5 enc_mask    = 7 → 三相对上 · 0 → 没收到/全错 · 1/2/4 → 只有 A/B/C 对上 · FFFE 内部错
```

> `code = 00`（跳过）的步，detail 恒 `0x0000` —— 那是"没走这条分支"，不是"测出来是 0"。

## 5. 建议的测试顺序（**安全**）

| 轮次 | 电机 | 目的 | 期望 |
|---|---|---|---|
| 1 | **不接** | 验流程能跑完、能正确报失败 | 通常 `AS:CS` 报 A1/A2/A3（没电机时自检本来就过不了）→ 流程照样给出报告，**不卡死** |
| 2 | 接上、小电流限流 | 验正常路径 | 全绿 `status=00` |
| 3 | 接上 | 拔掉一相动力线 | `AS:A3` → 步4 只应看到两相有波形（掩码 3/5/6）→ 判"MCU 正常、驱动级缺相" |
| 4 | 接上 | 拔掉编码器 | `AS:A2` → 步5 计数不符或 C0 → 判失败 |

> ⚠ 每轮之间断电重启，避免上一轮的注入值/状态残留。
> ⚠ 第 3/4 轮是**故意造故障**，确认判据真的能区分，不是"能跑就行"。

## 6. 故障对照表

| 现象 | 最可能原因 | 怎么确认 |
|---|---|---|
| 控制台发 `AS:Bb` 回 `[JIG] busy` | 治具正在跑别的命令/流程 | 等它回 IDLE 再发 |
| 控制台回 `[JIG] no reply` | FOC 没回：波特率不对 / TX-RX 没交叉 / 没共地 / 命令要 `\r\n` | 先用示波器看 PB10 有没有波形 |
| 帧命令（`A5 5B`）完全没回 | 串口助手勾了"发送新行" | 关掉再试 |
| `0x0022` 步1 失败，detail 指向某通道 | 该路**取样线没接**（10V/5V/3.3V 是治具自己的取样网络） | 按 detail 的通道号查线，不是板子坏 |
| 步2 失败（15 次没回） | 板子没起来 / 串口不对 | 回到 §3 用 `AS:Bb` 手工确认 |
| 步3 detail=`FF` | `AS:CS` 5 秒没回 | 校准可能更慢；或 FOC 没实现 |
| 步4 掩码 0 | 三路都没 PWM：`AS:PW` 没实现 / 采集没接到 | 先用示波器看 MCU 的 MA_IN/MB_IN/MC_IN |
| 步5 掩码 0 | 没收到 `AS:AaBbCc` | FOC 是否真的主动上报？格式对不对（脉冲个数、不带前导 0） |
| 报告 `status=05` 但看不出哪步 | 看 `fail_step` 和那一步的 code/detail | 工具 `flow6` 会直接把表打出来 |

## 7. 两个已知的"还没验"的点

| 项 | 说明 |
|---|---|
| 步4 的**单相缺失** | 宿主已验（掩码 3/5/6/1/0 五条用例都对），但**真机上拔一相才最终确认** |
| 步4 的`AS:PW` **实际频率/相位** | 规格要求 1 kHz 三相同步 50%，只有真机能确认；若实测不是 1 kHz，流程会判"没波形"（这是对的，但要改 FOC 侧） |
