# U1 固件实施计划（Detailed Change Plan）

> 目标：让 PC 能通过 USB CDC，把 FOC 板固件上传到治具 SPI Flash，并触发 ISP 烧录。
> 对应协议：`INFO/M1 测试治具PC端通讯协议.xlsx`
> 参考实现：`D:\Project\diameter_JIG\U1\U1project`

---

## 1. 目标与非目标

### 本次目标（In Scope）
1. U1 固件可编译、可通过 USB CDC 与 PC 通信。
2. 实现 xlsx 中全部 6 条命令：
   - `0x0009` 固件起始帧 → 选槽 / 解保护 / 擦扇区 / 写头部 / 进 UPLOADING
   - `0x000A` 固件数据帧 → 攒 256B 页 → 写 SPI Flash
   - `0x000B` 固件结束帧 → 刷残页 / 比对字节数 / 写完整标志 `0xA5` / 切槽 / 回 IDLE
   - `0x000C` 查询固件版本号（Flash 中）
   - `0x0112` 烧录 Flash 固件到 FOC 板（ISP，非阻塞状态机，烧完才回 ACK）
   - `0x000D` 查询固件版本号（FOC 板中）
3. 未识别命令统一回 `NIY(0xFF)`（协议状态码表已定义该码，属错误处理而非新增命令）。
4. Keil MDK 编译 0 Error / 0 Warning，产出 `.hex` / `.axf`。

### 非目标（Out of Scope，本轮不做）
- U2 固件（用户确认：U2 只做测试测量，烧录链路 U1 独立完成）。
- ADC / 电流 / 驱动信号等测试功能。
- PC 上位机软件。
- 新增 `PING`、查询 U1 自身版本等 xlsx 之外的命令（用户明确"只做 6 条"）。

## 2. 关键设计决策

| # | 决策 | 依据 |
|---|---|---|
| D1 | PC 链路 = **USB CDC 虚拟串口**（U1 PA11/PA12 → USB-B 座） | 用户确认 + 原理图 R90 1.5k D+ 上拉 + USBLC6-2E |
| D2 | xlsx 的「460800」不作波特率依据 | USB CDC 无真实波特率 |
| D3 | 帧格式 `A5 5B\|CMD(2)\|SEQ(2)\|LEN(2)\|DATA\|CRC16(2)`，全部**大端** | xlsx Sheet1 |
| D4 | CRC = MODBUS（poly 0xA001 反射，init 0xFFFF），范围 `F..D`，CRC 大端 | xlsx Sheet1 |
| D5 | 外层 Flash = **GD25Q128 @ SPI2**，软件 CS = **PB12** | 原理图 U10 与 U1 连线 |
| D6 | 双槽布局：Slot0(Bootloader)@0x00000、Slot1(App)@0x10000，每槽 64KB | 用户确认（同测径治具） |
| D7 | 头部 8B：`[0..3]` size u32 **小端**、`[4..6]` 版本号、`[7]` 完整标志 `0xA5` | 同测径治具 |
| D8 | 被烧板地址：Bootloader@0x08000000(0x5000) + App@0x08005000(0xA000) | 用户确认 |
| D9 | ISP 走 USART3，BOOT0/RESET 引脚 **宏占位**，待硬件确认 | 用户："还不清楚，可以先宏定义空着，后续提醒我" |
| D10 | ISP 目标器件默认按 **STM32F1（AN3155）** 实现，G0 差异（8 字节对齐）用宏切换 | 用户："U1 和 U2 都是 STM32F103C8T6" |
| D11 | 打开 SWD（移除 `__HAL_AFIO_REMAP_SWJ_DISABLE()` 与 PA13 EXTI 输入） | 原理图把 SWD 引到排针；CubeMX 的 No_Debug 会让 SWD 永久失效，阻断调试 |
| D12 | 删除 `Core/Src/usb.c`，USB 初始化改由 `USB_DEVICE/` 提供 | 避免 `hpcd_USB_FS` / `HAL_PCD_MspInit` 重复定义 |
| D13 | 板上无 LED，去掉参考实现的 `APP_SetRGB` | 原理图无 LED |

## 4. 状态机（供 logicprobe 校验）

### 4.1 顶层 `app_state`

| 状态 | 说明 |
|---|---|
| `IDLE` | 空闲，可接受任何命令 |
| `UPLOADING` | 固件上传中，只接受 `0x000A` / `0x000B` |
| `PROGRAMMING` | ISP 烧录中，只接受 `0x0112`（回 BUSY） |

转移表：

| # | from | event | guard | to | action |
|---|---|---|---|---|---|
| T1 | IDLE | `0x0009` 且 len≥9 且 0<size≤SLOT-8 且 frames>0 | — | UPLOADING | 解保护→擦扇区→写头部→ACK(00) |
| T2 | IDLE | `0x0009` 非法参数 | len<9 ∨ size=0 ∨ size>限 ∨ frames=0 | IDLE | ACK(ERR_SIZE) |
| T3 | IDLE | `0x0009` 擦除/写头失败 | — | IDLE | ACK(ERR_FLASH) |
| T4 | UPLOADING | `0x0009` | — | UPLOADING | ACK(BUSY) |
| T5 | UPLOADING | `0x000A` 且 `upload_error==0` 且 未溢出 | — | UPLOADING | 攒页→写 Flash→ACK(00) |
| T6 | UPLOADING | `0x000A` 且 `upload_error!=0` | — | UPLOADING | ACK(锁存错误码) |
| T7 | UPLOADING | `0x000A` 溢出 | count+len>total | UPLOADING | 锁存 ERR_OVERFLOW→ACK(0x0D) |
| T8 | UPLOADING | `0x000A` 写 Flash 失败 | — | UPLOADING | 锁存 ERR_FLASH→ACK(0x03) |
| T9 | UPLOADING | `0x000B` 且 error==0 且 count==total | — | IDLE | 刷残页→写完整标志→切槽→ACK(00) |
| T10 | UPLOADING | `0x000B` 且 count≠total | error==0 | IDLE | ACK(ERR_COUNT)，**不写完整标志**，切槽 |
| T11 | UPLOADING | `0x000B` 且 error!=0 | — | IDLE | ACK(锁存错误码)，不写完整标志，切槽 |
| T12 | UPLOADING | 10s 无新数据 | — | IDLE | ACK(ERR_TIMEOUT 或锁存错误码) |
| T13 | PROGRAMMING | `0x0112` | — | PROGRAMMING | ACK(BUSY) |
| T14 | IDLE | `0x0112` 且 两槽均有完整固件 | — | PROGRAMMING | ISP 状态机启动 |
| T15 | IDLE | `0x0112` 且 固件缺失 | size=0 ∨ 越界 | IDLE | ACK(ERR_NO_FW 0x06) |
| T16 | IDLE | `0x0112` 且 固件不完整 | flag≠0xA5 | IDLE | ACK(ERR_INCOMPLETE 0x07) |
| T17 | PROGRAMMING | ISP 全部步骤成功 | — | IDLE | ACK(00) |
| T18 | PROGRAMMING | ISP 任一步失败 | — | IDLE | ACK(ERR_PROG 0x04) |
| T19 | 任意 | 未识别 CMD | — | 不变 | ACK(NIY 0xFF) |

### 4.2 ISP 子状态机（`isp_state`）

`ISP_S0_IDLE → S1_CONNECT(BOOT0=H,RESET=L,10ms,RESET=H,50ms,发0x7F,等ACK) → S2_MASS_ERASE(0x44) → S3_WRITE_BL → S4_WRITE_APP → S5_GO → S6_DONE`

## 5. 不变量（Invariants）

| # | 不变量 |
|---|---|
| I1 | `app_state==UPLOADING` 时 `upload_count ≤ upload_total` 恒成立 |
| I2 | 完整标志 `0xA5` 只在 `count==total 且 无错误` 时写入 |
| I3 | `PROGRAMMING` 期间不响应除 `0x0112` 外的任何命令（回 BUSY） |
| I4 | `0x0112` 的 ACK 只在 ISP 状态机到达终态后发出一次，不重复 |
| I5 | 任何状态下 `0x0112`/`0x0009` 都不会让状态机"卡死"（每条转移都有出口） |
| I6 | Flash 擦除/写入前必先 `GD25Q_Unprotect()`（BP 位保护会导致静默失败） |
| I7 | 帧接收缓冲区不越界：`LEN > 256` 的帧被丢弃并重新同步 |

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| ISP 引脚未定 | 0x0112 无法真正烧录 | 全部集中到 `isp_config.h`；未配置时 ISP 直接回 `ERR_PROG` 并在代码注释标 `TODO` |
| 被烧板是 G0 而非 F1 | 写内存对齐报错 | `ISP_TARGET_F1` / `ISP_TARGET_G0` 宏切换 8 字节对齐 |
| 双镜像槽位与真实固件不符 | 烧录地址错 | 全部宏化（`flash_map.h`），改一处即可 |
| USB CDC 首次枚举失败 | PC 收不到任何帧 | 保留 SWD；USB MspInit 显式配 PA11/PA12 为 AF_PP（参考实现踩过的坑） |
| ARMCC 5 栈/堆不足 | 运行崩溃 | 保持 CubeMX 的 Stack 0x400 / Heap 0x400；大缓冲一律 `static` |
| 16MB Flash 擦除耗时长 | PC 侧超时 | Slot 只擦所需扇区（≤64KB/槽），不整片擦 |
