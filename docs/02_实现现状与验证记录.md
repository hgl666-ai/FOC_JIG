## 2. 协议（从 xlsx 逐格提取）

### 2.1 单帧结构（最低 10 字节）

| 字段 | 帧头 F | 命令 C | 帧序号 N | 数据长度 L | 数据 D | CRC16 |
|---|---|---|---|---|---|---|
| 字节数 | 2 | 2 | 2 | 2 | * | 2 |
| 数据类型 | A5 5B | uint16_t | uint16_t | uint16_t | * | uint16_t |

- **字节序**：所有数据**大端**。
- **帧头**：固定 `0xA5 0x5B`。
- **命令**：从 `0x01` 开始，`0x00` 不使用。
- **帧序号**：从 `0x01` 起递增 u16，`0xFFFF` 后回卷到 1；**序号 0 特殊对待**（治具主动帧用 0）。
  PC 发一帧 → 治具回 ACK，**ACK 序号与收到的序号相同**。
- **数据长度**：u16，表示 D 的字节数。
- **CRC16**：MODBUS/CRC16，**从「帧头 F」到「数据 D」全部参与计算**，CRC 本身大端存放。

### 2.2 命令表

| 功能 | 发送方 | 命令 | 帧序号 | LEN | 数据 D |
|---|---|---|---|---|---|
| 固件 起始帧 | PC | `0x0009` | N | 9 | 2B u16 总帧数 + 4B u32 文件大小 + 3B 版本号 |
| 固件 起始帧 ACK | 治具 | `0x0009` | N | 1 | 1B 错误码 |
| 固件 数据帧 | PC | `0x000A` | N | L | L 字节 OTA 数据 |
| 固件 数据帧 ACK | 治具 | `0x000A` | N | 1 | 1B 错误码 |
| 固件 结束帧 | PC | `0x000B` | N | 0 | / |
| 固件 结束帧 ACK | 治具 | `0x000B` | N | 1 | 1B 状态码 |
| 烧录 Flash 固件到 FOC 板 | PC | `0x0112` | N | 0 | / |
| 烧录 Flash 固件 ACK | 治具 | `0x0112` | N | 1 | 1B 状态码（**烧录完成后才返回**，`00` 成功） |
| 查询固件版本号（Flash 中） | PC | `0x000C` | N | 0 | / |
| 查询固件版本号 ACK | 治具 | `0x000C` | N | 4 | 状态码 + 3B [主][次][修订] |
| 查询固件版本号（FOC 板中） | PC | `0x000D` | N | 0 | / |

> **⚠ 修正记录（第 7 轮，用户确认）**：`0x0112` 最初被误读成 `0x0070` —— xlsx 该单元格存的是**数值 `112`**，

| 码 | 名称 | 码 | 名称 |
|---|---|---|---|

## 3. 架构

```
PC ──USB CDC──▶ 治具 U1 ──SPI2(PB12 CS)──▶ GD25Q128(16MB) 存被烧固件
                    │                        Slot0=Bootloader @0x00000
                    │                        Slot1=App        @0x10000
                    └──0x0112──▶ UART ISP (AN3155) ──▶ 外接被烧板 MCU
```

- 原理图这块板 = **治具**（U1 主控 + U2 副控）；**被烧 MCU 是外接的另一块板**（用户第 8 轮确认）。
- 与测径治具同构：外部 SPI Flash 存固件 + U1 做 ISP 烧录。
- 被烧板目标地址：Bootloader `0x08000000`(0x5000) + App `0x08005000`(0xA000)。

## 5. 与协议 xlsx 的逐条对照

| 命令 | xlsx 要求 | 实现 |
|---|---|---|
| `0x0009` | LEN=9：总帧数 u16 + 文件大小 u32 + 版本 3B | ✅ 大端解析；`len<9 / size=0 / size>限 / 帧数=0` → `02 ERR_SIZE`；擦除/写头失败 → `03 ERR_FLASH`；非 IDLE → `01 BUSY`；**另加 SPI Flash ID 自检**（见 §7.6） |
| `0x000A` | LEN=L：OTA 数据 | ✅ 攒 256B 页编程；溢出 `0D`；写失败 `03`；**错误锁存**（后续 DATA 帧只回原错误码、不写 Flash） |
| `0x000B` | LEN=0 | ✅ 刷残页 → 比对字节数（不符 → `0A`，**不写完整标志**）→ 写 `0xA5` → 回读校验 → 切槽 |
| `0x0112` | LEN=0；**烧录完成后才回 ACK** | ✅ 前置检查两槽（缺固件 `06` / 不完整 `07`）→ 启动非阻塞 ISP 状态机；终态由主循环回**一次** ACK（SEQ 锁存为受理时的序号） |
| `0x000C` | LEN=4：状态码+3B 版本 | ✅ 优先级 App 槽 → Bootloader 槽 |
| `0x000D` | LEN=4：失败时 `00 FF FF` | ✅ 走 `ISP_QueryTargetVersion()`；**被烧板版本查询协议未定，当前恒返回 `0C`+`00 FF FF`**（用户已同意先不管） |
| `0x000E` | LEN=1(mode)；mode=1 时**测试跑完才回 ACK** | ✅ 见 docs/07 §3-§4：非阻塞测试状态机（等稳定→与 U2 交换快照→比对→判定→回 77B）；mode=0 立即回最近一批，不触发测试 |
| 其它命令 | 状态码表定义了 `NIY(0xFF)` | ✅ 统一回 NIY |
| CRC 错误 | "仅诊断, 不回 ACK" | ✅ 直接丢弃，不回 ACK |
| 上传超时 | 10s 无新数据 | ✅ 自發 `0x000A`+`0C`，回 IDLE；不覆盖已锁存的错误码 |
| 非 IDLE 收命令 | "系统忙" | ✅ `UPLOADING`/`PROGRAMMING` 期间一律回 `01 BUSY` |

## 7. 验证过程抓出并修复的缺陷

> ⚠ 本节里**带 ISP / isp_* / BOOT0 字样的条目属于已退役的 ISP 时代**（源码与测试已删除，见附录 A）。
> 保留它们是因为教训本身仍然适用（命令要自适应、失败要恢复现场、被宏包住的代码最容易藏 bug），
> 但**不要再去改 `isp_programmer.c` / `isp_config.h`** —— 那两个文件已经不存在了。

### 7.1 帧接收缓冲区越界（第 1 轮，单测暴露）

原实现把帧解析直接放在中断里跑，一帧收完（`frame_ready=1`）后若上层还没取走，
后续字节会继续写 `frame_buf` 并把 `frame_pos` 一直加下去 → **缓冲区越界写**（内存踩踏）。
PC 把两帧粘连发出即可触发。

**修复**：改为「ISR 只压 512B 环形缓冲 + 主循环解析」，攒满一帧即停止出队。
> 同一套写法在参考项目 `diameter_JIG` 里也存在。

### 7.2 伪帧头导致长时间失步（第 1 轮）

头部只认 `A5 5B` 就无条件吃满 8 字节，遇到数据里出现的伪帧头会吞掉后续合法帧。

**修复**：`frame_resync()` —— LEN 非法时在已缓存字节里寻找下一个 `A5 5B` 重新对齐；伪帧头最终由 CRC 兜底。

### 7.3 ISP 擦除命令用错（第 2 轮，致命）

原实现照搬 G0 参考工程，只发 `0x44 Extended Erase`。
但 **`0x44` 是 bootloader v3.0+ 才有的命令；STM32F103 的 bootloader 是 v2.2，只认 `0x43`**。
若被烧板是 F103，**必然烧不进去**。

**修复**：握手后先读目标 bootloader 版本（AN3155 `0x01`），按版本决定先发 `0x43` 还是 `0x44`，另一个作兜底。
两条命令的全片擦除载荷都是 `FF FF 00`。

### 7.4 被烧板分区无边界校验（第 2 轮）

原来只校验 `size>0 且 ≤64KB-8`，未按槽位限制。若 Bootloader 镜像超过 `0x5000`，**会越界写坏 App 区**。

**修复**：`APP_ProgramPreCheck` 在**擦除之前**按槽位上限拒绝；`ISP_LoadImageHead` 再兜一层。

### 7.5 `ISP_WriteChunk` 的未使用形参（第 2 轮）

带一个 `data` 形参却从不使用（实际一直发模块内的 `s_buf`），是误用陷阱。已删掉形参并注明调用约束。

### 7.6 先擦除、后校验镜像头（第 3 轮，致命）

`ISP_ST_CONNECT` 原顺序是「握手 → 读版本 → **全片擦除** → 读头部校验 → 写」。
若镜像不合格（大小超分区 / 完整标志缺失 / 槽为空），**被烧板已经被擦掉却什么都没写进去 —— 板子报废**。
App 层的前置检查虽然挡得住，但 ISP 模块自身不该依赖调用方守规矩。

**修复**：改成**先把两段镜像头都校验通过（含分区上限），再擦除**；两段长度提前存进
`s_img_len_boot` / `s_img_len_app`。用例 T5/T9/T10 固化了这个顺序。

### 7.7 `GD25Q_ReadID` 比对常量错误（第 4 轮）

原实现（照搬参考工程）先发 3 个 dummy 再读 2 字节，并与 **`0xC817`** 比较。
查本地数据手册 `GD25Q128E Rev1.4`：JEDEC ID（RDID `0x9F`）= **`C8 40 18`**。
原实现读到的是 ID **之后**的字节，**在真实芯片上永远不可能相等** —— `GD25Q_Test()` 恒失败。

**修复**：正确返回 24 位 ID `0xC84018`，`GD25Q_Test()` 校验「制造商 `0xC8` + 容量 `0x18`」。

### 7.8 命令码读错（第 7 轮，用户指出）

见 §2.2 的修正记录：`0x0070` → **`0x0112`**。

### 7.9 PC 工具的两个可用性缺陷（第 8 轮）

1. 参数校验晚于开串口（`-p COM5 burn` 漏参数会先报串口错）→ 改为**先校验参数、再开串口**；
2. 端口打不开时抛裸 traceback → 改为友好提示 + 三条排查方向。

### 7.10 SPI Flash 提前自检（第 6 轮，新增能力）

`GD25Q_Test()` 此前无人调用、被链接器当死代码剔除。现接到 `0x0009` 的参数校验之后、擦除之前：
Flash 不在线 / 型号不对时，**第一条命令**就以 `03 ERR_FLASH` 暴露，而不是"擦除静默失败"或"上传到一半才报错"。
用例 T13 固化（RDID 返回全 0 → `0x0009` 回 `03`，且零擦除零写入）。

### 7.11 ISP 失败后没有恢复现场（第 9 轮，两处）

`ISP_SetFail()` 原来只改状态码，**不恢复任何硬件状态**：

- **BOOT0 一直保持高电平** → 治具持续把被烧板的 BOOT0 拉高，被烧板停在 bootloader，
  相当于被外部一直驱动一个启动配置脚。
- **ISP 串口一直停在 8E1** → 之后任何走这个口的**运行态（8N1）**收发都会因校验位不匹配而失败。
  典型表现：**第一次烧录失败之后，后面怎么都不对**。

**修复**：`ISP_SetFail()` 里把 BOOT0 拉回低电平、串口切回 8N1。
刻意**不**额外复位被烧板 —— 让它在 bootloader 里等下一次 `0x0112`，重试更直接。
（测径治具的 `ISP_Connect()` 失败时不做恢复，这里是刻意改进。）

另修一处：`BSP_ISP_UART_Init()` 原来把串口**上电就配成 8E1**，而那时还没有任何 ISP 会话；
改为上电默认 **8N1（运行态）**，由 `ISP_Start()` 在进入 bootloader 会话时才切 8E1。

### 7.12 补齐两块此前完全没有验证的契约（第 9 轮）

新增两个用例，把"我以为对"变成"已断言"：

| 用例 | 断言内容 | 编译配置 |
|---|---|---|
| **T14** | 进 ISP 切 8E1、**成功路径与失败路径退出时都必须回到 8N1** | 全部 3 种配置 |
| **T15** | BOOT0/RESET **波形**：先置空闲电平（BOOT0=0/RESET=1）→ BOOT0 拉高 → 紧接着 RESET 拉低 → 维持 ≥10ms → RESET 拉高；Go 之后与**失败之后**都必须把 BOOT0 放开 | `ISP_CTRL_PINS_CONFIRMED=1` |

> **T15 同时也第一次编译到了 `ISP_GpioInit()` 的函数体** —— 默认配置下那段被 `#if` 编译掉，
> 主机上从未构建过。新配置一上去就暴露了宿主 HAL 替身里缺 `GPIO_SPEED_FREQ_LOW` 宏的问题。

> **T15 第一版是我的测试写错了**：我假设"第 1 次 GPIO 写就是 BOOT0 拉高"，
> 但 `ISP_GpioInit()` 会**先**写空闲电平，所以真正的第 1、2 次写是 `BOOT0=0 / RESET=1`。
> 固件是对的，改成"定位 BOOT0 第一次拉高那一步再往后查"后通过。

### 7.13 控制脚 GPIO 端口时钟没开（第 10 轮，**只在打开 `ISP_CTRL_PINS_CONFIRMED` 后才暴露**）

`ISP_GpioInit()` 会把 **PC13（GPIOC）** 配成 RESET 输出，但
CubeMX 生成的 `MX_GPIO_Init()` 只使能了 **GPIOD / GPIOA / GPIOB**（板上实际用到 A/B），
**没有使能 GPIOC**。

STM32F1 上对"时钟未使能"的 GPIO 端口写 BSRR/BRR 是**静默无效**的。后果：
**RESET 永远不翻转 → 被烧板永远进不了 bootloader → 烧录必定失败**，而且没有任何报错线索。

**修复**：`ISP_GpioInit()` 里显式打开 GPIOA/GPIOB/GPIOC 三个端口时钟
（已使能的重复使能无害），这样以后把 BOOT0/RESET 改到任意 A/B/C 引脚都不会再踩这个坑。

> 这个 bug 从第 1 轮就在，但一直**不可见**：`ISP_GpioInit()` 的函数体整体被
> `#if (ISP_CTRL_PINS_CONFIRMED)` 包着，默认配置下根本不编译。
> 上一轮为了验证引脚波形加了 `pins` 编译配置，它才第一次被编译到 —— 一编译就暴露了。

**验证（T16，并证明测试有牙）**：宿主侧给 `RCC` 做了替身，测试直接断言 `APB2ENR` 的
IOPAEN/IOPBEN/IOPCEN 位。临时把三行时钟使能删掉重编：

```
[T16] 控制脚所用 GPIO 端口的时钟必须被使能
  FAIL: GPIOB 时钟已使能 (BOOT0)
  FAIL: GPIOC 时钟已使能 (RESET)
  FAIL: GPIOA 时钟已使能
    APB2ENR = 0x00000000        ← 修复前
```
恢复后 `APB2ENR = 0x0000001C`，全部通过。

### 7.14 PC 工具：`0x0009` 的 ACK 超时设置得太短（第 11 轮）

`foc_jig_tool.py` 的 `do_upload()` 用**默认 3 秒**等 `0x0009`（起始帧）的 ACK。

但 `0x0009` 在固件里会**触发扇区擦除**：按声明大小擦掉覆盖的 4KB 扇区，最大镜像 65528B → 最多 **16 个扇区**，
GD25Q128 单扇区擦除最长 **400ms** → 最坏约 **6.4 秒**。

> **后果**：真实硬件上会偶发"起始帧超时" —— 治具其实正在正常擦除，PC 却已经放弃了。
> 固件侧没有问题（擦除期间 `app_state` 还是 IDLE，不会误触发 10s 上传超时），纯粹是 PC 侧超时值不对。

**修复**：新增 `ERASE_TIMEOUT = 30.0`，`0x0009` 用它；超时提示里写明"该帧会触发扇区擦除"。

### 7.15 新增：一键烧录的镜像本地预检（第 11 轮）

`burn` 现在**在开串口之前**先把两个固件文件检查一遍（`preflight_burn()`）：

| 检查 | 硬错误? |
|---|---|
| 文件存在 / 可读 / 非空 | ✅ 是 |
| 不超过被烧板对应分区上限（Bootloader `0x5000` / App `0xA000`） | ✅ 是 |
| 向量表看起来像 Cortex-M 镜像（SP ∈ `0x2000xxxx`、复位向量为奇数 Thumb） | ❌ 仅提示不拦 |

两条设计考虑：
1. **放在开串口之前** —— 文件搞错不该先被"端口打不开"挡住；
2. **分区上限与固件 `flash_map.h` 的 `DUT_BOOT_SIZE`/`DUT_APP_SIZE` 对齐** ——
   提前拦下比"上传 40KB 后再被 0x0112 拒绝"省事，也避免操作员把 Boot 和 App 传反。

已用三个构造文件无硬件验证：正常文件→预检通过（随后才报端口打不开）；Bootloader 超限→**开串口前**被拒；
空文件→**开串口前**被拒。`selftest` 也加了 6 条纯函数用例（空/超限/正常/SP 异常/复位向量异常/Boot 超限）。

### 7.16 测量功能：整数 EMA 的滤波死区（第 13 轮，单测暴露）

**现象**：阈值阶跃测试里，V5 通道（α=1/64）从 5.000 V 阶跃到 4.000 V，
跑 600 次轮询后停在 **4.061 V** 不再收敛。

**根因**：指数滑动平均写成 `avg += (x - avg) >> shift`，当 `|x-avg| < 2^shift`
时增量被截断成 0。以毫伏为单位时 shift=6 的死区是 **±63 mV**
（3.3V 通道上相当于 1.9% 误差），相电压通道 shift=8 更是 **±255 mV**。

**修复**：内部换算与滤波一律改用**微伏**，死区降到 64 µV / 256 µV，
折算到输入侧 < 2 mV（可忽略）；同时把 `uV→mV` 的显示改成四舍五入。

**顺带修掉的同类问题**：滤波更新频率原本跟着主循环走（远高于 25 kHz 的 ADC 扫描率），
等效平均样本数会大幅减少、窗口时间常数也随环路频率漂移 →
改用 `DMA1_Channel1->CNDTR` 回卷判定"完成一轮扫描"，**一轮只更新一次**。

> 累计：**20 项缺陷**（含 **4 项致命**）。其中 13 项由测试/仿真发现、3 项由代码复查发现、
> 1 项用户指出、1 项 PC 工具时序、1 项工具链（7.17）、1 项自动化测试假通过（同 7.17）。

### 7.19 对着 ADIv5 规范核对，抓出 SWD 引擎两个致命错误（第 15 轮）

用户提供了 ADIv5 规范（IHI0031H）、F4 参考手册（rm0090）、Cortex-M4 编程手册（PM0214）
和 Arm 的 DAPLink 源码，于是把 SWD 引擎里**每一个常量**都对着资料核了一遍，抓到：

**① `FLASH_CR.STRT` 位号写错（致命）**：我写成 bit15，**RM0090 §3.9.7 明确是 bit16**。
后果：擦除命令根本不会启动，而 `BSY` 一直是 0 → 固件会"以为擦好了"继续编程，
直到撞上 PGAERR 才报错。**上板后永远烧不进去**，且现象会指向错误的方向。

**② `CSW.AddrInc` 语义记反（致命，影响回读校验）**：我按"0b00=自增 / 0b01=不自增"实现，
而 **ADIv5 表 C2-1 是反的**：`0b00 = Auto-increment off`（TAR 不变）、
`0b01 = Increment single`（每次 DRW 访问后自增）。
后果：`SWD_MemReadBlock()`（回读校验用它）会**反复读同一个地址**，
校验必然失败；DAPLink 的 `CSW_VALUE` 也正是 0x23000052（含 `CSW_SADDRINC`），佐证了正确取值。

**为什么测试全绿却没发现**：仿真模型是我自己写的 `sim_ap_inc()`/`T_CR_STRT` 也写了同一套错值——
**模型与固件共享同一个错误概念，自证式仿真抓不出来**。这是本次最大的教训。

顺带修掉两处（非致命）：
**③ 清 sticky 用写 CTRL/STAT**：SW-DP 上该位是 RO/WI 清不掉，而且会把 `CDBGPWRUPREQ`
一起清成 0（等于撤掉调试电源请求）→ 改成规范的 `ABORT = 0x1E`。
**④ 写事务尾部多打一个 turnaround**：ADIv5 §B4.1.1 明确 WDATA 之后"没有额外 turnaround"→ 去掉，
每个写事务省 1 拍（实测 87855 → 86647 周期/KB）。

**防回归**：新增 27 项"规范自检"（常量按手册字面值钉死 + 两条 CSW 语义用例）。
实测（当轮数据，见附录 B）：spike 86 项、宿主回归 1209 项全过，Keil U1/U2 均 0 Error / 0 Warning。

### 7.20 四路串口 + U1↔U2 链路：4 个坑（第 16 轮）

**① `Link_RequestPoll` 的 `*outlen` 一身二职 → 静默拷 0 字节**（宿主单测暴露，API 设计错误）。
原来把 `*outlen` 同时当"入参=缓冲容量"和"出参=应答长度"。调用方按习惯传了 `0`，
于是 `memcpy` 长度被截成 0：**函数返回成功、长度也对，数据却一个字节没拷**，
测试里看到的是栈上的旧数据（一眼看去像"内容错位"，很容易误判成收发丢字节）。
→ 改成固定容量契约：`out` 必须 ≥ `LINK_MAX_PAYLOAD`，函数恒拷 `resp_len` 字节。
教训：**别让一个参数既做输入又做输出**，尤其别把"容量"藏在输出参数里。

**② HAL 的 ORE（溢出）分支会悄悄关掉接收**（设计阶段按 HAL 源码抓出，未上板）。
`stm32f1xx_hal_uart.c` 的 ORE 路径是"先 `UART_EndRxTransfer()` 关 RXNEIE/PEIE/EIE 并把
`RxState` 置 READY，**再**回调 `HAL_UART_ErrorCallback()`"。
若错误回调里不重新 `HAL_UART_Receive_IT()`，这一路从此**永远收不到字节且不报任何错**。
→ `UartPort_OnError()` 里重挂接收（驱动不变量），`uart_cfg.c` 里先清 ORE 再分发；
宿主测试 §5 专门模拟"HAL 停了接收"并断言重挂成功。

**③ 假 HAL 的 TxCplt 重入让驱动"看起来在丢数据"**（测试自身的缺陷，值得记一笔）。
推线是嵌套的（发送完成回调里立刻发起下一段，又回到推线），
于是同一段数据被回调了两次 TxCplt → 驱动的 `tx_tail` 多推一格 → 后续内容整体错位。
真 HAL 每次 `HAL_UART_Transmit_IT` 只回调一次，**是仿真器写错了**。
→ `sim_tx_done()` 加幂等保护。教训：**仿真器与真实现的语义差，会伪装成被测代码的 bug**。

**④ UV4 在受限环境下"0 Error 却不产出 `.o/.axf/.map`"**（环境坑）。
Keil 的 UV4 以子进程方式跑 armcc/armlink；当构建环境限制子进程写文件时，
UV4 仍打印 `0 Error(s), 0 Warning(s)` 与 "linking..."/"FromELF..."，
但磁盘上只有 `.lnp/.sct/.dep` 和日志，没有任何产物——**"编译通过"是假的**；
更坑的是它会**先删掉旧产物**再链接，于是"失败的构建"还会顺手毁掉上一次的好产物。
→ 判断构建是否真的发生：看 `MDK-ARM/<target>/<name>.map` 时间戳是否刷新（本工程已用此判据复核）。

### 7.21 三个模块在两片各一份副本 → 加了"副本必须一致"的机械检查（第 16 轮收尾）

`uart_port` / `uart_link` / `protocol_frame` 在两片各自的工程目录里各有一份副本
（**不搞公共目录**：每个工程自包含）。代价是"改一边忘一边"，而后果是**静默的**：
字段布局变了而对面还是旧的 → STATUS 解出垃圾；帧格式变了 → 一直 CRC 错/超时。

加了两道机械保护：

1. **回归脚本第 7 阶段**用 `fc /b` 逐字节比对这 6 个文件对，不一致就 `[FAIL]` 并让回归退出码为 1。
   已反证：故意把 U2 的 `uart_port.c` 改一个字节 → 该阶段打印 `uart_port.c : DIFFERENT` +
   `[FAIL]`、回归退出码 1；还原后恢复 `[PASS]`。
2. **`LINK_CODE_VER`**（`uart_link.h`）：改变链路对外行为的改动 +1，
   从机在 STATUS 里回这个值，主机每 5 次保活探测（≈2.5 s）比对一次，
   `APP_U2VerOk()` 直接给出"两片是否同一版代码"。
   宿主测试新增 11 项断言覆盖"同版本通过 / 旧版本被检出 / 空指针安全"。

两片各自的编译产物、烧录判据与副本规则写在 `docs/10_UART四路驱动设计.md` §10。

### 7.22 ④ 脉冲捕获：三个真问题（第 17 轮）

**① 占空比被"多一个高电平段"带偏**（算法错误，单测抓出）。
一开始用"高电平总和 / 总时间"算占空比。但相邻边沿的区间数＝边沿数−1（奇数），
高、低两组的样本数会差 1 → 20kHz/50% 会算成 **34.7%**。
→ 改成**高、低各自取平均再合成**：`duty = avg_high / (avg_high + avg_low)`。
教训：**比值类统计必须先保证两边的样本数可比**。

**② 毛刺/丢沿会把平均值污染，但离群剔除不能"一刀切"**。
用中位数剔除异常区间是对的，但**必须按高、低两组各自取中位数**：占空比 10% 时高电平段
天生比低电平段短得多，用全体中位数当基准会把正常的高电平段全当异常丢掉（单测覆盖）。
现在的规则：偏离本组中位数 1/2~3/2 之外就丢，并置 `PULSE_F_DIRTY`。

**③ `mode=0` 只读应答被截断成 77 字节**（真 bug，全链路单测抓出）。
应答布局从 77B 扩到 167B 后，`APP_MeasCmd` 的只读分支仍然写死了旧长度
`APP_SendAck(cmd, s_meas_resp, MEAS_PACK_RESP_LEN)` → PC 会按 77B 解析、后面两段脉冲
读不到。→ 改成用打包函数的**实际返回长度**。
教训：**"别人返回的长度"永远不要用常量替代**，否则扩布局时一定漏一处。

另外顺手修掉一个**硬件隐患**：`tim.c` 原来把 TIM4（PB6/7/8）等配成 PWM 推挽输出，
经 3kΩ 会把被测板的三相输出节点拉低（连带相电压 ADC 读数偏低），等于跟被测板对打。
→ 改成输入捕获 + 引脚输入（含下拉），再生成须知写在 `docs/05` §2.5。

### 7.17 烧录方案换成 SWD：三处踩点（第 14 轮）

1. **`test/run_all_tests.cmd` 被改成 LF 换行 → cmd.exe 解析错乱**（严重：**假通过**）。
   `edit` 工具写回文件时用了 LF，cmd.exe 对 LF-only 的 .cmd 会把命令切碎执行，
   结果是所有测试**都没跑**，却打印出 `===== host tests: ALL PASS =====`。
   → 修法：把 .cmd 文件强制转回 CRLF；并在文档里记下这条教训
   （**改完 .cmd 必须检查换行**，否则会得到"看起来全绿"的假结果）。
2. **分区大小算错**（`DUT_APP_SIZE` 写成 0x78000，正确是 `0x100000-0x8000 = 0xF8000`）。
   被 `flash_map.h` 新加的编译期断言 `dut_app_must_end_at_flash_end` 在**编译期**拦下
   ——这正是当初加那批静态断言的目的。
3. **`0x000D` 的语义变化**：UART 时代读不到就回 `ERR_TIMEOUT`；
   SWD 能直接读到目标 Flash，于是"读得到但全 0xFF（App 区为空）"应回
   `ERR_NO_FW(0x06)` 而不是 `OK`＋`0xFF 0xFF 0xFF`。全链路测试相应更新。

### 7.18 SWD 引擎：模型与主机约定不一致导致的"假失败"（第 13 轮 spike）

spike 第一次跑起来时**第二批事务全部 NO_ACK**、总线冲突 118 次。
根因不是协议写错，而是**包同步规则不严谨**：模型早期用"8 位滑动窗口匹配请求头"，
窗口里残留着**上一个包头**的比特，导致在真包头之前 5 位就误判成包头。
→ 改成按 ADIv5 的做法：**空闲电平为低、Start 位(1) 的上升沿标记包头**
（并在主机侧补一个 spec 允许的空闲周期，让上升沿一定出现）。
修好后 59 项断言全过、冲突与奇偶错都为 0。

### A.1 ISP 实现要点（源码已删除，仅备查）

- **协议**：AN3155 系统 bootloader。`0x7F` 同步 → 读版本 `0x01` → 全片擦除 → 逐 256B 块写 `0x31`
  → （可选）回读 `0x11` → 跳转 `0x21`。
- **擦除**：`0x43`/`0x44` 运行时自适应（按读回的 bootloader 版本决定先试哪个），载荷 `FF FF 00`。
- **写内存**：长度字节 `N-1` + 数据 + 校验和（`N-1` 与全部数据字节的 XOR）；
  **长度统一补齐到 8 字节**——8 是 4 的倍数，同时满足 F1(4) 与 G0(8) 的对齐要求，**无需知道被烧板型号**。
  仿真器按这两套规则各跑一遍均为零对齐违规（用例 T7b）。
- **串口**：ISP 期间 8E1（bootloader 要求），Go 之后切回 8N1（应用运行态）；
  **失败路径同样切回 8N1 并放开 BOOT0**（见 §7.11）。
- **非阻塞**：`ISP_Step()` 每次只推进一步（一次握手 / 擦除 / 一个 256B 块 / 一次回读），不长时间独占主循环。
- **回读校验**（`ISP_VERIFY_ENABLED`，**默认关闭**）：每写完一段逐 256B 回读与源镜像 `memcmp`，
  不一致报 `ERR_PROG` 且不执行 Go。
  > 默认关闭的原因：回读时序在不同 bootloader 版本上略有差异，**格式若与实际器件不符，
  > 一次成功的烧录也会被判为 ERR_PROG**。bring-up 确认可用后再打开（改一个宏）。
  > 已用 armcc 单独验证该分支在**目标编译器**下也能干净编译。
- **调试日志**：关键节点打到 USART1（PA9/PA10，4P 排针）115200 8N1：
  `[ISP] target BL ver=0x??` / `sync FAIL` / `erase FAIL` / `image head invalid, ABORT before erase` / `verify: DATA MISMATCH`。

### A.2 参考测径治具核对了什么（ISP 时代的 BOOT0/RESET 做法）

`diameter_JIG/U1/U1project/Core/Inc/isp_programmer.h`：

```c
#define U4_BOOT0_HIGH()  HAL_GPIO_WritePin(GPIOA, GPIO_PIN_8,  GPIO_PIN_SET)
#define U4_BOOT0_LOW()   HAL_GPIO_WritePin(GPIOA, GPIO_PIN_8,  GPIO_PIN_RESET)
#define U4_RESET_HIGH()  HAL_GPIO_WritePin(GPIOB, GPIO_PIN_15, GPIO_PIN_SET)
#define U4_RESET_LOW()   HAL_GPIO_WritePin(GPIOB, GPIO_PIN_15, GPIO_PIN_RESET)
```

进 bootloader 时序：

```
BOOT0 = H  →  RESET 拉低  →  10ms  →  RESET 拉高  →  50ms  →  发 0x7F  →  等 ACK
```

**本工程的 `ISP_ST_CONNECT()` 与之一致**，无需改动。两点差异是**刻意**的：

1. 测径治具用 PA8/PB15；本板 PA8 = TIM1_CH1、PB15 = SPI2_MOSI（接 U10），**已被占用**，
   故改用同样空闲的 **PB1 / PC13**；
2. 本工程在 Go 之后把 BOOT0 拉回低电平（参考实现保持高电平），这样被烧板下次上电能从应用正常启动。

### A.3 一键烧录流程（ISP 时代；现在的一键烧录走 SWD，见 docs/09）

```
python tools/foc_jig_tool.py -p COM5 burn --boot bl.bin --app app.bin -v 1.0.0
```

```
[1/4] 上传 Bootloader → Slot0
[2/4] 上传 App → Slot1（自动切槽）
[3/4] 回读治具 Flash 校验版本号
[4/4] 0x0112 烧录到被烧板（烧完才回 ACK）
★ 烧录完成 OK
```

任一步失败即中止，并给出该步的排查提示。
