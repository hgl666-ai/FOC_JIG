# 23 一页纸：五项测试要测什么数据 + FOC 方怎么配合

> 给内部/对方对齐用。协议细节见 `docs/22_FOC固件对接要求_v1.2.docx`；台架操作见 `docs/21`。
> **一台治具、一份固件**：烧录（SWD 两线）+ 下面五项测试全在其中。

## 一、要测的数据（治具测什么 / FOC 板报什么 / 判据）

| # | 测试项 | 治具这侧测到的原始数据 | FOC 板要报的 | 当前固件判据 |
|---|---|---|---|---|
| ① | **电压检测** | 9 路模拟量 mV：<br>24V 母线 / 10V 驱动 / 5V / 3.3V / A·B·C 相电压 / 电流检测1·2 | **同样这 9 路** mV<br>（自己 ADC 换算，按“信号侧”） | 逐路比：\|治具−板子\| ≤ max(板子×5%, **200 mV**) |
| ② | **MCU 脉冲** | 3 路 PWM 的 **周期 / 高电平 / 占空比 / 边沿数**（治具定时器捕获） | —（只需按命令输出 1 kHz / 50%） | 周期 ≈ 1 ms、占空比 ≈ 500‰、**三路边沿数都 > 0** |
| ③ | **三相输出** | 3 路**相电压** mV（治具 140k/20k 分压，k=0.125） | —（同上 PWM） | 实测 ≈ **占空比 × 母线电压**；容差 max(母线×5%, **300 mV**) |
| ④ | **编码器** | 治具**发出**的 A/B/Z 脉冲数（A=1000、B=2000、Z=1，故意不同） | 它**数到的** A/B/Z 边沿数 + 方向 | 期望边沿 = 脉冲 × 2（**A=2000 / B=4000 / Z=2**）；偏差默认 0 |
| ⑤ | **相电流** | 两路电流检测 mV：**通流前 / 通流中** | 同上两路 mV：通流前 / 通流中 | 变化量 > **50 mV** 才算“有电流”；两边变化量互差 ≤ max(5%, **30 mV**) |

补充：
- **母线电压**（≈24 V）来自 ①，是 ③ 的判据输入 —— 所以 ① 不过，③ 就别看。
- ② 和 ③ **共用同一次 PWM 输出**（一次窗口采两样）。
- ① 和 ⑤ **共用 GET_ADC**，只是问的通道不同（0~6 是电压，7/8 是电流）。
- 判据的容差都是当前固件默认值，标定后可改（`vol_chk.h` / `phase_chk.h` / `cur_chk.h` 顶部宏）。

## 二、FOC 方要配合的

### A. 固件要实现（必须）

| # | 内容 |
|---|---|
| 1 | **9 条命令** `0x0200~0x0208`；其中 **PING / INFO / TEST_MODE / STOP 必做**，其余按能力在 INFO 里声明 |
| 2 | **测试模式**（`0x0202`）：进入时按序 **关三相输出 → 停控制环 → 清编码器计数 → 复位看门狗 → 回 OK**；幂等 |
| 3 | **失联看门狗**：`wdt_ms` 200~10000，**每收到一帧就重置**，超时立刻关输出；**不允许关掉** |
| 4 | **幂等**：超时后台会用同一 `SEQ` 重发一次，重复请求只回 OK、不重复执行动作 |
| 5 | `GET_ADC` 的 `mv` 必须是**信号侧**（相电压分压比 k=0.125，报“ADC 引脚电压”会差 8 倍） |
| 6 | `GET_ENC` 数的是**两种沿**（一个方波 = 2 个边沿），测试模式进入时清零、之后只增不减 |

### B. 参数要给我们（不然测出来的数没法用）

| # | 要什么 | 用在哪 |
|---|---|---|
| 1 | **UART 是哪一路、哪两个引脚、波特率** | 治具 USART3 现在固定 **115200**；不是这个数就得改 |
| 2 | **相电流量程**：采样电阻 / 放大倍数 / 基准，满量程对应多少安 | 现在只能比 mV，要换成安培必须有这个 |
| 3 | **编码器接口形式 + 高电平门限** | 治具输出是 3.3 V 推挽；若对方是 5 V 逻辑门限 3.5 V，治具要改开漏 |
| 4 | `GET_ADC` 的 `mv` 参考点（是否已折回分压前） | 不统一两边数字对不上 |
| 5 | 烧完固件后**会不会自动驱动电机** | 是的话测试流程要先按住它 |
| 6 | `AS:S800` / `AS:S0` 是否需要 **`\r\n` 结尾**、大小写是否敏感 | 现在正卡在这（见下） |

### C. 硬件要留

| # | 要留什么 |
|---|---|
| 1 | **SWD 两脚 PA13 / PA14**（治具烧录用，别复用成别的功能） |
| 2 | **USART 三根线**：治具 PB10(TX) → 板子 RX；PB11(RX) → 板子 TX；**共地** |
| 3 | **编码器 A/B/Z 测试点**（治具要往上打脉冲） |
| 4 | **三相输出 + 电流检测的测试点**（治具要量相电压和电流 mV） |

## 三、现在卡在哪（2026-11-07）

FOC 固件还没实现 `0x02xx`，所以先走**过渡路径**验通路：

```
PC ──USART1(115200)── 治具 ──0x001F 透传──USART3(115200)── FOC 板
                                    发它自己的 ASCII 命令 AS:S800 / AS:S0
```

**要对方回答两件事就能继续：**

1. **FOC 板那路 UART 的波特率是多少？**（治具固定 115200；不是就加一条“改波特率/自动扫波特率”的命令）
2. **`AS:S800` 需要 `\r\n` 结尾吗？大小写敏感吗？**

自测顺序（不需要对方在场）：

| 步 | 做 | 看到什么算过 |
|---|---|---|
| 1 | 拔掉 FOC 两根线，**短接治具 PB10/PB11**，`as-start --eol crlf` | `✅ 双向都通：对端回了 9 字节`，内容就是 `AS:S800\r\n` → 治具 USART3 没问题 |
| 2 | 恢复接线，再发 | `收到 N 字节` 且电机转 → 整条路径通了 |
| 3 | 只 `收到 0 字节` 且电机不转 | 查波特率 / TX-RX 是否交叉 / 共地 / 是否需要 `\r\n` |
