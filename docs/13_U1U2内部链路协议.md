# 13 U1 ↔ U2 内部链路协议（规范）

> 版本：**链路代码版本 `LINK_CODE_VER = 0x0104`**（v1.4 新增 `0x0109` ENC_XCHK；v1.3 是 `0x0103`）
> 状态：**规范已定稿，代码待实现**（实现清单见 §10）
> 适用链路：U1 的 USART3（PB10/PB11）↔ U2 的 USART3，115200 8N1
> 与 PC 协议的关系：**帧格式、序号规则、状态码表全部沿用** `INFO/M1 测试治具PC端通讯协议.xlsx`；
> 本文只额外定义"内部专用命令码段"和少数内部语义。
> 相关文档：`docs/10`（四路串口驱动）、`docs/07`（ADC 测量）、`docs/12`（脉冲捕获）

---

## 0. 一句话

U1 是主机、U2 是从机：**U1 问一句，U2 答一句**。本次在原有 4 条命令上补 4 条，解决三件事：

| 要解决的问题 | 用什么解决 |
|---|---|
| 两端采的不是同一段时间（交叉校验可能拿错窗口） | `0x0105` **ARM**：U1 喊"开始"，两端同时开窗 |
| 链路偶发断了只能干等 | `0x0106` **LINK_RESET** + 重传 + 半截帧超时 |
| U2 自己出问题（ADC 饱和、边沿丢、缓冲溢出）U1 不知道 | `0x0107` **EVENT**（U2 主动喊）+ `0x0108` **EVENT_GET**（U1 可靠补拉） |

## 1. 角色与物理层

| 项 | 值 |
|---|---|
| 物理链路 | U1 的 USART3（PB10=TX / PB11=RX）↔ U2 的 USART3，**必须交叉跳线（TX↔RX）且共地** |
| 参数 | 115200，8 数据位，无校验，1 停止位，无硬件流控（两片必须一致） |
| 角色 | **U1 = 主机**（唯一发起方）；**U2 = 从机**（只应答 + 主动发事件帧） |
| 并发 | U1 **一次只允许一条请求在飞**；忙时新请求直接被拒（不排队） |
| 优先级 | 串口中断优先级 3，低于 USB(0)、高于捕获(4) |

**U2 只会发两类帧**：
1. **ACK 应答**：`N = 收到的请求的 N`（与 PC 协议的 ACK 规则一致）；
2. **主动事件帧**：`N = 0`（与 PC 协议里"治具主动发的帧序号一律为 0"同一手法）。

## 2. 帧格式（与 PC 协议同一套）

| 字段 | 帧头 F | 命令 C | 帧序号 N | 数据长度 L | 数据 D | CRC16 |
|---|---|---|---|---|---|---|
| 字节数 | 2 | 2 | 2 | 2 | * | 2 |
| 取值 | `A5 5B` | uint16 | uint16 | uint16 | * | uint16 |

```
偏移   0    1     2      3      4      5      6      7     8 .. 8+L-1   8+L   9+L
     A5   5B   CMD_H  CMD_L  SEQ_H  SEQ_L  LEN_H  LEN_L   DATA...       CRC_H  CRC_L
```

**与 PC 协议完全一致的四个点（这是"格式一致"的实质）**

| 点 | 规则 |
|---|---|
| 字节序 | 所有多字节字段**大端**（高字节在前） |
| CRC16 | MODBUS（poly 0xA001 反射，init 0xFFFF），计算范围 = **帧头到数据 D 的最后一个字节**，CRC 本身大端存放 |
| 帧序号 N | 从 1 递增、`0xFFFF` 回卷；**0 专供"主动帧"**（U2→U1 的事件） |
| ACK | 应答帧的 N **等于**请求帧的 N；U1 只采纳"当前在等的那一发"的应答，其余计入 `rx_stale` 丢弃 |

**只有命令码段是内部专用的**：

| 码段 | 归属 | 说明 |
|---|---|---|
| `0x0009 ~ 0x0112` | PC ↔ U1 | xlsx 已定义 8 条，与本文无关 |
| **`0x0100 ~ 0x01FF`** | **U1 ↔ U2** | 本文定义 |

> 为什么不复用 PC 的命令码：U1 的两个串口各自独立解析，码段分开才不会撞车；
> 而**格式、序号规则、状态码表全部沿用** PC 那套，所以对使用者来说"格式一致"。

### 2.1 实际帧样例（可直接当对照用例）

```
── 请求（U1 → U2） ──────────────────────────────────────────────
PING       0x0100 N=1 LEN=0   A5 5B 01 00 00 01 00 00 98 30

MEAS_XCHK  0x0103 N=3 LEN=55  A5 5B 01 03 00 03 00 37 <55B 快照> <CRC>
PULSE_XCHK 0x0104 N=4 LEN=45  A5 5B 01 04 00 04 00 2D <45B 脉冲> <CRC>

                              00 01 01 03 00 2A 00 00 12 34 00 00 00 00
                              00 00 30 39 00 00 00 00 00 7F 00 00 00 00 30 4D
```

## 3. 通用规则

### 3.1 序号 N

- U1 每次发起请求 `N++`（从 1 开始，0 不用，回卷跳过 0）。
- U2 应答 `N = 请求的 N`。
- U1 收到 `N` 与 `wait_seq` 不同的**应答类**帧 → 计入 `rx_stale` 丢弃（迟到的旧应答不会污染下一次请求）。
- U2 主动事件帧 `N = 0`，**不需要应答**（可靠性由 §5.7 的补拉保证）。U1 对它的处理是特殊分支：
  `N == 0 且 CMD == 0x0107` → 当作事件收下（**不计入 `rx_stale`**）；U1 正等应答时收到它也不受影响（N 不同，不会误配）。
- **U2 的发事件时机**：只在"手上没有待处理的请求"时发（即上一次应答已经发完之后）。U2 不会在应答中途插事件帧，所以 U1 侧不会出现帧内交错。

### 3.2 状态码（直接用 PC 那张表）

应答数据区的**第 1 字节**是状态码（`PING` 除外，它的数据区是回环内容；`EVENT` 除外，它没有状态码）。
本协议用到下面 6 个，**取值与含义和 PC 协议完全一致**：

| 码 | 名称 | 本协议里的用法 |
|---|---|---|
| `00` | OK | 正常 |
| `01` | BUSY | U2 正在采集窗口内，不接受新 ARM；或上一次请求还没收尾 |
| `05` | ERR_TEST | U2 自检失败 / 本次采集结果判定不可用（`EVENT` 里有细节） |
| `0B` | ERR_PARAM | 长度不对、session=0、window_ms 越界、flags 保留位非 0 |
| `0C` | ERR_TIMEOUT | U2 内部等超时（如窗口已过、结果还没就绪） |
| `FF` | NIY | 命令未实现（**必须回，不能静默丢弃** —— 这样 U1 才能区分"U2 不在"和"U2 在但这条没实现"） |

### 3.3 超时

| 类别 | 命令 | 等应答上限 |
|---|---|---|
| 控制类 | PING / STATUS / LINK_RESET / EVENT_GET | **50 ms** |
| 数据类 | MEAS_XCHK / PULSE_XCHK | **300 ms** |
| 触发类 | ARM | **50 ms**（ARM 只登记并开窗，不等窗口结束） |

> ARM 的应答必须"收到就回"，**不能等窗口跑完**——否则 U1 的空闲窗口会被对侧拖长。

### 3.4 重传与幂等

| 规则 | 内容 |
|---|---|
| 重传范围 | 全部命令都允许重传（本协议的命令**都是幂等的**） |
| 重传次数 | 最多 **1 次**；重传**沿用同一个 N** |
| 幂等实现 | U2 保存"最近一次请求的 `N` + 命令码 + 应答内容"；收到 `N` 与命令码都相同的请求 → **直接重发缓存的应答，不重新执行** |
| 缓存失效 | 新的 `N` 到来时覆盖缓存；`LINK_RESET` 也清缓存 |
| 为什么必须这样 | 否则 ARM 一重传就会**重开窗口**，两端窗口就错位了 |

### 3.5 半截帧（本次新增）

- 每个字节记录到达时刻（`HAL_GetTick`）。
- `Link_Poll` 里检查：**若 `rx_cnt > 0` 且"距最后一个字节 > 5 ms"** → 判为断帧，丢弃已收字节、复位到"找帧头"，`rx_half` 计数 +1。
- 作用：对端发到一半掉线时，不会让那截字节一直挂着污染下一帧。

### 3.6 断链恢复（本次新增）

**触发**：U1 侧连续 **3 次**请求超时（`tx_timeout` 连续计数 ≥3）。

**动作**（只在 `app_state == IDLE` 时执行；测试/烧录进行中只累计计数、不打断流程）：

```
① U1 发 LINK_RESET（等 50ms）
② 无论成败：U1 清自己的收发环 + 复位链路会话（半截帧/等待状态）
③ 连续失败计数清零；若本次 RESET 也失败 → 进入退避：每 5 s 再试一次（不刷屏）
```

**U2 收到 LINK_RESET 时**：清收发环、复位会话（半截帧、幂等缓存、ARM 状态与结果）、重挂接收。
**事件表不清**（事件是故障证据），**统计不清**（诊断证据），只清"会话态"。

### 3.7 长度约定

- 单帧 DATA 上限 `LINK_MAX_PAYLOAD = 64 B`（含本协议所有载荷；最大的是 MEAS_XCHK 的 55 B）。
- 收到 `LEN > 64` → 判为非法帧，**丢弃并重同步**（`rx_len_err` 计数），不回状态码。

## 5. 各命令逐字节布局

### 5.1 `0x0100` PING

| 方向 | 数据区 |
|---|---|
| 请求 | 任意 0~64 B（保活用 0 B） |
| 应答 | **原样回显**请求数据区（没有状态码字节） |

用途：保活（U1 每 500 ms 一发）。**无需幂等特殊处理**（本来就无副作用）。

### 5.2 `0x0101` STATUS

请求数据区：空（0 B）。应答数据区 **28 B**：

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `ver_major` | U2 固件主版本 |
| 1 | 1 | `ver_minor` | U2 固件次版本 |
| 2 | 2 | `code_ver` | U2 的 `LINK_CODE_VER`（u16 大端）→ U1 用 `Link_CheckVersion()` 比对 |
| 4 | 2 | `alive` | 存活计数（U2 每应答一次 +1，u16 回卷） |
| 6 | 4 | `rx_frames` | U2 链路统计：收到的合法帧数 |
| 10 | 4 | `rx_crc_err` | CRC 错帧数 |
| 14 | 4 | `rx_bytes` | U2 该端口收到的字节数 |
| 18 | 4 | `rx_drop` | U2 该端口丢字节数 |
| **22** | **2** | **`caps`** | **能力位图（本次新增，见 §7.2）** |
| **24** | **2** | **`ev_pending`** | **待决事件位图：bit i = 事件码 (i+1) 有待决事件** |
| **26** | **2** | **`ev_overflow`** | 被丢弃的事件条数（u16 饱和） |

> 布局变化：22 B → **28 B**，这正是 `LINK_CODE_VER` 必须 +1 的原因。
> 老主机（只知道 22 B）遇到 28 B 会因 `LEN` 不匹配而判定版本不一致 → 提示重烧，不会解出垃圾。

### 5.3 `0x0103` MEAS_XCHK

| 方向 | 数据区 |
|---|---|
| 请求 | U1 的 **55 B 电压快照**（布局见 `docs/07` §3 / `meas_pack.h`） |
| 应答 | U2 的 **55 B 电压快照**（同一布局） |

快照 55 B：`flags(1) + ch_count(1) + round(2) + dt_ms(2) + vdda_mv(2) + cfg_crc(2) + 9 × [raw(2) + mv(2) + flags(1)]`
（无状态码字节；比对逻辑在 U1 侧完成 —— U2 不做判定。）

### 5.4 `0x0104` PULSE_XCHK

| 方向 | 数据区 |
|---|---|
| 请求 | U1 的 **45 B 脉冲结果**（布局见 `docs/12` §6 / `pulse_pack.h`） |
| 应答 | U2 的 **45 B 脉冲结果**（同一布局） |

> ⚠ **2026-10 更正**：原写"U1 测电机输出端 / U2 测主控驱动输入端"，**是错的** ——
> `MA0_OUT` 组在硬件上只有 ADC 通路、没有定时器通路。两片采的是**同一组信号**
> （`MA_IN/MB_IN/MC_IN`，接在两片的 PB5/PB4/PA8 上），用途是**冗余互比**，不是"同一相两端"。
> 详见 `docs/00` §3.5 与 `docs/12` §1/§10。**代码尚未改。**

45 B：`ver(1) + flags(1) + window_ms(2) + phase_count(1) + rsvd(1) + 3相 × 13B`
每相 13 B：`period_ns(4) + high_ns(4) + duty_permille(2) + edges(2) + flags(1)`。

### 5.5 `0x0105` ARM —— 同步触发（本次新增）

**请求数据区（5 B）**

| 偏移 | 长度 | 字段 | 取值与约束 |
|---|---|---|---|
| 0 | 2 | `session` | u16 大端，**从 1 开始递增**；0 → `0B ERR_PARAM`（0 保留，不用于真实触发） |
| 2 | 2 | `window_ms` | 采集窗口，**1 ~ 1000**；越界 → `0B ERR_PARAM`（当前用 200） |
| 4 | 1 | `flags` | bit0 = 要求硬件同步触发（**预留，当前必须为 0**）；其余位保留 = 0；非 0 → `0B ERR_PARAM` |

**应答数据区（3 B）**

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `status` | `00 OK` / `01 BUSY`（窗口正在跑）/ `0B ERR_PARAM` / `FF NIY` |
| 1 | 2 | `session` | 回显请求的 session（U1 用来确认这不是陈旧应答） |

**U2 侧状态与语义**

```
IDLE ──ARM(session 新)──▶ ARMED（窗口进行中，window_ms 计时）
ARMED ──窗口结束──────▶ READY（结果就绪，等 U1 来取）
READY ──ARM(session 新)──▶ ARMED（覆盖上一个结果）
READY/IDLE ──MEAS/PULSE_XCHK──▶ 只读结果，状态不变
任意 ──LINK_RESET──▶ IDLE（结果丢弃）
```

| 情况 | U2 行为 |
|---|---|
| `IDLE` / `READY` 收到新 session 的 ARM | 立刻开窗（**同一主循环轮次内**）→ 回 `00 OK` |
| `ARMED` 收到 ARM | 回 `01 BUSY`（不打断当前窗口、不排队） |
| 收到**与上次相同** session 的 ARM（重传） | 幂等：回当前状态，**不重开窗**（靠 §3.4 缓存） |
| 结果被 `XCHK` 取走后 | 结果**保留**（可重复取，便于 U1 重试），直到被下一个 ARM 覆盖或 `LINK_RESET` |
| 窗口期间"没信号" | **照常回 OK**，无信号由 45 B/55 B 里的 flags 表达（U1 判，U2 不判） |

**U1 侧动作**

```
发 ARM →（发送队列排空后）立刻开自己的窗口
      → 等自己窗口结束 → 取本片结果
      → MEAS_XCHK / PULSE_XCHK 取 U2 结果（现在是同一段时间的）
      → 比对判定
```

**两端窗口错位** = U2 收到帧的时间 − U1 开窗时间 ≈ 帧传输时间(0.87 ms) + U2 主循环延迟(≪1 ms) → **< 2 ms**。
窗口 200 ms 时两端重叠 >99%，对"周期/占空比"读数没有影响（两边测的都是稳态波形）。

> 若将来要测**两端相位差**或把窗口缩到几毫秒级，再用 `flags.bit0` 走 PB9↔PA11 硬连线触发 —— **协议不用改**。

### 5.6 `0x0106` LINK_RESET（本次新增）

| 方向 | 数据区 |
|---|---|
| 请求 | 空 |
| 应答 | 1 B 状态码（`00 OK`） |

U2 收到后：清收发环 → 复位会话（半截帧计数、幂等缓存、ARM 状态与结果）→ 重挂接收 → 回 `00 OK`。
**事件表与统计不清**。U1 收到应答后做同样的事（清自己的环与会话）。

### 5.7 `0x0107` EVENT —— U2 主动上报（本次新增）

- **方向 U2 → U1，帧序号 N = 0**，不需要应答。
- 数据区 **8 B**：

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `ev_code` | 事件码（见下表） |
| 1 | 1 | `sev` | 严重度：0=info 1=warn 2=error |
| 2 | 2 | `arg0` | 事件参数（随事件码） |
| 4 | 2 | `arg1` | 事件参数（随事件码） |
| 6 | 2 | `count` | 该事件**累计**发生次数（u16 饱和） |

**事件码表**

| 码 | 含义 | `arg0` | `arg1` | 严重度 |
|---|---|---|---|---|
| `0x01` | ADC 某通道饱和/贴边 | 通道号（0..8） | 原始码值 | warn |
| `0x02` | 采集被截断/DMA 轮次丢失 | 累计次数 | 0 | warn |
| `0x03` | 参考电压异常（VDDA 越界） | VDDA(mV) | 0 | error |
| `0x04` | 捕获窗口无效（三相都没结果） | 相位掩码 | 0 | warn |
| `0x05` | 捕获边沿被丢弃（毛刺过多） | 累计丢弃数 | 0 | info |
| `0x06` | 收到不认识的命令 | 命令码 | 次数 | info |
| `0x07` | 内部自检失败 | 检查项号 | 0 | error |
| `0x08` | 事件队列/缓冲溢出 | 被丢弃事件数 | 0 | error |

**可靠性设计（关键）**：事件**当"状态"用，不当"消息"用**：

1. U2 侧对每个事件码维护"置位 + 参数 + 累计次数"（`ev_pending` 位图见 §5.2 偏移 24）；
2. 事件发生时 U2 **立刻**发一帧 `EVENT`（快路径，~1 ms 到 U1）；
3. U1 在每 2.5 s 的 STATUS 里看到 `ev_pending != 0` → 用 `EVENT_GET` **可靠补拉**（慢路径）；
4. 所以 EVENT 帧丢了也不会丢事件 —— 只是晚 2.5 s 知道。

### 5.8 `0x0108` EVENT_GET（本次新增）

| 方向 | 数据区 |
|---|---|
| 请求 | 空 |
| 应答 | **9 B** |

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | `status` | 恒为 `00 OK`（命令本身执行成功）；**"有没有事件"由下一个字节的 `ev_code` 表达** |
| 1 | 1 | `ev_code` | 取到的事件码；**0 = 当前没有待决事件** |
| 2 | 1 | `sev` | 严重度 |
| 3 | 2 | `arg0` | 参数 |
| 5 | 2 | `arg1` | 参数 |
| 7 | 2 | `count` | 该事件累计次数 |

**取即清**：返回后 U2 把该事件码的 `ev_pending` 位清掉（参数与累计次数保留，供下一次再发生时继续累加）。
U1 每次只取一条，`ev_pending` 还有位置位就再取一次（主循环里慢慢取，不阻塞）。

### 5.10 `0x0109` ENC_XCHK（v1.4 新增）

**用途**：任务 ⑤ 编码器检测的**回环采集** —— U1 从 CN2 的 A/B/Z 发定量脉冲串，
U2 数一遍这三根线上的边沿回来，证明"信号真的到线上了"。

| 方向 | 数据区 |
|---|---|
| 请求 | 1 B **动作**：`0` = 清零计数器（发脉冲之前调）；`1` = 读取（发完之后调） |
| 应答 | 清零：1 B 状态码；读取：**15 B** = `status(1) + cnt_a(4) + cnt_b(4) + cnt_z(4) + lost(2)` |

- 计数语义：**数边沿**（上升 + 下降都算），所以 **1 个完整脉冲 = 2 个边沿**，
  和 DUT 侧的 `DUT_GET_ENC`（`docs/15` §7.9）对齐。
- `lost`：捕获中断里发现"标志清完立刻又置位"的次数（边沿比中断还快）。
  正常恒为 0；上板看到非 0 说明可能数漏了，要查中断负载。
- 非法动作 / 长度不对 → 回 `0B ERR_PARAM`。

**为什么不用 `PULSE_XCHK`（0x0104）**：`pulse_cap.c` 是**单例**，而 U2 的滚动窗口
一直在采 MA_IN 组。编码器采集只需要"个数"，所以 U2 用了一套**独立计数器**
（`enc_cap.c`，TIM4 输入捕获），于是两组可以**同时采** ——
不需要"采集源切换"，也不用改 ARM 的语义。代价是只给边沿数、不给周期/占空比（⑤ 不需要）。

> ⚠ **两片不能同时驱动 CN2 的三根线**：U1 发的时候 PB6/PB7/PB8 是 AF 推挽输出，
> U2 那边必须保持输入。U1 发完 `EncGen_Stop()` 会把脚收回输入态（见 `docs/12` §2）。

### 5.9 预留

- `0x0102`：预留给"U2 主动取数"类命令（当前不需要）。
- `0x0109 ~ 0x01FF`：未分配。收到未分配命令 → 回 `FF NIY`（并计一次 `0x06` 事件）。

## 6. 时序

### 6.1 保活（现状不变）

```
U1                                    U2
 │  每 500 ms：PING ─────────────────▶ │ 原样回显
 │  ◀────────────────────────── PING  │
 │  每 5 次 PING（≈2.5 s）改发 STATUS ─▶ │ 打包 28B 状态
 │  ◀──────────────────────── STATUS  │
 │  → APP_U2Alive()=1；比对 code_ver → APP_U2VerOk()
 │  → 看 ev_pending：非 0 就 EVENT_GET 取一条
```

### 6.2 一次完整测量（PC 的 `0x000E` / `0x000F`）—— **改成两端同窗**

```
PC            U1                                  U2
 │ 0x000F ──▶ │
 │            │ ① 等本片电压稳定
 │            │ ② ARM(session=N, 200ms) ─────────▶ │ 收到即开窗（同一轮次）
 │            │ ◀──────────────────── ARM OK      │
 │            │ ③ 本片开窗（错位 <2 ms）
 │            │    ……两端各采 200 ms……
 │            │ ④ 本片出结果
 │            │ ⑤ MEAS_XCHK(55B) ──────────────▶ │ 只读，不改状态
 │            │ ◀───────────────── MEAS_XCHK 55B │
 │            │ ⑥ PULSE_XCHK(45B) ─────────────▶ │
 │            │ ◀──────────────── PULSE_XCHK 45B │
 │            │ ⑦ 比对 → 判定
 │ ◀─ 应答 ─── │
```

要点：
- **ARM 的应答不等窗口**（§3.3），所以步骤 ② 只花 ~1 ms 就回来了；
- **ARM 失败（超时 / `01 BUSY` / `FF NIY`）时 U1 不开窗**，本次测量按"对侧缺席"处理：
  继续采本片、交叉校验块置 `NO_PEER`；调试模式（`MEAS_CC_REQUIRED=0`）仍回 `00 OK`，生产模式判 `05 ERR_TEST`；
- 两端窗口现在覆盖同一段时间 → 交叉校验不再比"两段不同的波形"；
- `session` 每次测量 +1，U1 在应答里核对回显，防止把陈旧应答当本次结果。

### 6.3 断链恢复（§3.6 的时序）

```
U1                                    U2
 │ 请求 ────────────────────────────▶ │  ✗（线松了/对端忙）
 │ ✗ 超时 #1                          │
 │ 请求（同 N 重传）─────────────────▶ │  ✗
 │ ✗ 超时 #2                          │
 │ 请求 ────────────────────────────▶ │  ✗
 │ ✗ 超时 #3  → 触发恢复              │
 │ LINK_RESET ──────────────────────▶ │ 清环+复位会话
 │ ◀────────────────── LINK_RESET OK  │
 │ 清自己的环与会话，失败计数清零       │
 │ （若 RESET 也失败：每 5 s 退避重试）│
```

### 6.4 事件上报的两条路径

```
快路径：U2 检测到异常 ──立刻发 EVENT(N=0)──▶ U1 记入自己的事件表 → 日志/上报 PC
慢路径：U1 每 2.5 s 的 STATUS 里 ev_pending≠0 ──EVENT_GET──▶ 取一条并清位
        （EVENT 帧丢了也能拿到，只是晚 ≤2.5 s）
```

## 7. 版本与能力协商

### 7.1 `LINK_CODE_VER`

- 当前：`0x0102` → **本次改为 `0x0103`**。
- 规则不变（`uart_link.h` 里写着）：**任何改变链路对外行为（帧格式 / 字段布局 / 时序）的改动都必须 +1，两片一起重编重烧**。
- U1 比对方式：STATUS 的 `code_ver` ↔ 本片 `LINK_CODE_VER`，结果暴露为 `APP_U2VerOk()`（1 = 两片同版）。
- 不一致时：U1 **不采用** U2 的测量数据；调试模式下仍回 `00 OK`（只置 `NO_PEER`），
  生产模式（`MEAS_CC_REQUIRED=1`）判 `05 ERR_TEST`，并在事件/日志里明确提示"两片版本不一致，请重烧"。
  —— 用 `LINK_RESET` 解决不了这个问题。

### 7.2 能力位图 `caps`（本次新增）

STATUS 应答偏移 22 的 2 字节，bit 置 1 = 支持：

| bit | 命令 | bit | 命令 |
|---|---|---|---|
| 0 | `0x0100` PING | 5 | `0x0106` LINK_RESET |
| 1 | `0x0101` STATUS | 6 | `0x0107` EVENT |
| 2 | `0x0103` MEAS_XCHK | 7 | `0x0108` EVENT_GET |
| 3 | `0x0104` PULSE_XCHK | 8 | `0x0109` ENC_XCHK（v1.4） |
| 4 | `0x0105` ARM | 9..15 | 预留 = 0 |

> `LINK_CAP_ALL` 随之从 `0x00FF` 变成 **`0x01FF`**（bit0..8）。
> ⚠ 老固件只知道 bit0..7，看到 `caps` 里的 bit8 只会当成"不认识的位"，**不影响兼容**；
> 反过来，老 U2 会因为 `LINK_CODE_VER` 不一致被 U1 检出（`APP_U2VerOk()=0`），提示重烧。

好处：以后再加命令，**老版本对面不会"整个链路不可用"**，而是明确"这条不支持"（U1 看到 caps 缺位就不发那条，或发出去以 `FF NIY` 处理）。

## 8. 错误处理与恢复矩阵

| 现象 | 最可能原因 | 协议层动作 |
|---|---|---|
| 一直超时，`tx_timeout` 持续增长 | 跳线没交叉 / 对端没上电 / 波特率不一致 | 连续 3 次 → `LINK_RESET` → 仍不行则退避重试；**同时**报"链路不通" |
| `code_ver` 不一致 | 有一片没跟着重烧 | **不采用**对侧数据；提示重烧（`LINK_RESET` 无效） |
| `rx_crc_err` 偶发增长 | 线长/干扰/串阻缺失 | 该帧丢弃；重传 1 次即可恢复；持续增长查硬件 |
| `rx_half` 增长 | 对端发到一半复位/掉线 | 丢弃半截帧并重同步（§3.5），下一次请求自然恢复 |
| `rx_len_err` 增长 | 对面是不同版本/不匹配的波特率 | 丢弃并重同步；按 `code_ver` 判断是否重烧 |
| `rx_stale` 增长 | 迟到的旧应答 | 丢弃（正常现象，链路抖动后会短暂出现） |
| `rx_drop` 增长 + ORE | 主循环被长时间占用 / 对端发太密 | 查主循环是否有阻塞；必要时缩短窗口或降速 |
| ARM 回 `01 BUSY` | 上一次窗口还在跑 | U1 等本次测试收尾后再 ARM（不要立刻重试） |
| ARM 回 `0B ERR_PARAM` | window 越界 / flags 非 0 / session=0 | 修正参数（属编程错误，不重试） |
| 收到 `FF NIY` | 对端没实现该命令 | U1 查 `caps` → 记录"对端能力不足"，不重试 |
| 事件 `ev_overflow` 增长 | U1 取事件太慢 | U1 加快 `EVENT_GET` 轮询；事件本身已在 U2 侧累计计数 |

## 9. 与 PC 协议对照（哪些照搬、哪些内部专用）

| 项 | PC ↔ U1 | U1 ↔ U2（本文） |
|---|---|---|
| 帧格式 | `A5 5B\|CMD\|SEQ\|LEN\|DATA\|CRC16` | **完全相同** |
| 字节序 / CRC | 大端 / CRC16-MODBUS | **完全相同** |
| 序号规则 | 1 起递增；0 = 主动帧 | **完全相同** |
| ACK 规则 | ACK 的 N = 收到的 N | **完全相同** |
| 状态码表 | 00/01/02…/FF | **取值与含义相同**（用到 6 个） |
| 命令码段 | `0x0009~0x0112` | **`0x0100~0x01FF`**（唯一刻意的不同） |
| 传输介质 | USB CDC | USART3 115200 |
| 出错策略 | CRC 错只诊断不回 | CRC 错丢弃 + **重传 1 次**（内部链路要自己扛） |
| 判定归属 | U1 判（PC 只拿结论） | **U1 判**（U2 从不下结论） |
