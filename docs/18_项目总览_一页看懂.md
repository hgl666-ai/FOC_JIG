# 18 项目总览（一页看懂）

> 写给想快速搞清"这个治具是干什么的、做到哪一步了、还差什么"的人（不用懂代码）。
> 细节各自在 `docs/00~17`，本文只讲大图和现状。

---

## 1. 一句话说清这个治具

**一块插在电脑上的小板子（USB 供电），产线工人把它压到 FOC 板上：
先给 FOC 板烧固件，再给 FOC 板做 6 项功能测试，最后给出 PASS/FAIL。**

它自己**没有电机、没有功率级**，只能干两件事：
- **烧录**：用两根线（SWD）把固件写进 FOC 板的芯片；
- **测量**：用一堆"万用表式"的线读 FOC 板上的电压、波形、电流。

而"让电机转起来""输出三相电压""通电流"这些**必须由 FOC 板自己做** —— 所以测试时要 FOC 板配合（它得听得懂我们发的命令）。

---

## 2. 硬件长什么样

板上其实有**两颗单片机**，分工不同：

| 谁 | 角色 | 干什么 |
|---|---|---|
| **U1** | 主控（指挥） | 接电脑、烧录 FOC 板、下命令、做判定、跟电脑说话 |
| **U2** | 测量副手 | 只负责"另一双眼睛"：同样测一遍，用来和 U1 互相校验 |

一颗 U1 只有 9 路模拟输入和几路测波形的脚，**测一遍不信、测两遍才可信** —— 所以要有 U2。

**四条连线（每条都是同一套数据格式）**：

```
  电脑(PC) ──USB──► U1 ──串口3──► U2            （内部互检）
                      │
                      ├──串口1──► FOC 板          （发命令/收数据）
                      └──SWD────► FOC 板          （烧固件、读芯片信息）
```

**所有连线用同一套"信封"格式**，所以一套代码能用三处：

```
A5 5B | 命令(2) | 序号(2) | 长度(2) | 数据(n) | 校验(2)
```

## 3. 产线上一次完整动作（这是最重要的流程）

```
① 工人把 FOC 板放上治具、压下
        ↓  治具给 FOC 板送 5V 电（顶针接触）
② PC 问一句：治具你在吗？U2 在吗？         → 命令 0x0017
③ PC 把固件传给治具（治具先存自己 Flash）    → 0x0009 → 0x000A×N → 0x000B
④ PC 让治具烧到 FOC 板                     → 0x0112
        ↓  治具顺便读 FOC 板的芯片 UID，主动推给 PC（板子身份证） → 0x0024
⑤ PC 发"一条命令跑完六项测试"               → 0x0010
        ↓  治具内部自动：让 FOC 进测试模式 → 测电压 → 测波形 → 判相电压
        ↓              → 测编码器 → 测电流 → 关输出
⑥ PC 拿到一份汇总：PASS / FAIL，FAIL 还会说是第几步坏的
⑦ 工人抬起治具，换下一块
```

**整块板子，PC 只需要发 4 类命令**：自检 → 上传固件 → 烧录 → 一键测试。其余都是"想细看某一项"时才发。

## 4. PC 能发的命令（谁发、谁收、回什么）

| 想干什么 | PC 发 | 谁来回 | 回多少字节 |
|---|---|---|---|
| 治具/副手是否在线 | `0x0017` | 治具 | 32 |
| 查治具固件版本 | `0x000C` | 治具 | 4 |
| 查 FOC 板固件版本 | `0x000D` | 治具（走 SWD 读） | 4 |
| 上传固件 | `0x0009`+`0x000A`×N+`0x000B` | 治具 | 各 1 |
| 烧录到 FOC 板 | `0x0112` | 治具 | 1 |
| **板子 SN 主动上报** | （不用发） | **治具自己推** | **16** |
| ② 电压检测 | `0x0015` | 治具（会去问 FOC 板） | 71 |
| ③ 波形检测 | `0x0019` | 治具（会去指挥 FOC 板） | 91 |
| ④ 三相输出检测 | `0x001A` | 治具（会去指挥 FOC 板） | 34 |
| ⑤ 编码器检测 | `0x001B` | 治具（会去指挥 FOC 板） | 29 |
| ⑥ 电流检测 | `0x0014` | 治具（会去指挥 FOC 板） | 22 |
| 六项一次跑完 | `0x0010` | 治具 | 29（含每步结果） |
| 只看原始波形 | `0x000F` | 治具 | 91 |
| 只看 9 路电压 | `0x000E` | 治具 | 77 |
| 手工给 FOC 板发命令（调试） | `0x0011` | 治具转发 → FOC 板 | 变长 |

**上位机只需要记住一件事**：应答第 1 个字节是状态 —— `00` = 合格，**`05` = 测完了但不合格**（这是正常结果，不是通讯错误！）。

## 5. 六项测试：各自怎么测、做到哪了

| # | 测什么 | 怎么测（大白话） | 治具侧 | 还缺 |
|---|---|---|---|---|
| ① | 和 FOC 板说话 | 发一条命令看它回不回 | ✅ 完成 | FOC 固件要按规格实现 |
| ② | 各路电压 | 治具自己量 9 路，同时问 FOC 板"你量到多少"，比 | ✅ 完成 | FOC 固件要能报自己量到的值 |
| ③ | 主控波形 | FOC 板输出方波，治具数频率/占空比 | ✅ 完成 | FOC 固件要能"按我的要求输出方波" |
| ④ | 三相输出 | 让 FOC 板输出电压，看"电压 ≈ 占空比 × 母线" | ✅ 完成 | 同上 + **工位要有 24V** |
| ⑤ | 编码器 | **治具**发脉冲，副手 U2 数一遍，FOC 板也数一遍，三个数对 | ✅ 完成 | FOC 固件要能"数边沿并上报" + **接线** |
| ⑥ | 相电流 | 让 FOC 板通一个电流，两边各量一次，比 | ✅ 完成 | FOC 固件要能通流并上报 + **夹具要有电流回路** |

**"治具侧完成"= 固件写好、有自动化测试、逻辑跑通**；**不等于"上板验过"**（见第 7 节）。

## 6. 已经做完的（可交付）

**固件**
- 四条链路的收发（电脑 / 副手 / FOC 板 / SWD），统一信封 + 校验 + 序号 + 重传
- 只造一次、两片共用的一套代码（17 个文件逐字节一致，回归自动比对）
- 20 条 PC 命令 + 1 条主动上报 + 9 条内部链路命令
- 六项判定：电压 / 相电压 / 电流 / 编码器三方对齐（都按"数据不全不冤判"的规矩）
- 一键全流程、单项一条命令（③④⑤⑥ 都打包好了）
- 烧录：SPI Flash 存固件 + SWD 写目标 + 分区保护
- **板子 SN 主动上报 `0x0024`**：烧录成功后读 FOC 板的 96-bit UID，主动推给 PC 落库
  （同一块板不重复上报；读 UID 失败静默跳过，不影响烧录结果）

**验证**
- 电脑上模拟全套流程跑的自动化测试：**2436 条断言，全过**（含 SN 上报 22 项）
- 两片固件都能编译：**0 错误 0 警告**（U1：Code=39412 / RO=688 / RW=632 / ZI=11960；
  U2：Code=16572 / RO=600 / RW=100 / ZI=4572），17 对两片副本逐字节一致
- 原理图连线结论已逐脚核对过（并纠正过一处重大误判）

> ⚠ **以上全是"电脑上模拟 + 编译"的结论，真板一次都还没跑过。**

## 7. 缺陷 / 风险（按"要不要紧"排）

### ✅ 已解决（原来的 🔴 第 1 条，留档）

| 原问题 | 结论 |
|---|---|
| 治具到底用哪两个脚烧 FOC 板？图纸上找不到 | **已解决（2026-10-27 新版治具原理图）**：**SWCLK = PA14（`U1-SCLK`）、SWDIO = PA13（`U1-SWD`）** —— 新版板把 U1 自己的 SWD 口独立引出来，专门给 FOC 板烧录用。代码已改、`SWD_PINS_CONFIRMED=1`。⚠ **真板烧录仍未实测**（见 §9 ⑤），代价见下面第 8 条 |

### 🔴 必须解决，否则产线跑不起来

| # | 问题 | 说明 |
|---|---|---|
| 1 | **FOC 板固件一条命令都还没实现** | 六项测试全卡在这。规格已写好（`docs/16` 给固件同事，带 31 条可直接对拍的帧） |
| 2 | **24V 母线谁供** | ④⑥ 要真的输出电压/电流，必须有 24V。治具只测不供，工位得给 |
| 3 | **⑥ 的电流回路** | 不接电机就没电流，测不到采样/放大链路（要么夹具串个限流电阻） |

### 🟡 会影响准确性，上板要标定

| # | 问题 | 说明 |
|---|---|---|
| 4 | 9 路分压系数是"算出来的" | 实际电阻/基准有 1~3% 误差，要用万用表对一遍（这是②④⑥判得准不准的基础） |
| 5 | 判定容差都是估值 | ±5%、±30mV 这类数字要拿真板子收紧或放宽 |
| 6 | 编码器电平门限未知 | 治具是 3.3V 输出，若 FOC 板是 5V 逻辑可能收不到（量一下那 3 个点即可判断） |
| 7 | 电流量程未知 | 现在只能比 mV，换算成安培要采样电阻/放大倍数 |
| 8 | **生产固件会关掉 U1 自己的 SW-DP** | 烧 DUT 的固件里 PA13/PA14 是普通 IO（AFIO `SWJ_CFG=100`）→ **U1 以后只能走 H1(BOOT0)+USART3 升级**，要调试 U1 得专门编一版（`SWD_FREE_DEBUG_PINS=0`，那一版**不能烧 DUT**）。所以板上 **H1 跳线和那两针串口不能省**（`docs/09` §2.1） |
| 9 | **DUT 分区地址已确认，但 `DUT_VER_OFFSET` 仍是占位** | 分区已按 FOC 工程确认：**Boot 64K（`0x08000000`+`0x10000`）/ App `0x08010000`+512K**；`0x000D` 读版本号在 App 里的偏移还是占位的 `0x20`，等 FOC 工程给真值 |

### 🟢 已知小问题（不影响主线）

| # | 问题 |
|---|---|
| 10 | 固件默认 `JIG_DUT_LINK=0`，那 7 条涉及 FOC 板的命令会回"未实现"，用之前要改一处宏重新编译 |
| 11 | 调试模式下"波形检测"不判合格（产线要判就得换生产模式，或改用打包命令） |
| 12 | PC 工具（`tools/foc_jig_tool.py`）只认烧录那几条，六项测试还得手工发帧 |
| 13 | 烧录失败只回一个状态码，分不清"连不上/擦除失败/校验失败" |
| 14 | `0x000D` 读 FOC 板版本依赖 SWD，且版本偏移还是占位（= 第 9 条） |

## 9. 现在离"能上产线"还差多少

```
已完成 ████████████████████░░░░  治具固件（六项都能跑，有自动化测试）
待办   ░░░░░░░░░░░░░░░░░░░░░░░░  
       ① ~~烧录通路（问硬件）~~ ✅ 已定：PA14=SWCLK / PA13=SWDIO（2026-10-27 新图）
       ② FOC 板固件（等对方实现）
       ③ 接线 + 24V + 电流回路（夹具/工位）
       ④ 上板标定（分压系数、容差）
       ⑤ 真板烧一次（烧录链路只在电脑上模拟过，真板一次都没烧）  ← 现在最关键
```

**能验证的先后顺序**（不用等所有事情齐）：
1. **今天就能验**：治具自检（`0x0017`）、9 路电压（`0x000E`）、编码器治具自环（`0x0012`+`0x0013`）
2. **接好线就能验**：⑤ 的接线是否通、④ 的相电压（要 24V）
3. **FOC 固件来了之后**：①~⑥ 逐项跑，再用 `0x0010` 一键
4. **最后**：真板烧录实测 → 全流程连跑 → 上产线
