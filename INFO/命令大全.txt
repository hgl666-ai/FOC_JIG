0. 总览
--------------------------------------------------------------------------------

0.1 帧格式（两条链路完全一致）

 偏移   0    1          2            3             4            5           6          7        8 .. 8+L-1     8+L       9+L
         A5   5B   CMD_H  CMD_L  SEQ_H  SEQ_L  LEN_H  LEN_L   DATA...      CRC_H  CRC_L

    +--------+------+----------------------------------------------------------+
    | 字段   | 字节 | 说明                                                     |
    +--------+------+----------------------------------------------------------+
    | 帧头 F |  2   | 固定 A5 5B                                               |
    | 命令 C |  2   | 大端 u16，见第 1/2 章命令表                              |
    | 序号 N |  2   | 大端 u16，从 1 递增、FFFF 回卷；0 专供"主动帧"            |
    | 长度 L |  2   | 大端 u16，表示 DATA 的字节数（不含帧头/CRC）             |
    | 数据 D |  L   | 见各命令说明                                             |
    | CRC16  |  2   | MODBUS 校验，大端存放                                    |
    +--------+------+----------------------------------------------------------+

    一帧最短 10 字节（L=0）。单帧 DATA 上限：
        PC ↔ U1 : 256 字节
        U1 ↔ U2 :  64 字节

0.2 字节序
    所有多字节字段大端（高字节在前）。

0.3 CRC16 规则
    算法    : MODBUS（多项式 0xA001 反射，初值 0xFFFF）
    计算范围: 从"帧头 A5"到"数据 D 的最后一个字节"（不含 CRC 自身）
    存放    : 大端（高字节在前）
    校验失败: 接收方只做诊断计数、不回任何应答，发送方靠超时重发。
    自检    : CRC16("123456789") = 0x4B37

0.4 帧序号 N 与 ACK 规则
    1) PC 每发一帧 N 递增（从 1 开始，0xFFFF 后回卷，跳过 0）。
    2) 应答帧的 N 等于请求帧的 N（ACK 回显）。
    3) 治具/U2 主动发起的帧（非应答）N 一律为 0，便于接收方区分
       "这是我那条命令的应答" 还是 "对端自己发过来的"。
    4) 收到 N 与"当前在等的那一发"不符的应答 → 当作陈旧帧丢弃（不报错）。
    5) 命令码未定义 → 回 FF（NIY，未实现），不能静默丢弃：
       否则对端只能看到一个超时，分不清"设备不在"和"命令没实现"。

0.5 状态码总表（PC 侧与内部链路共用同一张表）
    +------+------------------+------------------------------------------------+
    | 码   | 名称             | 含义                                           |
    +------+------------------+------------------------------------------------+
    | 0x00 | OK               | 成功                                           |
    | 0x01 | BUSY             | 系统忙：非空闲状态收到命令（上传中/烧录中/采集中）|
    | 0x02 | ERR_SIZE         | 文件大小异常（0 / 越界 / 帧数 0）              |
    | 0x03 | ERR_FLASH        | 治具 SPI Flash 读写失败 / 器件 ID 不对         |
    | 0x04 | ERR_PROG         | 烧录被烧板失败（SWD 连接/擦写/校验失败）       |
    | 0x05 | ERR_TEST         | 治具测试判定失败（电压超差 / 脉冲两端对不上）  |
    | 0x06 | ERR_NO_FW        | 固件不存在（槽为空 / 目标读到全 FF）           |
    | 0x07 | ERR_INCOMPLETE   | 固件不完整（完整标志 0xA5 缺失）               |
    | 0x08 | ERR_CRC          | 帧 CRC 错误（仅诊断，不回 ACK）                |
    | 0x09 | ERR_SEQ          | 帧序号非递增（仅警告，不拒绝）                 |
    | 0x0A | ERR_COUNT        | 上传字节数与声明不符                           |
    | 0x0B | ERR_PARAM        | 参数错误（mode 非法 / 长度不对）               |
    | 0x0C | ERR_TIMEOUT      | 上传 10s 无新数据 / 连不上目标                 |
    | 0x0D | ERR_OVERFLOW     | 上传溢出（锁存，后续数据帧一直回此码）         |
    | 0xFF | NIY              | 命令未实现                                     |
    +------+------------------+------------------------------------------------+

0.6 两条链路的分工
    PC ↔ U1 : 命令码 0x0009~0x0112；U1 是"被 PC 指挥的执行者"，也是判定方。
    U1 ↔ U2 : 命令码 0x0100~0x01FF；U1 是主机、U2 是从机，U2 从不做判定。
    U1 两个串口各自独立解析，所以命令码段分开、互不干扰；
    但帧格式、序号规则、状态码表完全一致。

一、PC ↔ 治具 U1
================================================================================

命令总表
    +--------+--------------------------------+--------+--------+--------+
    | 命令   | 功能                           | 方向   | 请求LEN| 应答LEN|
    +--------+--------------------------------+--------+--------+--------+
    | 0x0009 | 固件起始帧（开始上传）         | PC→U1  |   9    |   1    |
    | 0x000A | 固件数据帧                     | PC→U1  | 1..256 |   1    |
    | 0x000B | 固件结束帧                     | PC→U1  |   0    |   1    |
    | 0x000C | 查询固件版本（治具 Flash 中）  | PC→U1  |   0    |   4    |
    | 0x000D | 查询固件版本（被烧板中）       | PC→U1  |   0    |   4    |
    | 0x000E | 测量 ADC（9 路模拟量）         | PC→U1  |   1    |  77    |
    | 0x000F | 脉冲捕获（三相 PWM）           | PC→U1  |   1    |  91    |
    | 0x0010 | 一键全流程（②③④⑤⑥ 一次跑完）| PC→U1  |   0    |  29    |
    | 0x0011 | DUT 协议透传（调试万能口）     | PC→U1  | 2..66  | 1..65  |
    | 0x0012 | 编码器脉冲发生（⑤ 治具发）     | PC→U1  | 0/12   |   9    |
    | 0x0013 | 读/清 U2 的编码器边沿计数      | PC→U1  |   1    | 2/16   |
    | 0x0014 | 相电流检测（⑥ 一条命令跑完）   | PC→U1  | 0/8    |  22    |
    | 0x0015 | 电压检测（② 一条命令跑完）     | PC→U1  |   0    |  71    |
    | 0x0016 | 三相输出判据（④）              | PC→U1  |   7    |  34    |
    | 0x0017 | 治具自检/在线状态（任何状态可问）| PC→U1 |   0    |  32    |
    | 0x0018 | 编码器三方对齐判定（⑤ 判定层） | PC→U1  |  38    |  29    |
    | 0x0019 | ③ 一条命令（MCU 脉冲检测）     | PC→U1  |   0    |  91    |
    | 0x001A | ④ 一条命令（三相输出检测）     | PC→U1  |   0    |  34    |
    | 0x001B | ⑤ 一条命令（编码器检测）       | PC→U1  |   0    |  29    |
    | 0x0112 | 烧录 Flash 固件到被烧板        | PC→U1  |   0    |   1    |
    +--------+--------------------------------+--------+--------+--------+
    注：0x0011 的应答长度 = 1（治具状态码）+ DUT 应答的 DATA 长度。
        0x0013 清零时应答 2B，读取时应答 1+15=16B。
        0x0010 内部会按顺序调用 0x0015/0x000F/0x0016/0x0012/0x0013/0x0014，
        这些子命令的应答会**照常**发给 PC（同 SEQ），最后再回 0x0010 的汇总。
        0x0019/0x001A/0x001B/0x0014 是"单项一条命令"：内部同样串子命令，但
        **子命令的应答一律拦下不发**，只回最后那一份报告 → 一条命令一条应答。
        详细字段与上位机用法见 docs/17；DUT 侧协议见 docs/15 与 docs/16。

1.1  0x0009  固件起始帧
--------------------------------------------------------------------------------
功能      : 开始一次固件上传：声明总帧数、文件大小、版本号；
            治具据此"选槽 → 解保护 → 擦除覆盖的扇区 → 写槽头"。
发送方    : PC
接收方    : 治具 U1
帧头      : A5 5B
命令      : 00 09
帧序号    : N（PC 递增的自然序号）
数据长度  : 00 09（= 9 字节）
数据      : {2 字节 u16：总帧数（本次上传要发多少个 0x000A 帧）
             4 字节 u32：文件大小（字节）
             3 字节    ：版本号 [主][次][修订]}
             —— 共 9 字节，全部大端
CRC16     : MODBUS，覆盖 帧头..数据末字节，大端
ACK 内容  : 命令 00 09；帧序号 = N；长度 00 01；数据 = 1 字节状态码
            状态码：00 OK / 01 BUSY / 02 ERR_SIZE / 03 ERR_FLASH
示例      : 总帧数 2、大小 0x1000、版本 1.2.3、N=1
            PC → : A5 5B 00 09 00 01 00 09 00 02 00 00 10 00 01 02 03 56 14
            U1 → : A5 5B 00 09 00 01 00 01 00 DD 89        （00 = OK）
备注      : 1) 文件大小上限 65528 字节；大小为 0 / 越界 / 帧数为 0 → 02 ERR_SIZE。
            2) 两轮上传自动切槽：第 1 轮写 Slot0（Bootloader），第 2 轮写 Slot1（App）。
            3) 起始帧会触发扇区擦除，最坏约 6.4 秒（16 个 4KB 扇区 × 400ms），
               上位机等待时间要给够（参考实现用 30 秒）。
            4) 槽头 8 字节：[0..3] 大小 u32 小端、[4..6] 版本号、[7] 完整标志 0xA5。

--------------------------------------------------------------------------------
1.2  0x000A  固件数据帧
--------------------------------------------------------------------------------
功能      : 携带固件数据；治具攒满 256 字节写一页 SPI Flash。
发送方    : PC
接收方    : 治具 U1
帧头      : A5 5B
命令      : 00 0A
帧序号    : N（递增）
数据长度  : 00 LL（1 ~ 256）
数据      : 本次要写入的原始固件字节（长度 = L）
CRC16     : 同上
ACK 内容  : 命令 00 0A；帧序号 = N；长度 00 01；数据 = 1 字节状态码
            状态码：00 OK / 01 BUSY / 03 ERR_FLASH / 0D ERR_OVERFLOW（溢出后锁存）
示例      : 4 字节数据 DE AD BE EF、N=2
            PC → : A5 5B 00 0A 00 02 00 04 DE AD BE EF AF F8
            U1 → : A5 5B 00 0A 00 02 00 01 00 ...           （00 = OK）
            溢出应答示例：A5 5B 00 0A 00 02 00 01 0D 6F 48 （0D = ERR_OVERFLOW）
备注      : 1) 单帧数据上限 256 字节，超过会被整帧判非法并重新同步。
            2) 累计字节数超过起始帧声明的大小 → 锁存 0D，之后每个数据帧都回 0D。
            3) 10 秒没有新数据：治具主动发一帧 0x000A（见 1.9），
               帧序号 = 最后收到的那一帧的序号，数据 = 0C ERR_TIMEOUT，并回到空闲。

--------------------------------------------------------------------------------
1.3  0x000B  固件结束帧
--------------------------------------------------------------------------------
功能      : 声明本次上传结束：刷最后一个残页 → 比对字节数 → 写完整标志 → 切槽。
发送方    : PC
接收方    : 治具 U1
帧头      : A5 5B
命令      : 00 0B
帧序号    : N（递增）
数据长度  : 00 00
数据      : 无
CRC16     : 同上
ACK 内容  : 命令 00 0B；帧序号 = N；长度 00 01；数据 = 1 字节状态码
            状态码：00 OK / 0A ERR_COUNT / 锁存的错误码（03 / 0D）
示例      : N=3
            PC → : A5 5B 00 0B 00 03 00 00 48 35
            U1 → : A5 5B 00 0B 00 03 00 01 00 87 89        （00 = OK）
备注      : 1) 实收字节数与声明不符 → 0A ERR_COUNT，且不写完整标志（记为不完整）。
            2) 无论成功失败都会切槽并回到空闲，便于下一轮上传。

--------------------------------------------------------------------------------
1.4  0x000C  查询固件版本号（治具 Flash 中）
--------------------------------------------------------------------------------
功能      : 读取治具板载 SPI Flash 里已存固件的版本号（上传后校验用）。
发送方    : PC
接收方    : 治具 U1
帧头      : A5 5B
命令      : 00 0C
帧序号    : N（递增）
数据长度  : 00 00
数据      : 无
CRC16     : 同上
ACK 内容  : 命令 00 0C；帧序号 = N；长度 00 04；
            数据 = [0] 状态码 + [1..3] 版本号 主/次/修订
            状态码：00 OK / 06 ERR_NO_FW（槽空）/ 07 ERR_INCOMPLETE（完整标志缺失）
            失败时版本号返回 00 FF FF
示例      : N=4，App 槽里是 v1.0.0
            PC → : A5 5B 00 0C 00 04 00 00 49 31
            U1 → : A5 5B 00 0C 00 04 00 04 00 01 00 00 2A 7F
备注      : 两个槽都有固件时报 App 槽（Slot1）的版本。

--------------------------------------------------------------------------------
1.5  0x000D  查询固件版本号（被烧板中）
--------------------------------------------------------------------------------
功能      : 读被烧板（STM32F405 目标板）里正在运行的固件版本号。
发送方    : PC
接收方    : 治具 U1
帧头      : A5 5B
命令      : 00 0D
帧序号    : N（递增）
数据长度  : 00 00
数据      : 无
CRC16     : 同上
ACK 内容  : 命令 00 0D；帧序号 = N；长度 00 04；
            数据 = [0] 状态码 + [1..3] 版本号 主/次/修订
            状态码：00 OK / 06 ERR_NO_FW（读到全 FF，App 区为空）
                    / 0C ERR_TIMEOUT（连不上目标）
示例      : N=5，连不上目标
            PC → : A5 5B 00 0D 00 05 00 00 49 5D
            U1 → : A5 5B 00 0D 00 05 00 04 0C 00 FF FF 5A 31   （0C = 失败）
备注      : 1) 实现方式：通过 SWD 直接读目标 App 分区，不需要目标配合串口协议。
            2) 版本号在 App 分区里的偏移是 flash_map.h 的 DUT_VER_OFFSET（当前占位 0x20）。
            3) 这条命令是最便宜的烧录链路冒烟测试：不需要上传任何固件。

--------------------------------------------------------------------------------
1.6  0x000E  测量 ADC（9 路模拟量）
--------------------------------------------------------------------------------
功能      : 读/测 9 路模拟量：24V、10V、5V、3.3V、A/B/C 相电压、2 路电流检测。
发送方    : PC
接收方    : 治具 U1
帧头      : A5 5B
命令      : 00 0E
帧序号    : N（递增）
数据长度  : 00 01
数据      : [0] 模式：00 = 只读（立刻回最近一批，不触发测试）
                        01 = 测试（等数据稳定 → 与 U2 交叉校验 → 回结论）
            其它值 / LEN=0 → 回 0B ERR_PARAM
CRC16     : 同上
ACK 内容  : 命令 00 0E；帧序号 = N；长度 00 4D（= 77）；
            数据 = [0]       状态码（00 OK / 05 ERR_TEST / 0B ERR_PARAM /
                                     01 BUSY / 0C ERR_TIMEOUT：9 路一直不稳定）
                   [1..55]   电压快照 55 字节（见附录 A）
                   [56..76]  交叉校验块 21 字节（见附录 B）
示例      : 只读，N=6
            PC → : A5 5B 00 0E 00 06 00 01 00 1E 89
            测试，N=7
            PC → : A5 5B 00 0E 00 07 00 01 01 22 49
            U1 → : A5 5B 00 0E 00 07 00 4D | 状态1B+快照55B+校验块21B | F0 6B
备注      : 1) mode=01 时治具会先向 U2 发 ARM 让两块板采同一段时间
               （见 2.5），窗口 20ms；窗口跑完才回这一帧，耗时约十几毫秒。
            2) 调试模式（默认）不做门限判定：9 路是否合格看快照 55B 里的
               flags 的 ALL_OK 位；生产模式才按规格门限判，超差回 05 ERR_TEST。
            3) U2 缺席：交叉校验块置 NO_PEER 位；调试模式仍回 00 OK，
               生产模式（要求交叉校验）回 05 ERR_TEST。
            4) 哪一路超差看 21B 校验块里的掩码（一位一路）。

--------------------------------------------------------------------------------
1.7  0x000F  脉冲捕获（三相 PWM 频率/占空比）
--------------------------------------------------------------------------------
功能      : 测三相 PWM 的周期与占空比：U1 测电机输出端，U2 测驱动输入端，
            两片在同一个时间窗里各采 200ms，然后交换结果做对比。
发送方    : PC
接收方    : 治具 U1
帧头      : A5 5B
命令      : 00 0F
帧序号    : N（递增）
数据长度  : 00 01
数据      : [0] 模式：00 = 只读（回最近一次结果）
                        01 = 测试（ARM 同步 → 两端各采 200ms → 交换 → 回结论）
            其它值 / LEN=0 → 回 0B ERR_PARAM
CRC16     : 同上
ACK 内容  : 命令 00 0F；帧序号 = N；长度 00 5B（= 91）；
            数据 = [0]       状态码
                   [1..45]   本片（U1，电机输出端）脉冲结果 45 字节（见附录 C）
                   [46..90]  对侧（U2，驱动输入端）脉冲结果 45 字节
示例      : 测试，N=8
            PC → : A5 5B 00 0F 00 08 00 01 01 E7 4B
            U1 → : A5 5B 00 0F 00 08 00 5B | 状态1B+本片45B+对侧45B | 22 BC
备注      : 1) 频率范围 10 Hz ~ 60 kHz；超出会置"超范围"标志而不是给假值。
            2) 占空比只记录不判：死区、驱动延时会让输入/输出两端天然不同。
            3) 判据（默认关闭，生产模式打开）：两端对不上（一端有信号一端没有，
               或周期差 > 1%）即判 05 ERR_TEST。
            4) U2 缺席时对侧那 45 字节按"无数据"打包（无信号标志置位）。

--------------------------------------------------------------------------------
1.8  0x0112  烧录 Flash 固件到被烧板
--------------------------------------------------------------------------------
功能      : 把治具 Flash 里的两段镜像（Bootloader + App）通过 SWD 两线
            烧进被烧板，烧完复位让目标运行。
发送方    : PC
接收方    : 治具 U1
帧头      : A5 5B
命令      : 01 12
帧序号    : N（递增）
数据长度  : 00 00
数据      : 无
CRC16     : 同上
ACK 内容  : 命令 01 12；帧序号 = N（受理时的序号，锁存后回显）；
            长度 00 01；数据 = 1 字节状态码
            状态码：00 OK / 01 BUSY / 02 ERR_SIZE / 03 ERR_FLASH /
                    04 ERR_PROG（连接/擦写/校验失败）/ 06 ERR_NO_FW / 07 ERR_INCOMPLETE
示例      : N=9
            PC → : A5 5B 01 12 00 09 00 00 59 09
            U1 → : A5 5B 01 12 00 09 00 01 00 96 98        （00 = OK，烧完才回）
备注      : 1) ACK 在烧录完成后才返回：擦除 + 写入通常十几秒到几十秒，
               期间 PC 不要断线、不要连发命令。
            2) 物理链路：SWCLK + SWDIO + 共地，不用 BOOT0、不用 RESET；
               烧完靠目标的 AIRCR.SYSRESETREQ 复位运行。
            3) 烧录前会做前置检查：两槽缺固件 → 06；不完整 → 07；越界 → 02。
            4) 目标连不上（如程序占用了 PA13/PA14、或开了读保护）→ 04 ERR_PROG。

--------------------------------------------------------------------------------
1.9  治具主动帧  0x000A（上传超时通知）
--------------------------------------------------------------------------------
功能      : 上传过程中 10 秒没有新数据，治具主动通知 PC "这次上传黄了"。
发送方    : 治具 U1
接收方    : PC
帧头      : A5 5B
命令      : 00 0A
帧序号    : = 最后收到的那一帧的序号（当作那条数据帧的迟到应答）
数据长度  : 00 01
数据      : 0C ERR_TIMEOUT（若之前已锁存错误码，则回锁存的码）
CRC16     : 同上
ACK 内容  : 不需要 PC 应答
示例      : A5 5B 00 0A 00 02 00 01 0C AF 89
备注      : 收到后治具已回到空闲状态，PC 可以直接开始下一轮上传。


--------------------------------------------------------------------------------
1.10  0x0017  治具自检 / 在线状态
--------------------------------------------------------------------------------
功能      : 一次问清"治具在不在、U2 在不在、内部链路有没有错"。
            上位机"设备连接/自检"页用；**只读、无副作用、任何状态都能问**
            （它不走 BUSY 闸门 —— 治具正忙时普通命令只能拿到 01 BUSY，这条照样回）。
数据      : 无（LEN 必须为 0，否则回 0B ERR_PARAM）
ACK 内容  : 命令 00 17；帧序号 = N；长度 00 20（= 32）；数据 32 字节：
            [0]     状态码 00
            [1]     当前状态机 0=INIT 1=IDLE 2=上传 3=烧录 4=测量 5=等DUT
                              6=发编码器脉冲 7=等U2编码器 8=相电流 9=电压 10=一键
            [2]     flags: bit0=U2在线 bit1=两片链路代码版本一致
                            bit2=内部链路忙 bit3=本固件编进 DUT 链路
            [3..4]  U2 的链路代码版本（0x0104）
            [5..6]  U2 的能力位图
            [7..8]  U2 报的存活计数
            [9..10] 保活探测成功次数
            [11..12] 保活探测超时次数
            [13..16] U1<->U2 链路收到帧数（u32）
            [17..20] U1<->U2 链路 CRC 错次数（u32）
            [21..22] 请求超时次数
            [23..24] 上一发没收尾就重发的次数
            [25..26] U1 链路串口接收丢字节数
            [27..28] U1 链路串口 HAL 拒发次数（正常恒 0）
            [29..30] U2 报的接收丢字节数
            [31]    保留 0
示例      : 请求 A5 5B 00 17 00 01 00 00 46 8F
            应答 A5 5B 00 17 00 01 00 20 00 01 00 04 01 01 FF 00 00 12 00 31
                 00 02 00 00 00 07 00 00 00 00 00 00 00 00 00 00 00 00 00 00
                 00 00 DC 5A
            （这只是示例值；SEQ/CRC 以实际帧为准）
备注      : 上位机建议：flags.bit0 == 0 → 先报"U2 不在"；flags.bit1 == 0 →
            两片固件版本不一致（只重烧了一片）；probe_fail / CRC 错持续增长 →
            内部串口有问题。


--------------------------------------------------------------------------------
1.11  0x0011  DUT 协议透传（调试万能口）
--------------------------------------------------------------------------------
功能      : 把一条 DUT 命令原样转发给被测板，再把被测板的应答带回来。
            被测板协议见 docs/15 / docs/16（命令空间 0x0200~0x02FF）。
            有了它，DUT 侧新增命令**不需要改治具固件**就能调。
数据      : [0..1]  DUT 命令号（2 字节大端，**只接受 0x0200~0x02FF**）
            [2..]   DUT 命令的 DATA（原样）
ACK 内容  : 命令 00 11；帧序号 = N；长度 = 1 + DUT 应答 DATA 长度；
            数据 = [0] 治具状态码 + [1..] DUT 应答的 DATA（原样，含 DUT 自己的状态字节）
示例      : 让被测板 PING：请求 A5 5B 00 11 xx xx 00 06 02 00 DE AD BE EF <CRC>
            应答             A5 5B 00 11 xx xx 00 05 00 DE AD BE EF <CRC>
备注      : 治具状态 00 = 转发成功；0C = DUT 没应答；01 = 上一发没收尾。


--------------------------------------------------------------------------------
1.12  0x0012  编码器脉冲发生（⑤ 治具发脉冲）
--------------------------------------------------------------------------------
功能      : U1 用 TIM4 在 CN2 的 A/B/Z 三根线上发一串定量脉冲，让被测板去数。
数据      : LEN=0 → 用默认参数（A=1000 个 @5kHz、B=2000 个 @10kHz、Z=1 个）
            LEN=12 → cnt_a(2) cnt_b(2) cnt_z(2) freq_a(2) freq_b(2) freq_z(2)
ACK 内容  : 命令 00 12；帧序号 = N；长度 00 09；数据 9 字节：
            [0] 状态码
            [1] 完成掩码：bit0=A bit1=B bit2=Z
            [2] 提前中止标志（1 = 没按计划发完）
            [3..4]  A 相实际翻转次数（应 = 2 x 脉冲数）
            [5..6]  B 相同上
            [7..8]  Z 相同上
备注      : 发完约 200 ms 才回 ACK（期间治具在发脉冲）。
            频率范围 100~20000 Hz，脉冲数 <= 32767；参数非法回 0B 且不发任何脉冲。


--------------------------------------------------------------------------------
1.13  0x0013  读/清 U2 的编码器边沿计数（⑤ 回环）
--------------------------------------------------------------------------------
功能      : 让 U2 把"它在 CN2 那三根线上数到的边沿数"清掉或报上来。
数据      : [0] 动作：00 = 清零，01 = 读取（其它回 0B）
ACK 内容  : 命令 00 13；帧序号 = N；长度 00 02（清零）或 00 10（读取）；
            数据 = [0] 治具状态码 + [1..] U2 的原始应答：
              清零：1 字节（U2 状态码）
              读取：15 字节 = 状态(1) + cnt_a(4) + cnt_b(4) + cnt_z(4) + 丢沿(2)
备注      : **清零要放在发脉冲之前、读取放在之后**，这样 U2 数到的就正好是这一串。


--------------------------------------------------------------------------------
1.14  0x0014  相电流检测（⑥，一条命令跑完整流程）
--------------------------------------------------------------------------------
功能      : 读基线 -> 让被测板静态通流 -> 等稳定 -> 再读一次 -> 判定 -> 出报告。
数据      : LEN=0 → 默认（A->B、1000‰、200 ms、两路电流都读）
            LEN=8 → [0] 上桥相掩码 bit0=A bit1=B bit2=C（只许 1 位）
                     [1] 下桥相掩码（只许 1 位，且必须与上桥不同相）
                     [2..3] 占空比 千分比
                     [4..5] 持续时间 ms
                     [6] 要读的电流通道 bit0=电流1 bit1=电流2（不能为 0）
                     [7] 保留 0
ACK 内容  : 命令 00 14；帧序号 = N；长度 00 16（= 22）；数据：
            [0] 状态码（00 合格 / 05 不合格 / 0C DUT 没应答）
            [1] 问 DUT 时的状态码
            [2] 电流路数（=2）
            [3] 保留
            之后每路 9 字节：[flags(1) jig_idle(2) jig_on(2) dut_idle(2) dut_on(2)]
            flags: 01=合格 02=无数据 04=没通流 08=超差
备注      : 治具比的是"通流前 -> 通流中"的**变化量**，不用管放大器零点偏置。


--------------------------------------------------------------------------------
1.15  0x0015  电压检测（②，一条命令跑完整流程）
--------------------------------------------------------------------------------
功能      : 问 DUT 的 INFO 拿能力位图 -> 按位图问 GET_ADC -> 与治具 9 路逐通道比对。
数据      : 无（LEN=0）
ACK 内容  : 命令 00 15；帧序号 = N；长度 00 47（= 71）；数据：
            [0]     状态码（00 合格 / 05 不合格）
            [1]     问 DUT 时的状态码
            [2..3]  DUT 报的协议版本
            [4..5]  DUT 的能力位图 adc_mask
            [6..7]  汇总：01=9 路都过了一遍 02=至少一路不合格 04=至少一路没判成
            [8..]   每路 7 字节 x 9：
                    flags(1) + jig_mv(2) + dut_mv(2) + err_mv(2, 有符号)
                    通道序号 0..8 = 24V母线/10V驱动/5V/3.3V/A相/B相/C相/电流1/电流2
            flags: 01=通过 02=数据不全不判 08=超容差
备注      : DUT 没在 adc_mask 里声明的通道跳过并标 02（不判），不算失败。


--------------------------------------------------------------------------------
1.16  0x0016  三相输出判据（④）
--------------------------------------------------------------------------------
功能      : 对"已有的一次测量快照 + 一次脉冲结果"做判定，判据是
              V_相电压平均值 约等于 占空比 x 母线电压
数据      : [0]     mode：00 = 静态电平（不查脉冲），01 = PWM（同时查脉冲）
            [1..2]  A 相占空比 千分比；0xFFFF = 该相高阻（不判）
            [3..4]  B 相
            [5..6]  C 相
ACK 内容  : 命令 00 16；帧序号 = N；长度 00 22（= 34）；数据：
            [0]     状态码
            [1..2]  汇总：01=三相都判过 02=至少一相不合格
            [3]     相数（=3）
            [4..]   每相 10 字节：
                    flags(2) + expect_mv(2) + err_mv(2,有符号) + tol_mv(2) + duty_pm(2)
            flags: 01=合格 02=高阻不判 04=无数据 08=母线太低(不判)
                   10=期望有 PWM 但没测到边沿 20=偏差超容差 40=占空比与 ③ 不符
备注      : 依赖之前已经跑过 0x000F（它用那次快照里的相电压和母线）。
            母线没电时三相都会报 08（"测不了"），不是"板子坏"。


--------------------------------------------------------------------------------
1.17  0x0018  编码器三方对齐判定（⑤ 的判定层）
--------------------------------------------------------------------------------
功能      : 把三个数喂进来，直接回合格/不合格：
              治具意图(2 x 脉冲数)  vs  U2 实测  vs  DUT 上报
            判据层是纯函数，治具不缓存任何状态（上位机手里本来就有这三组数）。
数据      : 38 字节：
            [0..1]   exp_a 治具发的 A 相**脉冲个数**（层里 x2 变边沿）
            [2..3]   exp_b
            [4..5]   exp_z
            [6..7]   tol 允许的**边沿数**偏差（默认 0）
            [8..11]  u2_a  U2 实测边沿数（0x0013 那 4 字节）
            [12..15] u2_b
            [16..19] u2_z
            [20..21] u2_lost  U2 报的丢边沿次数
            [22..25] dut_a DUT 上报边沿数（0x0011 透传 0x0208 回来的）
            [26..29] dut_b
            [30..33] dut_z
            [34]     dut_dir DUT 报的解码方向（s8： +1 / -1 / 0）
            [35]     avail：bit0 = 有 U2 数据，bit1 = 有 DUT 数据（其它位 -> 0B）
            [36..37] 保留 00
ACK 内容  : 命令 00 18；帧序号 = N；长度 00 1D（= 29）；数据：
            [0]     状态码（00 合格 / 05 不合格）
            [1..2]  汇总：0001=三相都判过 0002=至少一路不合格
                           0004=至少一路缺数据 0008=U2 丢过边沿(警告)
                           0010=发了脉冲但 DUT 报方向没动(警告)
            [3]     路数（=3）
            [4..5]  u2_lost
            [6]     dut_dir
            [7]     保留
            之后每路 7 字节：flags(1) + exp_edges(2) + u2_edges(2) + dut_edges(2)
            flags: 01=三边一致(只有两边都有数据时才给) 02=数据不全不判
                   04=U2 不符  08=DUT 不符
备注      : 只有 U2 不符 -> 信号/接线问题；只有 DUT 不符 -> DUT 解码/计数问题
            （常见：它按脉冲数报了，差一倍）；两边都不符 -> 多半 A/B/Z 接错了。


--------------------------------------------------------------------------------
1.18  0x0010  一键全流程（②③④⑤⑥ 一条命令跑完）
--------------------------------------------------------------------------------
功能      : 进测试模式 -> ②电压 -> ③④脉冲+相电压 -> ⑤编码器 -> ⑥电流 -> 关输出。
数据      : 无（LEN=0；本命令目前不收参数，全部用默认值）
ACK 内容  : 命令 00 10；帧序号 = N；长度 00 1D（= 29）；数据：
            [0]      状态码（00 全部通过 / 05 有步骤不合格）
            [1]      总步数（=12）
            [2]      实际跑完几步
            [3]      第一个失败的步骤号（1 基）；0 = 没有失败
            [4..27]  每步 2 字节 x 12：状态(1) + 结果码(1)
                     状态: 00 没跑 01 OK 02 失败 03 跳过(数据不全) 04 超时
                     结果码: 该步子命令的原始状态码
            [28]     保留 0
            12 步顺序：
              1  透传 0x0202 进测试模式（wdt=4000ms）
              2  0x0015 ② 电压检测
              3  透传 0x0204 发 PWM（1kHz 三相 50% 300 个）
              4  0x000F mode=1 ③ 脉冲采集
              5  0x0016 mode=1 ④ 三相输出判定（500‰）
              6  透传 0x0202 再进一次（清编码器计数）
              7  0x0013 动作=0  U2 清零
              8  0x0012 发编码器脉冲（默认参数）
              9  0x0013 动作=1  读 U2 计数
             10  透传 0x0208 读 DUT 计数 + 内部三方判定（= 0x0018 的判据）
             11  0x0014 ⑥ 相电流检测（默认 A->B 100% 200ms）
             12  透传 0x0203 关输出
备注      : 1) 中途各子命令的应答**照常发给 PC**（同 SEQ），最后才是本命令的汇总；
               上位机可以只等 0x0010 那一条。
            2) 某一步失败/超时不中断，继续跑完（一次压合看到全貌），
               单步超时上限 4 秒。
            3) **烧录不在里面**：0x0112 要几十秒，建议"先烧录成功，再 0x0010"。


--------------------------------------------------------------------------------
1.19  0x0019  ③ 一条命令（MCU 脉冲检测）
--------------------------------------------------------------------------------
功能      : 把原来要发的 3 条打包成一条：
              透传 0x0202 进测试模式 → 透传 0x0204 发 PWM → 0x000F 采集 → 透传 0x0203 关输出
数据      : 无（LEN 必须为 0，否则回 0B ERR_PARAM）
            参数固定：PWM 1kHz、三相 50%、300 个；DUT 看门狗 4000ms
ACK 内容  : 命令 00 19；帧序号 = N；长度 = 那份脉冲报告的原始长度（正常 00 5B = 91）；
            数据 **就是 0x000F 的应答数据**（布局见附录 C 两遍：前 45B = U1，后 45B = U2）
            —— 上位机复用 0x000F 的解析即可。
            若流程在中途就失败（一个可用报告都没拿到），回 1 字节状态码。
备注      : 1) **中途子命令的应答一律不发**，所以一条命令只有一条应答（上位机不用认帧）。
            2) 每步超时上限 4 秒；某步失败仍继续跑完，最后按拿到的报告回。
            3) 这个命令自己会进测试模式、自己会关输出，PC 不用再发 0x0202/0x0203。


--------------------------------------------------------------------------------
1.20  0x001A  ④ 一条命令（三相输出检测）
--------------------------------------------------------------------------------
功能      : 原来 4 条打包成一条：
              进测试模式 → 发 PWM → 0x000F 采集 → 0x0016 相电压判定 → 关输出
数据      : 无（LEN=0）；PWM 参数同 0x0019（1kHz、三相 50%、300 个）
ACK 内容  : 命令 00 1A；帧序号 = N；长度 = 那份判定报告的原始长度（正常 00 22 = 34）；
            数据 **就是 0x0016 的应答数据**（flags/expect/err/tol/duty 每相 10B）
备注      : 判据 V_相电压平均值 约等于 占空比 x 母线电压；母线没电时三相报 08（测不了）。


--------------------------------------------------------------------------------
1.21  0x001B  ⑤ 一条命令（编码器检测）
--------------------------------------------------------------------------------
功能      : 原来 6 条打包成一条：
              进测试模式 → 0x0013 清零 → 0x0012 发脉冲 → 0x0013 读 U2
              → 透传 0x0208 读 DUT → 0x0018 三方判定 → 关输出
数据      : 无（LEN=0）；脉冲用默认 A=1000@5kHz、B=2000@10kHz、Z=1
ACK 内容  : 命令 00 1B；帧序号 = N；长度 = 那份判定报告的原始长度（正常 00 1D = 29）；
            数据 **就是 0x0018 的应答数据**（汇总 + 每路 flags/exp/u2/dut）
备注      : 一句话结论看 [0]：00 = 三边对齐合格，05 = 不合格。
            [1..2] 的汇总能分清"信号没出去 / DUT 解码错 / 接错线"。
            判据层和单独发 0x0018 是**同一个函数**，不会出现两套标准。


================================================================================
1.22  数据字段速查（0x0010 ~ 0x001B 按块写）
================================================================================
说明：全部大端；"请求数据"= PC 发出的 DATA，"应答数据"= 治具回的 DATA（第 0 字节通常
      是状态码：00 OK / 05 判定不合格 / 0B 参数错 / 0C 超时）。

0x0010  一键全流程（③④⑤⑥ 一次跑完）
  请求数据  : {}                        （LEN=0，不收参数）
  应答数据  : {1 字节   ：状态码（00 全部通过 / 05 有步骤不合格）
               1 字节   ：总步数（=12）
               1 字节   ：实际跑完几步
               1 字节   ：第一个失败的步骤号（1 基，0 = 没有）
               12×{1 字节：该步状态 00没跑/01OK/02失败/03跳过/04超时
                    1 字节：该步结果码}
               1 字节   ：保留 0}        共 29 字节

0x0011  DUT 协议透传
  请求数据  : {2 字节 u16：DUT 命令号（只接受 0x0200~0x02FF）
                n 字节    ：DUT 命令的数据（原样，可为空）}
  应答数据  : {1 字节   ：治具状态码（00 转发成功 / 0C DUT 没应答）
                m 字节    ：DUT 应答的数据（原样，含 DUT 自己的状态字节）}

0x0012  编码器脉冲发生（⑤ 治具发）
  请求数据  : {}  或  {2 字节 u16：A 相脉冲个数
                       2 字节 u16：B 相脉冲个数
                       2 字节 u16：Z 相脉冲个数
                       2 字节 u16：A 相频率 Hz
                       2 字节 u16：B 相频率 Hz
                       2 字节 u16：Z 相频率 Hz}     共 12 字节
  应答数据  : {1 字节   ：状态码
               1 字节   ：完成掩码 bit0=A bit1=B bit2=Z
               1 字节   ：提前中止标志（1 = 没按计划发完）
               2 字节 u16：A 相实际翻转次数（应 = 2×脉冲数）
               2 字节 u16：B 相实际翻转次数
               2 字节 u16：Z 相实际翻转次数}        共 9 字节

0x0013  读/清 U2 的编码器边沿计数
  请求数据  : {1 字节：动作（00 清零 / 01 读取）}
  应答数据  : {1 字节：治具状态码
               + 清零时：{1 字节：U2 状态码}                              共 2 字节
               + 读取时：{1 字节 ：U2 状态码
                          4 字节 u32：A 相边沿数
                          4 字节 u32：B 相边沿数
                          4 字节 u32：Z 相边沿数
                          2 字节 u16：U2 丢边沿次数}                      共 16 字节}

0x0014  相电流检测（⑥ 一条命令）
  请求数据  : {}  或  {1 字节   ：上桥相掩码 bit0=A bit1=B bit2=C（只许 1 位）
                       1 字节   ：下桥相掩码（只许 1 位，必须与上桥不同相）
                       2 字节 u16：占空比 千分比
                       2 字节 u16：持续时间 ms
                       1 字节   ：要读的电流通道 bit0=电流1 bit1=电流2（不能为 0）
                       1 字节   ：保留 0}             共 8 字节
  应答数据  : {1 字节：状态码（00 合格 / 05 不合格 / 0C DUT 没应答）
               1 字节：问 DUT 时的状态码
               1 字节：电流路数（=2）
               1 字节：保留
               2×{1 字节   ：flags（01合格 02无数据 04没通流 08超差）
                  2 字节 u16：治具通流前的 mV
                  2 字节 u16：治具通流中的 mV
                  2 字节 u16：DUT 通流前的 mV
                  2 字节 u16：DUT 通流中的 mV}}        共 22 字节

0x0015  电压检测（② 一条命令）
  请求数据  : {}                                        （LEN=0）

0x0018  编码器三方对齐判定（⑤ 判定层）
  请求数据  : {2 字节 u16：A 相**脉冲个数**（治具发的，层里 ×2 变边沿）
               2 字节 u16：B 相脉冲个数

               4 字节 u32：U2 实测 Z 相边沿数
               2 字节 u16：U2 报的丢边沿次数
               4 字节 u32：DUT 上报 A 相边沿数
               4 字节 u32：DUT 上报 B 相边沿数
               4 字节 u32：DUT 上报 Z 相边沿数
               1 字节 s8 ：DUT 报的解码方向（+1/-1/0）
               1 字节   ：可用标志（bit0 有 U2 数据 bit1 有 DUT 数据，只认这两位）
               2 字节   ：保留 00}                     共 38 字节

               2 字节 u16：汇总（0001=都判过 0002=有不合格 0004=有缺数据
                                 0008=U2丢过边沿(警告) 0010=发了脉冲但方向没动(警告)）
               1 字节   ：路数（=3）
               2 字节 u16：U2 丢边沿次数
               1 字节 s8 ：DUT 方向
               1 字节   ：保留
               3×{1 字节   ：flags（01三边一致 02缺数据不判 04 U2不符 08 DUT不符）
                  2 字节 u16：意图边沿数
                  2 字节 u16：U2 实测边沿数（>65535 饱和）
                  2 字节 u16：DUT 上报边沿数（>65535 饱和）}}   共 29 字节

19. MCU 脉冲检测 一条命令跑完（③ 打包）
--------------------------------------------------------------------------------
  功能    : 把"进测试模式 → 让被测板发已知 PWM → 200ms 采集 → 关输出"
            打包成一条命令；应答就是那份脉冲报告。
  发送方  : PC
  帧头F   : A5 5B
  命令C   : 00 19
  帧序号N : N
  数据长度L: 00 00
  数据D   : 无（参数固定：PWM 1kHz、三相 50%、300 个；看门狗 4000ms）
  CRC16   : 2B
  备注    : ✅ 已实现（宿主 2414 条断言全过；本命令单独验了"只回一条应答"）
            - 内部依次：透传 0x0202 进测试模式 → 透传 0x0204 发 PWM
                        → 0x000F 采集 → 透传 0x0203 关输出
            - **中途子命令的应答一律拦下不发**，所以一条命令只有一条应答
            - 每步超时上限 4 秒；某步失败仍继续跑完
            - ACK: CMD=00 19, SEQ=回显, LEN=00 5B(91), DATA=
                   [1B 状态码][45B U1 脉冲结果][45B U2 脉冲结果]
              （45B 布局见附录 C；与 0x000F 的应答完全一致，解析可复用）
            - 若中途失败（一个可用报告都没拿到）: LEN=00 01, DATA=[1B 状态码]
            - 这个命令自己进测试模式、自己关输出，PC 不用再发 0x0202/0x0203

20. 三相输出检测 一条命令跑完（④ 打包）
--------------------------------------------------------------------------------
  功能    : 把"进测试模式 → 发 PWM → 采集 → 相电压判定 → 关输出"打包成一条。
  发送方  : PC
  帧头F   : A5 5B
  命令C   : 00 1A
  帧序号N : N
  数据长度L: 00 00
  数据D   : 无（PWM 参数同 0x0019；判定用三相各 500‰）
  CRC16   : 2B
  备注    : ✅ 已实现
            - 判据：V_相电压平均值 ≈ 占空比 × 母线电压
            - 母线没电时三相都报 08（"测不了"），**不是"板子坏"**
            - ACK: CMD=00 1A, SEQ=回显, LEN=00 22(34), DATA=
                   [1B 状态码][2B 汇总][1B 相数=3]
                   + 3×[2B flags][2B 期望mV][2B 差值s16][2B 容差mV][2B 占空比]
              （与 0x0016 的应答完全一致）
            - 若中途失败: LEN=00 01, DATA=[1B 状态码]

21. 编码器检测 一条命令跑完（⑤ 打包）
--------------------------------------------------------------------------------
  功能    : 把"进测试模式 → U2 清零 → 治具发脉冲 → 读 U2 → 读 DUT → 三方判定
            → 关输出"打包成一条。
  发送方  : PC
  帧头F   : A5 5B
  命令C   : 00 1B
  帧序号N : N
  数据长度L: 00 00
  数据D   : 无（脉冲用默认：A=1000@5kHz、B=2000@10kHz、Z=1）
  CRC16   : 2B
  备注    : ✅ 已实现
            - 一句话结论看 DATA 第 0 字节：00 = 三边对齐合格，05 = 不合格
            - 汇总位能分清"信号没出去(U2 不符) / DUT 解码错(DUT 不符) / 接错线(都不符)"
            - 判据层和单独发 0x0018 是**同一个函数**，不会出现两套标准
            - ACK: CMD=00 1B, SEQ=回显, LEN=00 1D(29), DATA=
                   [1B 状态码][2B 汇总][1B 路数=3][2B U2丢沿][1B DUT方向][1B 保留]
                   + 3×[1B flags][2B 意图边沿][2B U2边沿][2B DUT边沿]
              （与 0x0018 的应答完全一致）
            - 若中途失败: LEN=00 01, DATA=[1B 状态码]


================================================================================
二、U1 ↔ U2（内部链路）
================================================================================
链路参数：USART3，115200 8N1，无硬件流控；U1 = 主机，U2 = 从机。
跳线必须交叉（U1.TX→U2.RX、U1.RX→U2.TX）且必须共地。

命令总表
    +--------+--------------------------------+----------+--------+--------+
    | 命令   | 功能                           | 方向     | 请求LEN| 应答LEN|
    +--------+--------------------------------+----------+--------+--------+
    | 0x0100 | 回环自检（保活）               | U1→U2    | 0..64  |  = 请求|
    | 0x0101 | 查从机状态（版本/统计/事件）   | U1→U2    |   0    |  28    |
    | 0x0102 | 预留                           |   —      |   —    |   —    |
    | 0x0103 | 交换电压快照                   | U1→U2    |  55    |  55    |
    | 0x0104 | 交换脉冲结果                   | U1→U2    |  45    |  45    |
    | 0x0105 | ARM（同步触发：两端同窗采集）  | U1→U2    |   5    |   3    |
    | 0x0106 | 链路复位                       | U1→U2    |   0    |   1    |
    | 0x0107 | 事件上报                       | U2→U1    |   —    |   8    |
    | 0x0108 | 取一条待决事件                 | U1→U2    |   0    |   9    |
    | 0x0109 | 读/清编码器边沿计数（⑤ 回环）  | U1→U2    |   1    | 1/15   |
    +--------+--------------------------------+----------+--------+--------+
    链路版本：LINK_CODE_VER = 0x0104（v1.4）；能力位图 LINK_CAP_ALL = 0x01FF（bit0..bit8）

通用约定
    · 收到未分配命令（0x0102、0x010A~0x01FF）→ 回 FF NIY。
    · 等应答上限：控制类 50ms；数据类（0x0103/0x0104）300ms；ARM 50ms。
    · 请求超时后自动重传 1 次，且沿用同一个序号；
      U2 认出重复请求后直接重发上次的应答，不重新执行（幂等）。
    · 帧内字节间隔超过 5ms 判为"半截帧"，丢弃并重新找帧头（错误计数 rx_half）。

--------------------------------------------------------------------------------
2.1  0x0100  回环自检（保活）
--------------------------------------------------------------------------------
功能      : U1 每 500ms 发一发；U2 把数据区原样回显 → 证明链路通、跳线交叉正确。
发送方    : U1
接收方    : U2
帧头      : A5 5B
命令      : 01 00
帧序号    : N（U1 递增）
数据长度  : 00 00（也可带任意 0~64 字节用于回环测试）
数据      : 任意（回显内容）
CRC16     : 同上
ACK 内容  : 命令 01 00；帧序号 = N；长度与请求相同；数据 = 请求数据原样回显
            （没有状态码字节）
示例      : N=1、空数据
            U1 → : A5 5B 01 00 00 01 00 00 98 30
            U2 → : A5 5B 01 00 00 01 00 00 98 30        （原样回显）
备注      : U1 用它把"U2 在不在"变成持续可观测的事实（APP_U2Alive()）。

--------------------------------------------------------------------------------
2.2  0x0101  查从机状态
--------------------------------------------------------------------------------
功能      : 读 U2 的版本、链路代码版本、存活计数、链路与串口统计、能力与事件位图。
发送方    : U1
接收方    : U2
帧头      : A5 5B
命令      : 01 01
帧序号    : N（U1 递增）
数据长度  : 00 00
数据      : 无
CRC16     : 同上
ACK 内容  : 命令 01 01；帧序号 = N；长度 00 1C（= 28）；数据 28 字节，见附录 D
示例      : N=2
            U1 → : A5 5B 01 01 00 02 00 00 58 FD
            U2 → : A5 5B 01 01 00 02 00 1C 00 01 01 03 00 2A 00 00 12 34 00 00
                   00 00 00 00 30 39 00 00 00 00 00 7F 00 00 00 00 30 4D
备注      : 1) U1 每 5 次保活（约 2.5 秒）插一次 STATUS。
            2) 用 code_ver 比对"两片是不是同一版固件"：不一致时 U1 不采信 U2 数据。
            3) caps 能力位图让"对端老版本"变成明确的一条能力缺失，而不是整个链路不可用。

--------------------------------------------------------------------------------
2.3  0x0103  交换电压快照
--------------------------------------------------------------------------------
功能      : U1 把自己的 55 字节电压快照发给 U2，U2 回自己那份 55 字节；
            比对由 U1 做（判定方只有一个，避免两套判据跑偏）。
发送方    : U1
接收方    : U2
帧头      : A5 5B
命令      : 01 03
帧序号    : N（U1 递增）
数据长度  : 00 37（= 55）
数据      : U1 的 55 字节电压快照（布局见附录 A）
CRC16     : 同上
ACK 内容  : 命令 01 03；帧序号 = N；长度 00 37；数据 = U2 的 55 字节电压快照
            （请求长度不足时回 1 字节 FF NIY）
示例      : N=3
            U1 → : A5 5B 01 03 00 03 00 37 | U1 的 55B 快照 | F9 6E
            U2 → : A5 5B 01 03 00 03 00 37 | U2 的 55B 快照 | <CRC>
备注      : 快照 55B 正好装得进内部链路单帧上限 64B。

--------------------------------------------------------------------------------
2.4  0x0104  交换脉冲结果
--------------------------------------------------------------------------------
功能      : U1 发自己测到的三相脉冲结果（电机输出端），U2 回自己那份（驱动输入端）；
            U1 比较"输入端有 PWM、输出端就该有对应波形"。
发送方    : U1
接收方    : U2
帧头      : A5 5B
命令      : 01 04
帧序号    : N（U1 递增）
数据长度  : 00 2D（= 45）
数据      : U1 的 45 字节脉冲结果（布局见附录 C）
CRC16     : 同上
ACK 内容  : 命令 01 04；帧序号 = N；长度 00 2D；数据 = U2 的 45 字节脉冲结果
示例      : N=4
            U1 → : A5 5B 01 04 00 04 00 2D | U1 的 45B 结果 | 2E FA
            U2 → : A5 5B 01 04 00 04 00 2D | U2 的 45B 结果 | <CRC>
备注      : 两端的 45B 里都带 window_ms，便于确认"这次是不是同一次窗口"。

--------------------------------------------------------------------------------
2.5  0x0105  ARM（同步触发）
--------------------------------------------------------------------------------
功能      : U1 喊一声"预备—开始"，让两块板在同一个时间窗里采集。
            解决"U1 按需采、U2 滚动采，交换回来的可能是两段不同时刻波形"的问题。
发送方    : U1
接收方    : U2
帧头      : A5 5B
命令      : 01 05
帧序号    : N（U1 递增）
数据长度  : 00 05
数据      : [0..1] session   u16 大端，从 1 开始递增（0 = 非法）
            [2..3] window_ms u16 大端，采集窗口毫秒（1 ~ 1000）
            [4]    flags     保留位，当前必须 0（bit0 预留给将来的硬连线触发）
            参数非法 → 回 0B ERR_PARAM
CRC16     : 同上
ACK 内容  : 命令 01 05；帧序号 = N；长度 00 03；
            数据 = [0] 状态码 + [1..2] session 回显（大端）
            状态码：00 OK（已开窗）/ 01 BUSY（上一个窗口还在跑）/ 0B ERR_PARAM
示例      : N=5，session=1，窗口 200ms
            U1 → : A5 5B 01 05 00 05 00 05 00 01 00 C8 00 EE 28
            U2 → : A5 5B 01 05 00 05 00 03 00 00 01 F0 6B   （00 = OK）
            忙碌应答：A5 5B 01 05 00 05 00 01 01 21 59        （01 = BUSY）
备注      : 1) U2 收到 ARM 后立刻回 ACK 并同时开窗；U1 发完 ARM 也立刻开
               自己的窗 → 两端窗口错位 < 2ms（200ms 窗口下重叠 >99%）。
            2) 应答不等采集结束（收到就回，约 1ms），否则 U1 会被拖住。
            3) 同一个 session 重复请求（重传）不会重开窗口（幂等）；
               换了 session 才会覆盖上一个结果。
            4) 结果保留到被 0x0103/0x0104 取走、或被下一个 ARM 覆盖、或链路复位。
            5) 对端若不支持 ARM（caps 里没有该位），U1 自动退回"各自最近一次"的老流程。

--------------------------------------------------------------------------------
2.6  0x0106  链路复位
--------------------------------------------------------------------------------
功能      : 连续通信失败后的恢复动作：清收发环、复位会话
            （半截帧 / 等待状态 / ARM / 幂等缓存）。
发送方    : U1
接收方    : U2
帧头      : A5 5B
命令      : 01 06
帧序号    : N（U1 递增）
数据长度  : 00 00
数据      : 无
CRC16     : 同上
ACK 内容  : 命令 01 06；帧序号 = N；长度 00 01；数据 = 00 OK
示例      : N=6
            U1 → : A5 5B 01 06 00 06 00 00 59 09
            U2 → : A5 5B 01 06 00 06 00 01 00 96 98
备注      : 1) 触发条件：U1 连续 3 次请求超时，且自己处于空闲状态
               （正在测试/烧录时只累计计数，不打断流程）。
            2) 事件表与统计不清 —— 它们是故障证据，只清"会话态"。
            3) 复位也失败 → 退避 5 秒再试，避免一直刷屏重试。

--------------------------------------------------------------------------------
2.7  0x0107  事件上报（U2 → U1，主动）
--------------------------------------------------------------------------------
功能      : U2 自己发现问题时主动告诉 U1（不必等 U1 来问）。
发送方    : U2
接收方    : U1
帧头      : A5 5B
命令      : 01 07
帧序号    : 0（主动帧专用；与"应答"天然区分得开）
数据长度  : 00 08
数据      : [0]    事件码（见附录 E）
            [1]    严重度：00 提示 / 01 警告 / 02 错误
            [2..3] 参数 1（含义随事件码）
            [4..5] 参数 2（含义随事件码）
            [6..7] 该事件累计发生次数（大端，饱和在 0xFFFF）
CRC16     : 同上
ACK 内容  : 不需要应答
示例      : 第 5 路 ADC 饱和（事件码 01，参数1 = 通道号 5，参数2 = 码值 0x1234）
            U2 → : A5 5B 01 07 00 00 00 08 01 02 00 05 12 34 00 01 DC D9
备注      : 1) 这是"快路径"（约 1ms 到达）；万一这帧丢了也不会丢事件 ——
               U2 同时把"有哪些事件待处理"记在位图里（STATUS 的 ev_pending），
               U1 每 2.5 秒查一次 STATUS 就能发现并用 0x0108 补拉。
            2) 事件是状态、不是易丢的消息：同一事件重复发生只累加次数。
            3) U2 只在"手上没有待处理请求"时发事件帧，不会插在应答中间。

--------------------------------------------------------------------------------
2.8  0x0108  取一条待决事件
--------------------------------------------------------------------------------
功能      : U1 从 U2 那里取走一条待决事件的详细信息（取即清）。
发送方    : U1
接收方    : U2
帧头      : A5 5B
命令      : 01 08
帧序号    : N（U1 递增）
数据长度  : 00 00
数据      : 无
CRC16     : 同上
ACK 内容  : 命令 01 08；帧序号 = N；长度 00 09；
            数据 = [0]     00 OK
                   [1]     事件码（0 = 当前没有待决事件）
                   [2]     严重度
                   [3..4]  参数 1（大端）
                   [5..6]  参数 2（大端）
                   [7..8]  累计次数（大端）
示例      : N=7，取到"第 5 路 ADC 饱和、累计 1 次"
            U1 → : A5 5B 01 08 00 07 00 00 58 31
            U2 → : A5 5B 01 08 00 07 00 09 00 01 02 00 05 12 34 00 01 5E 26
备注      : 1) 每次只取一条（取最早待决的那条）；位图里还有就再取一次。
            2) 取走后 U2 把该事件的位图位清掉，但参数与累计次数保留，
               下次同一事件再发生时继续累加。


--------------------------------------------------------------------------------
2.9  0x0109  读/清编码器边沿计数（⑤ 回环）
--------------------------------------------------------------------------------
功能      : U2 在 CN2 的 A/B/Z 三根线上独立数边沿（**不复用 0x0003 那套捕获单例**，
            所以能和滚动窗口同时跑）。U1 在"发脉冲之前清零、发完之后读取"，
            拿到的就正好是这一串。
发送方    : U1
接收方    : U2
帧头      : A5 5B
命令      : 01 09
帧序号    : N（U1 递增）
数据长度  : 00 01
数据      : [0] 动作：00 = 清零，01 = 读取（其它 -> FF 或 0B）
CRC16     : 同上
ACK 内容  : 命令 01 09；帧序号 = N；
            清零时 长度 00 01，数据 = U2 状态码
            读取时 长度 00 0F（=15），数据 = 状态(1) + cnt_a(4) + cnt_b(4)
                                            + cnt_z(4) + 丢沿计数(2)，全部大端
            状态码：00 OK / 0B 参数错 / FF 未实现
备注      : 1) 计数是**边沿个数**（上升+下降），不是解码后的位置值 ——
               和 DUT 侧 0x0208 的量纲必须一致，否则两边天然差一倍。
            2) 丢沿计数是 U2 自己的诊断量（ISR 发现标志被覆盖），正常恒为 0。
            3) PC 侧不是直接发这条，而是通过 0x0013 转发（见 1.13）。

附录 F · 常见问题速查
================================================================================
    收不到任何应答   : 先查 USB CDC 枚举（PC 侧）/ 跳线交叉与共地（两片之间）；
                       CRC 错的帧是不回 ACK 的，用工具抓原始字节看。
    一直是 01 BUSY   : 上一轮没收尾（上传中断/烧录中/测试中）；等待或复位。
    03 ERR_FLASH     : 治具自己的 SPI Flash（U10 GD25Q128）不在线或型号不对。
    04 ERR_PROG      : SWD 烧录失败：目标没供电/没共地/SWD 两线接反/
                       目标程序占用了 PA13-PA14/目标开了读保护。
    05 ERR_TEST      : 测试判定失败：看 0x000E 的校验块掩码、0x000F 的两端对比标志。
    06 ERR_NO_FW     : 对应槽里没固件（先上传）。
    0C ERR_TIMEOUT   : 上传超时 / 0x000D 连不上目标。
    FF NIY           : 命令没实现（老固件）；内部链路可先用 0x0101 看 caps 位图。
